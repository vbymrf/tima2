# Сценарии на телефонах

Заведён 2026-09-29 решением заказчика, после прогона стенда, который трижды завис и один
раз позвонил чужому контакту. Устройство повторяет `adaptive-ops-runner` (роли, база
правил, журнал), но единица здесь — **элемент сценария**, а не ярус проверки.

## Главное

1. **Элемент приводит телефоны к названному состоянию и сам проверяет, что привёл.**
   Нажатие — не результат. Результат — строка журнала приложения (`files/logs/<дата>.txt`):
   «звонок начат видео=true», «стадия звонка стала=Connected», «звонок закончен»,
   «следующий набор забега номер=». Экран — только там, где журнал молчит (выбран ли
   набор в окне стенда).
2. **Сторож снаружи.** Элемент идёт отдельным процессом с пределом времени. Превысил —
   процесс останавливается со всеми дочерними (adb, maestro, sh), итог «превышено
   время». Зависание — самая частая беда (заказчик), и зависший элемент сам себя не
   остановит.
3. **Сброс** после любого недостигнутого элемента: звонков нет, окно звонка закрыто,
   драйвера Maestro нет, приложение впереди. Сброс проверяется тем же журналом. Второй
   недостигнутый звонок подряд — серия останавливается.
4. **Способ нажатий выбирает опыт, а не таблица.** Элемент с нажатиями пробуется и adb,
   и Maestro. Каждая попытка — строка в `project/methods.md`. Когда по элементу три и
   больше попыток каждым способом, лучший виден из журнала и становится выбором по
   умолчанию. **Заказчик выбор перебивает:** в задаче на тестирование он указывает
   способ; тест по инициативе агента — на усмотрение агента.
5. **Решения при отладке — по гипотезе, без вопросов.** Какую пару взять первой, что
   делать после сброса — агент выбирает сам, записывает гипотезу и итог. Спрашивать
   только то, что агент решить не вправе: поведение продукта, действие наружу,
   перезагрузку телефона.
6. **Отладка — с одного элемента, одного прогона, одного телефона** (для звонка — одной
   пары). Потом проверка на остальных. Потом серия.
7. **Каждая встреченная проблема — правило** в `knowledge/phone.md` (симптом, проверка,
   причина, что делать, как убедиться), строка в `INDEX.md`. Чат — не хранилище.

## Роли

| Роль | Кто | Что делает |
|---|---|---|
| Основная модель | ведущий разговор | пишет сценарий и элементы, решает, что доказано, проверяет по журналам телефонов сама |
| Исполнитель | субагент | запускает элемент или серию по `WORKER.md`, возвращает отчёт со временем; сценарий не правит |
| Журналист | субагент посильнее | проблему — в правило базы, попытку — в `methods.md` (`JOURNAL-AGENT.md`) |

Отчёт исполнителя — не доказательство. Основная модель открывает `report.jsonl` и журналы
телефонов и пересчитывает сама.

**Делегировать неизвестность, а не нажатие.** Элемент, дважды прошедший без правок,
замораживается (`frozen:` в профиле) и запускается основной моделью одной командой.

## Где что лежит

| Что | Где | Почему там |
|---|---|---|
| элементы, сторож, сброс | `maestro/phone/scenario.py`, `phone.py` | код — латиницей, рядом со сценариями Maestro |
| сценарии Maestro элементов | `maestro/phone/flows/*.yaml` | запуск только через `maestro/run.sh` |
| отчёты прогонов | `doc_add/тесты-звонков/сценарии/<время>/report.jsonl` + снимки | сырые данные вне git (`ПРОГОНЫ-СТЕНДА.md`) |
| своды | `doc_mig/ФУНКЦИОНАЛ/АВТОТЕСТЫ/` | для человека, в git |
| правила и попытки | этот навык | едут на вторую машину |

## Граница безопасности

- **Можно без вопросов:** читать экран и журналы, нажимать в приложении TIMA, класть свои
  наборы стенда (сняв прежние), будить экран через `run.sh`/`wake-phone.sh` (они записывают и
  возвращают настройки), выгружать драйвер Maestro, **перезапускать приложение**
  (`am force-stop` + `am start`) — решение заказчика 2026-09-29.
- **С разрешения:** перезагрузка телефона — после неё пропадает доступ к нему; настройки
  телефона вне `run.sh` (поворот, яркость); установка APK (память `tima-install-on-request`).
- **Нельзя:** `adb shell monkey` (запрет `adaptive-ops-runner`), `adb kill-server`,
  нажимать «📞» вне окна звонка (PH-10), набирать звонок, пока журнал не показал конец
  прошлого (PH-7).
