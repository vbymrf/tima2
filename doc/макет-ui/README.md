# Макет UI — то, что есть сейчас

Раздел показывает **графический интерфейс приложения в его нынешнем виде**: какие
есть окна, какие подокна открываются поверх них, куда ведёт каждая кнопка и какие
элементы появляются только при условии.

Открывается в браузере, без сборки и без инструментов:

```
doc/макет-ui/индекс.html
```

Дальше — по ссылкам. Главная страница и есть карта архитектуры интерфейса.

---

## Чем этот раздел является

**Описью состава и переходов.** Здесь можно проверить утверждение вида «из чата
нельзя попасть в контакты» или «удаление аккаунта спрятано в самом низу главного
окна» — не запуская приложение и не читая `App.kt`.

Это опись **фактического** состояния, снятая с кода 2026-08-17
(`client/composeApp/src/commonMain/kotlin/io/tima/app/App.kt`, 2560 строк). Не
замысел, не план.

## Чем не является

**Не эталоном оформления.** Отступы, цвета, размеры шрифта, радиусы взяты из
[токены.css](токены.css) и приведены только затем, чтобы макет можно было
смотреть. Соответствие приложения этим цифрам **не требуется и не проверяется.**

Причина: сегодняшний вид — это не выбранный дизайн, а его отсутствие. В коде стоит
пустой `MaterialTheme {}` без единого своего цвета, то есть всё, что вы видите, —
умолчания Material 3. Фиксировать умолчания как эталон бессмысленно.

Поэтому `токены.css` — **стартовая точка для оформления**, файл, который правят
первым. Обязательны в этом разделе другие вещи: состав элементов, условия их
появления и переходы.

**Не заменой [doc_UI](../doc_UI/00-index.md).** Там — техническое задание на
продукт целиком: пять базовых окон, истории, коллекции, личные страницы,
сообщества. Здесь — то, что уже собрано и работает. Расхождение между разделами
нормально и ожидаемо: одно описывает цель, другое — положение дел.

## Окно, подокно, общее

| Вид | Признак | Как выйти |
|---|---|---|
| **Окно** | занимает экран целиком, предыдущего под ним не остаётся | «←» или своя кнопка возврата |
| **Подокно** | открывается над одним конкретным окном, оно остаётся под ним | «Отмена», касание вне, кнопка действия |
| **Общее** | открывается над **любым** окном — живёт в оболочке, а не в окне | своя кнопка |

Подокно бывает двух механик, и это указано на каждой его странице:

- **поверх** — `AlertDialog`, затемнение, окно под ним видно;
- **на месте** — часть окна разворачивается в форму, ничего не затемняется
  (`if (showCreateGroup) { … }`). Обозначено штриховой рамкой.

## Уровень видно по ссылке

Вложенность пути = вложенность интерфейса. Другого признака не нужно:

```
окна/дом.html                              окно
окна/дом/создать-группу.html               подокно окна «дом»
окна/вход-код/номер-занят.html             подокно окна «вход-код»
окна/вход-код/номер-занят/начать-заново.html   подокно этого подокна
общие/обновление.html                      поверх любого окна
```

Ссылка сама говорит, где вы находитесь, — и когда интерфейс поменяется, соврать
она не сможет: переезд файла и есть переезд подокна.

## Кликабельно = ведёт туда же

**Если в макете элемент кликабелен, в приложении соответствующая кнопка ведёт в то
же место.** Некликабельный элемент в приложении действует на месте: отправляет,
переключает, обновляет список.

Правило нужно, чтобы карту можно было проверять обходом: непройденная ссылка —
это ненайденный переход, а лишняя ссылка — переход, которого в коде нет.

## Полосы системы нарисованы нарочно

Сверху и снизу рамки — серые полоски. Это заглушки статусбара и полосы навигации
(`WindowInsets.safeDrawing`). В браузере их нет, и без них макет врал бы про
доступную высоту: экран, который в браузере влезает ровно, на телефоне уезжает
под часы.

**Розовая полоса статуса** означает, что окно под неё залезает — вставки в коде
не применены. Это не оформительская придирка, а дефект, и он помечен на страницах
таких окон.

## Состав раздела

| Файл | Что |
|---|---|
| [индекс.html](индекс.html) | карта: окна, подокна, переходы, развилки |
| [токены.css](токены.css) | цвета, шрифты, ритм — **правится в первую очередь** |
| [каркас.css](каркас.css) | рамка устройства и классы элементов |
| `окна/*.html` | окна |
| `окна/<окно>/*.html` | подокна этого окна |
| `общие/*.html` | подокна поверх любого окна |

Классы в разметке названы по сущности приложения, а не по внешнему виду:
`.кнопка` — `Button`, `.кнопка-текст` — `TextButton`, `.поле` —
`OutlinedTextField`, `.плашка` — `Surface(surfaceVariant)`, `.диалог` —
`AlertDialog`, `.пузырь` — сообщение в переписке.

Это сделано затем, чтобы правка оформления не переименовывала сущности, а порт в
Compose читался однозначно: у каждого класса есть один и только один
соответствующий вызов.

## Как поддерживать

Раздел устареет в тот день, когда `App.kt` поменяется, а его не тронут. Дешёвого
способа это отследить нет — автоматической сверки макета с Compose не существует.
Поэтому:

- Появилось окно или подокно — добавляется страница, иначе карта начинает врать
  молча, а это хуже её отсутствия.
- Каждая страница называет место в коде (`App.kt:строки`). Строки съезжают —
  верен код.
- Расхождение обнаружено — верен код, правится макет.

Раздел описывает интерфейс **до** рефакторинга `App.kt`. Когда UI будет разнесён
по файлам, ссылки «где в коде» на каждой странице перестанут быть номерами строк
одного файла и станут именами файлов — это ожидаемо и полезно: пока они указывают
в один файл на 2560 строк, они и показывают, в чём проблема.
