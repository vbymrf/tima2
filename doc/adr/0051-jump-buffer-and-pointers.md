# ADR-0051. Буфер переходов и указатели; вставка на строку курсора; галочки своего с другого устройства

**Дата:** 2026-10-21
**Статус:** принят — решения заказчика 2026-10-21: «нужно хранить определенные точки… сообщение с которого
совершается переход и сообщение, на который перешли… Если совершили другой переход — пишем в конец… По сути
имеем буффер на клиенте переходов… лимит запоминаний»; «один буффер для сообщества / чата… на сервер не
уходит… назад очищает»; «п4 — делаем общим правилом для всех переходов, одинаковые точки не дописываются»;
«Окно Общение, добавляем вкладку Указатели. Вместо Коллекции. Внутри полностью берем механизм Разделов из Окна
Телефон… Делаем единый стиль — код… Храним раздельно»; «делаем кнопку назад для вкладки Указатель… Помним
только последний… повторные, пришедшие сразу, объединяем как одна точка»; «1. каждая своей 2. да 3. да 4. да»;
«не делаем открытыми… храним»; «Новый кусок становится, если мы перемещаемся за значимый элемент»; «1-4 да,
5. Подборка и Подкладка ставится так же, как виджет… сливать да».

## 1. Буфер переходов

Переходы по ответу, вставленному, «Продолжить чтение», закреплённому и указателю пишутся в **буфер
переходов** — местную историю, а не «назад» приложения.

| Что | Решение |
|---|---|
| Сколько буферов | **один на сообщество** (все его группы) и **один на каждую переписку вне сообщества** — группу, личную. Ключ: `community:<id>`, `group:<id>`, `personal:<переписка>` |
| Где хранится | **на устройстве**, на сервер не уходит; переживает закрытие приложения. Настройки устройства, ключ `jumps.<буфер>` — строка до 20 точек |
| Предел | **20 точек**; старые вытесняются |
| Точки | «откуда» — **само сообщение, на ссылке которого нажали** (не край экрана); «куда» — сообщение, к которому перешли; «из Указателей» — вход из вкладки. Закреплённое без сообщения-источника — край экрана, как прежде |
| Новый переход | **в конец**; «вперёд» не стирается |
| Точка «куда» | записывается сразу, **работать начинает, когда сообщение целиком ушло с экрана** |
| Одинаковые точки | **подряд не дописываются** — общее правило: дважды та же ссылка, повторный приход из «Указателей» — одна точка |
| «Назад», «вперёд» | ходят по точкам. Стоим на точке — к предыдущей; ушли с неё — к ней самой. Точка в другой переписке того же буфера — открыть её и перейти; «из Указателей» — во вкладку «Указатели», в ту же сущность |
| Долгое нажатие на «назад» | буфер очищен |
| Ссылка на сообщение группы того же сообщества | открыть ту группу и перейти к сообщению; вне сообщества — как прежде, окно одного сообщения |

**Почему настройки, а не таблица.** Буфер — одна строка на ключ, читается целиком и пишется целиком; миграция
базы ради неё не нужна. Поиска по точкам нет.

## 2. Указатели

**Указатель — это подборка** ([ADR-0050](0050-quote-underlay-properties-links.md) §1): ссылка на сообщение,
на устройстве, до 100 на уровень. Одно хранение для вставки (редактор) и для просмотра и переходов
(вкладка «Указатели» окна «Общение», вместо «Коллекций»).

| Что | Решение |
|---|---|
| Уровень | сообщество; иначе группа; **у личной — своя переписка** (`personal:<переписка>`; до 2026-10-21 — одна общая `self`). Редактор личной переписки вставляет из всех личных |
| Раздел | у **самого указателя** (колонка `section_id`, пусто — «Общий»); разделы — свой набор `pointer_section` |
| Разделы, «Вид» | **механизм «Телефона» целиком, один код** (`SectionsScreen`, `BookViewSheet`), хранение и вид — свои (`pointers.*`) |
| «Убрать раздел» | **кнопка с подтверждением красной плашкой** — у всех трёх наборов разом |
| Сущность | сообщество, группа, личная переписка; строка — как в «Социуме», вторая строка — что это («чат», «группа открытая», «группа закрытая», «сообщество»); долгое нажатие — «В раздел», «Убрать» (с подтверждением) |
| Внутри сущности | сообщения **пузырём ленты**; нажатие по сообщению — переход; рядом или долгое — выделение; «В раздел», «Убрать» |
| Журнал указателей | первым в «Виде» вкладки: раздел, вид сущности, поиск по тексту, галочки; «В раздел», «Убрать», «Перейти» |
| «Назад» вкладки | **повторяет последний переход** по указателю; помнится один |
| Сообщение-цель с сервера | **хранится на устройстве** — ответ сервера как есть (кадр группы или открытая запись), **закрытый ключом устройства** (`ref_cache`). Показ: база устройства → сохранённое → сервер; сервер ответил «нет» — сохранённое удаляется |
| Индекс «кто на кого ссылается» | **открытыми колонками — нет** |
| Ссылки метаданными на сервере | **нет** — ни для закрытых (связь «кто что цитирует» — утечка, которую прячет шифрование тела), ни для открытых (сервер и так читает тело). Вопрос — вместе с «Ответами» |

Миграция базы устройства 22 → 23: колонка раздела у подборки, `self` → `personal:<переписка>`, таблицы
`pointer_section` и `ref_cache`.

## 3. Вставка на строку курсора; слияние текста

- Виджет, подборка, подкладка, список, ряд встают **на строку курсора**, кусок текста режется надвое:
  на пустой строке — вместо неё; в начале непустой — над ней; иначе — под строкой; в последней строке —
  за куском. Выбран виджет — под ним. Подкладка и ответ в ячейку ряда не встают — за ряд.
- «Выше»/«Ниже» над текстом переносят **строки**, а не кусок; новый кусок — только за значимым элементом
  (виджет, список, метка, ряд).
- Убрали или увели разделявшее — **сошедшиеся куски текста одного вида сливаются**, курсор на стыке.
- Метка «Продолжение» — по-прежнему в конце основной части.

## 4. Галочки своего с другого устройства

Сервер пишет «доставлено» и «прочитано» в ленту состояний **пользователя**-отправителя — их забирают все его
устройства. Своё сообщение, написанное с другого своего устройства, приходит входящим, но **получает те же
знаки**: одна галочка (на сервере, раз пришло), две чёрные, две зелёные — по времени написания.
«Ждёт отправки» и «не ушло» бывают только на устройстве, где сообщение написали.

## Следствия

- Формат конверта, тело и сервер не меняются; всё — клиент.
- На втором устройстве указателей и буфера нет: на сервер они не уходят.
- Указатель на личное сообщение, которого нет на устройстве, — «недоступно»: сервер отдаёт личное только
  обёрткой для другого устройства.
