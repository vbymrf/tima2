# ADR-0043. Два вида сборки Android: отладочная раздаётся, быстрая — по надобности

**Дата:** 2026-10-09
**Статус:** принят. Клиент — `5b3ac812`, `29c7f3cf` и коммиты плана (БС).

План — [ПЛАН-(БС)-БЫСТРОЙ-СБОРКИ-И-ПЕРЕНОСА.md](../../doc_mig/ПЛАН-(БС)-БЫСТРОЙ-СБОРКИ-И-ПЕРЕНОСА.md).
Разбор и замеры — [беда 2026-10-08](../../doc_mig/БЕДЫ/2026-10-08-redmi-тормозит-и-свайп.md).
Инструкция — [ВИДЫ-СБОРКИ.md](../../doc_mig/ВИДЫ-СБОРКИ.md).

---

## Контекст

- Людям раздаётся отладочная сборка (`assembleDebug`, флаг `DEBUGGABLE`). Android её заранее не
  компилирует вовсе, компилятор на ходу у неё урезан, профили Compose в неё не попадают.
- На Redmi A3 (MT6765, 32 бита) это давало прокрутку «Звонков» 69 / 150 мс на кадр (середина / 90%)
  и около секунды на смену окна. Та же программа без флага отладки — 22 / 48 мс сразу и 14 / 17 мс
  после компиляции.
- На флаге отладки держится `run-as`, а на нём — инструменты агента: чтение журнала с телефона,
  сценарии на телефонах, наборы и отчёты стенда звонков.

## Решение

Две сборки из одного кода, с одним пакетом `io.tima.app.v2`, одной подписью (`5877a0b5…`) и одним
номером версии.

| | Отладочная | Быстрая |
|---|---|---|
| Команда | `assembleDebug` | `assembleFast` |
| Раздаётся стендом | да | **нет** — руками на нужный телефон; на стенд только по прямому указанию |
| Имя версии | `2.0.N-dev-v2` | `2.0.N-dev-v2-fast` |
| Флаг отладки | есть | нет |
| Журнал | внутри; агент читает `run-as` | внутри; только «Сообщить о проблеме» |
| Сценарии агента, файлы стенда звонков | работают | не работают |

Правила:

1. **Быстрая живёт до ближайшего обновления.** Номер общий: следующая раздаваемая версия встаёт
   поверх и возвращает отладочную.
2. **Скорость меряется только на быстрой.** Замер на отладочной говорит о флаге отладки, а не о коде.
3. **На стендовом телефоне быстрая компилируется сразу после установки**
   (`cmd package compile -m speed-profile -f io.tima.app.v2`). Сама система делает это в фоне, когда
   телефон на зарядке и не используется; каждое обновление сбрасывает компиляцию.
4. Журнал в обеих сборках пишется во внутреннюю память — место не меняется.

## Почему не иначе

- **Раздавать быструю всем** — закрывает агенту журнал и стенд звонков на всём парке. Перенос
  журнала во внешнюю папку это решает, но открывает журнал кабелю и старым Android; заказчик выбрал
  оставить отладочную в раздаче.
- **Своя подпись быстрой** — обновление на месте сломалось бы: Android не ставит пакет с другим
  ключом поверх.
- **R8 сразу** — отдельный план ([ПЛАН-(СЖ)](../../doc_mig/ПЛАН-(СЖ)-R8-ДЛЯ-БЫСТРОЙ-СБОРКИ.md)):
  выигрыш есть и без него, а риск поломок (JNI, сериализация) проверяется только прогоном по телефону.
