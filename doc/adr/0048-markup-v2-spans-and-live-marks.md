# ADR-0048. Разметка v2: узел со своими свойствами, отрезки внутри; знаки — только способ набора

**Дата:** 2026-10-19
**Статус:** принят — решения заказчика 2026-10-19: «1. Согласен. Возвращаешь галочку… 2. Формат v2.
3. да, полные для свойств и короткие для отрезков»; обсуждение того же дня («У нас щас телеграм модель
entities. Но в коде есть еще markdown…», «Узлы были изначально созданы для упрощения отображения,

## Контекст

Тело сообщения — узлы (чистый текст) и разметка JSON (ADR-0011). В разметке v1 три отдельных
списка, связанных номерами: `n` — номера узлов, `blocks` — вид строк со ссылками на номера,
`entities` — оформление внутри строки со ссылкой на номер узла. Разметка длинная и нестрогая: блок
может сослаться на чужой номер, номер — остаться без блока.

Знаки быстрого оформления (`**`, `# `, `-->`) при этом нигде не хранятся: строка ввода разбирает их
при отправке, а редактор держит текст со знаками внутри и прячет их при показе. Отсюда обходы:
экранирование набранных знаков, стирание спрятанного знака, «ждущий» жирный.

## Решение

### 1. Знаки — способ набора, а не хранения

- Галочка «Знаки md» возвращается в редактор и действует и на строку ввода.
- **Включена:** набранные знаки видны **серыми**; знак с парой (`**жирный**`, `~~…~~`) превращается в
  оформление, как только набран закрывающий, — знаки исчезают, слово оформлено. Знак строки без пары
  (`# `, `## `, `### `, `- `, `--> `, ```` ``` ````) превращается сразу, первым.
- **Выключена:** знаки — обычный текст.
- Одинаково в редакторе и в строке ввода («быстрой отправке»).
- Внутри редактор и строка ввода держат **текст и отрезки**, а не текст со знаками. В тело уходят
  узлы и разметка, знаков в нём нет.

### 2. Разметка v2: блоки по порядку, узлы забираются по порядку

```json
{"v":2,"blocks":[
  {"type":"heading","level":1},
  {"e":[["b",7,6],["i",14,6]]},
  {"type":"flex","style":{"background":"amber-soft"},"children":[
    {"type":"cell","nodes":1,"style":{"width":"40"},"e":[["b",6,5]]},
    {"type":"cell","nodes":1,"style":{"width":"60"},"children":[{"type":"emoji","widget":{"text":"🎉"}}]}
  ]}
]}
```

- **Номеров узлов нет.** Блоки идут в порядке документа (сверху вниз, ячейки слева направо, вложенное —
  после своего блока); каждый текстовый блок забирает **следующие** узлы.
- **Сколько узлов забирает блок** — поле `nodes` (число), по умолчанию: абзац, заголовок, цитата, пункт
  списка, блок кода — 1; ряд, строка ряда, ячейка, таблица, список, разделитель, виджет — 0. Узлов в
  теле ровно столько, сколько забрали блоки, — иначе разметка не принимается.
- **Свойства — полными именами:** `type` (нет — абзац), `level`, `style` (имена палитры и ступени, как
  в v1), `widget`, `children`, `nodes`.
- **Отрезки — коротко, внутри своего блока:** `"e":[[вид, начало, длина], …]`; виды: `b` жирный, `i`
  курсив, `u` подчёркнутый, `s` зачёркнутый, `h` маркер, `c` код, `l` ссылка (четвёртым — адрес), `m`
  упоминание (четвёртым — ник, пятым — человек), `t` метка (четвёртым — слово). Границы — в знаках
  текста блока; у блока из нескольких узлов (многострочная цитата) — по его узлам, сложенным через
  перевод строки.
- Отрезки — только где оформлена часть строки: заголовку, цитате и ячейке без оформления их нет.
- Простое сообщение — по-прежнему один узел и пустая разметка.

### 3. Версии

- Пишется только **v2** (`"v":2`). Разметка без `v` — **v1**, читается как прежде: на стенде живут
  сообщения и клиенты прежнего вида.
- Внутри клиента — одна модель разметки (v1-классы); v2 — её запись. Разбор, проверка
  (`MarkupRules`), показ и правка по узлам не меняются.
- Новый вектор `markup_json_v2` — разметка образцового сообщения в v2; прежний `markup_json` остаётся
  и сверяет чтение v1.
- Сервер разметку не разбирает (проверяет только, что это JSON) — его выкатка не нужна.

### 4. Ячейка — область со своим списком блоков

Ячейка, как `div`: своя ширина и стиль, внутри те же блоки, что в сообщении, — абзацы, заголовки,
списки, цитаты, код и виджеты. Стиль ячейки (цвет, фон, размер, выравнивание) действует на всё внутри.
В v2 это `"children"` ячейки; однострочный текст ячейки v1 (`"nodes":1` у самой ячейки) читается как
прежде.

## Следствия

- Разметка короче (образцовое сообщение: 606 знаков вместо 770; набранное с оформлением — примерно
  вдвое) и строгая: число узлов проверяется.
- Сообщение из одного виджета (без текста): узлов нет, тело читается с одним пустым узлом — так
  было всегда; v2 это учитывает.
- Сервер пишет у записи канала `markup_version = 1` по-прежнему: версию клиент читает из самого
  JSON (`"v"`). Клиент до 179 разметку v2 не разберёт — покажет сообщение без оформления.
- Правка по узлам (ADR-0045) не меняется: номер узла — его место в теле.
- Если разметку нельзя записать в v2 (номера узлов не по порядку — у собранного нашим кодом так не
  бывает), пишется v1: она по-прежнему принимается.
- Работа идёт по [ПЛАН-(ФР)](../../doc_mig/ПЛАН-(ФР)-ФОРМАТА-РАЗМЕТКИ.md): формат → редактор на
  отрезках → строка ввода → ячейка со своими блоками.

## Отвергнуто

- **Хранить markdown в теле** — знаки не строги, их разбор у разных клиентов расходится, а
  оформление ячеек и виджетов ими не выразить.
- **Отрезки по всему тексту, как в Телеграме, без узлов** — правка по узлам и показ по узлам
  удобнее, смещения внутри узла короткие и не сдвигаются от правки соседнего.
- **Оставить v1 и переделать только редактор** — длинный нестрогий JSON с номерами остался бы.
