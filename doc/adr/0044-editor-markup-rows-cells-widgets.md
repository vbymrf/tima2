# ADR-0044. Разметка редактора: ряды, ячейки, виджеты, стили именами

**Дата:** 2026-10-18
**Статус:** принят — решения заказчика 2026-10-15…18, собраны в
[doc_mig/РЕДАКТОР-СООБЩЕНИЙ.md](../../doc_mig/РЕДАКТОР-СООБЩЕНИЙ.md).
**Дополняет:** [ADR-0011](0011-message-content-model.md) — модель «узлы + разметка» остаётся, здесь
только то, что редактор кладёт в разметку.
**Порядок работ:** [doc_mig/ПЛАН-(РС)-РЕДАКТОРА-СООБЩЕНИЙ.md](../../doc_mig/ПЛАН-(РС)-РЕДАКТОРА-СООБЩЕНИЙ.md).

---

## Контекст

ADR-0011 завёл формат: текст — массив узлов (`MessageBody.nodes`), структура — разметка JSON
(`MessageBody.markup`, `Markup.kt`), закрытый каталог типов с `UNKNOWN`
(`MarkupTypes.kt`). Набор блоков там общий — «абзац, заголовок, контейнер, таблица». Редактор
сообщений (решения 2026-10-17…18) требует конкретики: ряд ячеек с ширинами, виджеты в ячейках,
стиль ряда и ячейки, ссылки на другие сообщения (ответ, вставленное из подборки, подкладка).

## Решение

### 1. Формат конверта не меняется

Всё новое — **содержимое разметки**, которое прежний читатель пропускает: незнакомое поле
игнорируется (`ignoreUnknownKeys`), незнакомый тип блока — `UNKNOWN` и показывается текстом.
Полей `MessageBody` не добавляется, `Markup.version` остаётся 1, `format_version` конверта не
растёт.

### 2. Узел

| Где текст | Узел |
|---|---|
| вне ряда и таблицы | каждый абзац, заголовок, пункт списка, цитата, блок кода — свой узел (как в ADR-0011) |
| ячейка ряда | **ячейка — один узел** |
| ячейка таблицы | **ячейка — один узел** |

**Ниже ячейки оформление не идёт** (заказчик 2026-10-18): внутри узла ячейки только инлайн-
оформление (жирный, курсив, маркер…) и переносы строк. Отсюда: **в ячейке ряда один виджет
«Текст»** — это узел ячейки, — и сколько угодно прочих виджетов.

Правка сообщения (новая запись с изменёнными узлами, `doc_mig/РЕДАКТОР-СООБЩЕНИЙ.md` §8) меняет
узлы; правка ячейки не трогает соседние.

### 3. Блоки

Новые значения `BlockType` (провод — строка `wire`):

| `wire` | Что | Дети / узлы |
|---|---|---|
| `flex` | **ряд**: 1–4 ячейки в строку, высота по содержимому | дети — `cell` |
| `cell` | ячейка ряда или таблицы (тип уже есть) | `nodes` — узел ячейки (0 или 1); дети — виджеты |
| `table` → `row` → `cell` | таблица (типы уже есть) | ячейка — один узел |
| `divider` | разделитель `---` между узлами | — |
| `code_block` | блок кода | один узел |
| `image` | виджет «Картинка» | — |
| `link` | виджет «Ссылка» | — |
| `cloud` | виджет «Облако» | — |
| `map` | виджет «Карта» | — |
| `contact` | виджет «Контакт» | — |
| `reply` | блок ответа `@Ник` | — |
| `quoted` | вставленное из подборки | — |
| `emoji` | крупный эмоджи | — |
| `underlay` | подкладка — **только в конце сообщения** | — |

Новый `EntityType`: `highlight` — маркер (`==текст==`).

Данные виджета — объект `widget` у блока (типизированный, все поля необязательные):

| Поле | Кому | Значение |
|---|---|---|
| `media` | `image`, `link` (картинка карточки) | номер в `MessageBody.media` |
| `url` | `link`, `cloud` | адрес |
| `mode` | `link` | `plain`, `button`, `card` |
| `title`, `description` | `link` (карточка), `cloud` (имя файла) | текст |
| `kind` | `cloud` | `file`, `document`, `audio`, `video` |
| `lat`, `lon`, `label` | `map` | координаты и подпись |
| `user_id`, `name`, `phone` | `contact`, `reply` | кто |
| `text` | `emoji` | сам эмоджи |
| `ref` | `reply`, `quoted`, `underlay` | ссылка на сообщение: `kind` (`personal`, `group`, `channel`), `container`, `message` |
| `author` | `quoted`, `underlay` | показывать автора первым |
| `cut` | `quoted` | `full` или `cut` (по соседу в ряду, иначе три строки) |
| `lines` | `underlay` | сколько строк показать до «Продолжить чтение» |

**Ссылка — не копия.** У `reply`, `quoted`, `underlay` в теле только `ref`; содержимое клиент берёт
выдачей одного сообщения по номеру, а сервер отвечает либо сообщением, либо служебным «уровень N
— недоступно» (один механизм доступа, `РЕДАКТОР-СООБЩЕНИЙ.md` §11.3).

### 4. Стиль — имена и ступени

Стиль блока — `MarkupBlock.style`, **только изменённое**; не указано — по умолчанию.

| Ключ | Где | Значения |
|---|---|---|
| `width` | `cell` ряда | проценты, целое; сумма по ряду — 100 |
| `background` | `flex`, `cell`, `table` | **имя палитры** |
| `color` | `cell`, текст вне ряда | имя палитры |
| `size` | то же | `smaller`, `normal`, `larger` |
| `align` | то же | `start`, `center`, `end` |
| `valign` | `cell` | `top`, `center`, `bottom` |
| `padding` | `flex`, `cell` | `none`, `small`, `normal`, `large` |
| `divider` | `flex`, `table` — после блока | `hidden`, `1`, `2`, `4` |
| `divider_color` | то же | имя палитры |
| `merge` | `cell` таблицы | `up` (`^^`), `left` (`<<`) |

**Цвета — только имена палитры**, кодов нет: у имени своё значение в светлой и тёмной теме
(таблица имён — клиент, `core-ui`). Незнакомое имя — свойство отбрасывается.

**Фон.** ADR-0011 §9 запрещает «полноэкранную заливку»; `StyleCascade` выполнял это, вырезая фон
из любого слоя документа. Теперь граница точнее: **фон ряда, ячейки и таблицы — именем палитры —
разрешён**, он внутри пузыря и экран не заливает; фон **документа, чата и сообщества** по-прежнему
вырезается. Контраст текста проверяется с фоном его ячейки — защитный пол действует как прежде.

### 5. Пределы

| Что | Предел |
|---|---|
| текст — массив узлов | 4096 знаков UTF-16 ([ADR-0019](0019-message-level.md) §3) |
| разметка JSON до сжатия | 32 КБ |
| открытое сообщение целиком на сервере | 48 КБ (было 16 КБ) |
| ячеек в ряду | 1–4 |
| рядов в сообщении | 20 (предложение, правится на примерах) |
| картинок в сообщении | 10 |
| превью фото без текста | 20 КБ каждое, до 10 в сообщении |

Проверка — одна функция в `messenger-crypto` для отправки, приёма и вкладки JSON редактора: каталог,
ширины, пределы, имена палитры, ступени. Не прошло на отправке — не отправляется; на приёме —
сообщение показывается без оформления (как испорченная разметка по ADR-0011).

### 6. Показ: без горизонтальной прокрутки

ADR-0011 §8 «таблицы прокручиваются горизонтально» **отменяется** (заказчик 2026-10-18):

- что не вмещается в ширину, **уходит вниз** — ячейки ряда встают в столбик;
- у каждого виджета минимальный размер, невидимого содержимого нет;
- таблица допустима, если в её ячейку помещается «99» на самом узком телефоне (пузырь около
  360 dp) при шрифте сообщений 22; иначе редактор её не отправляет;
- текст в ячейке таблицы переносится где кончилась ширина, без правил переноса.

`ContentProfile.horizontalScroll` уходит.

## Последствия

- Каталог `MarkupTypes` и модель `Markup` растут добавлением; прежние сообщения читаются как были.
- Сервер разметку приватного сообщения не видит; публичную по-прежнему проверяет только как JSON
  (`channels.go`) — новая проверка пределов на сервере — только размер.
- Появляется вектор разметки `schema/test-vectors` (ADR-0011 «открыто: `markup_json`») — образец
  сообщения с рядом, таблицей и виджетами.
- ADR-0011 §8 и §9 читаются вместе с этим ADR: §8 — без прокрутки, §9 — фон блока разрешён.
