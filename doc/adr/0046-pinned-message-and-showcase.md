# ADR-0046. Закреплённое сообщение и описание — сообщения уровня 0

**Дата:** 2026-10-18
**Статус:** принят — решения заказчика 2026-10-18 («Перед выкаткой нужно добавить закрепление
сообщения… у нас нет места для сообщений уровня 0», «Согласен со всеми предложениями… записывай план»,
«Сообщество не имеет сообщений уровня выше 0. Но 0 — имеет… Так же супер сообщение»).

## Контекст

Два пробела перед выкаткой редактора.

1. **Закрепления не было нигде.** Важное сообщение в переписке тонет в ленте.
2. **Сообщениям уровня 0 негде жить.** Сервер хранил их с самого начала — описание группы не особое
   поле, а обычное сообщение уровня 0 (ADR-0019 §4), — но клиент показывал их в ленте вперемешку с
   разговором, а не вступившему не показывал вовсе. Получалось, что описание видит только тот, кому
   оно уже не нужно.

## Решение

### 1. Закреплённое — одно на контейнер, сервер знает его открыто

- Одно сообщение на личную переписку, группу, канал. Новое закрепление заменяет прежнее.
- **Номер закреплённого хранит сервер открыто** — таблица `pins (container_kind, container_id,
  message_id, pinned_by, pinned_at)`. Заказчик: «иначе никто не узнает; метаданные у нас открытые».
  Так и для личной переписки: номер сообщения не раскрывает содержимого, а без сервера второе
  устройство и собеседник закрепления не узнали бы.
- **Права:** личная — любой из двух участников закрепляет, меняет и снимает; группа и канал —
  модератор и выше (`403 not_moderator`). Закрепить можно только живое сообщение этого же контейнера,
  не правку и не комментарий (`409 message_not_pinnable`).
- **Удалённое закреплённое открепляется само** — в той же транзакции, что пометка удаления;
  отдельного события нет: клиенты узнают по `message.deleted`.
- Событие `message.pinned {chat_id | group_id, message_id, by}` (0 — сняли) — участникам. У канала
  событий нет, как нет их у удаления записи: лента канала забирается при открытии.
- Клиент: «Закрепить» / «Открепить» в меню сообщения, полоса «Закреплено» под шапкой (нажатие —
  переход, «✕» — снять), **служебная строка словами читающего без уведомления**: «Вы закрепили
  сообщение», «Аня закрепил(а) сообщение».

### 2. Описание — уровень 0 только окном «Описание»

- **Уровень 0 забирается только когда человек открыл описание.** В ленту, уведомления и счёт нового
  он не попадает — «как страница пользователя: не зашёл — ничего не увидел». Отсюда:
  - сервер не рассылает событий о новом сообщении уровня 0 и не поднимает вершину;
  - история группы и лента канала принимают необязательный `no_showcase=1` (API расширяется,
    установленные клиенты не ломаются), новый клиент его шлёт;
  - клиент прячет уровень 0 из ленты группы, но держит под рукой — подкладке и переходу.
- **Не больше 50** сообщений уровня 0 у сущности; 51-е — `409 showcase_full`. Сужение уровня
  освобождает место. Прежнее «отдельным пределом не ограничивается» отменено.
- **Есть у каждой сущности** — группы, канала, сообщества (у сообщества только уровень 0 и бывает).
- Выдача `GET /{groups|channels|communities}/{id}/showcase` — от старых к новым, вместе с номером
  суперсообщения. Права — как у уровня 0: участник и тот, кому открыта карточка.
- Окно «Описание» открывается аватаром в разделах (Каталог, Друзья), текстом шапки группы; не
  вступившему нажатие на группу сообщества открывает «Описание», а не пустую переписку. Внизу —
  «Вступить» или «Подписаться».

### 3. Суперсообщение — вид описания задаёт владелец

- У каждой сущности место под одно суперсообщение, по умолчанию пустое
  (`showcase_super` у `groups`, `channels`, `communities`). Ставит и снимает **владелец**
  (`PUT/DELETE …/showcase/super`); суперсообщение — живое сообщение уровня 0 этой же сущности.
- Владелец создаёт его редактором: в документе уже стоят **подкладки всех сообщений уровня 0
  списком** (по три строки, «Продолжить чтение»); вид меняет как у любого сообщения. У группы
  сообщение уходит обычной очередью, и номер ставится суперсообщением, когда пришёл от сервера; у
  сообщества переписки нет — редактор открывается в самом окне.
- **Показ:** есть суперсообщение — оно; нет и сообщений до трёх — лентой целиком; больше — списком по
  три строки, нажатие открывает сообщение **одно, без ленты**.

## Следствия

- Описание не хранится на устройстве: окно забирает его каждый раз. Без сети — «не загрузилось».
- Установленные клиенты (до 168) уровень 0 по живому каналу больше не получают и в истории видят
  его как прежде — расхождение исчезает с обновлением.
- Закрепление канала сервер умеет, а клиент нет: окна ленты канала в приложении нет (страница
  человека — его лента). Появится вместе с ним.
- Журнал: `PIN-MSG` (закреплено, снято, отказ кодом, событие), `SHOWCASE` (открыто — вид, сколько,
  есть ли суперсообщение, как показано).

## Отвергнуто

- **Закрепление только на устройстве** — второе устройство и собеседник его не видят.
- **Номер закреплённого внутри зашифрованного служебного сообщения** — закрытость ничего не даёт
  (номер — метаданные, сервер и так знает номера), а «удалённое открепляется само» стало бы делом
  каждого клиента.
- **Описание полем группы** — одно поле не вмещает ни оформления, ни нескольких частей, ни уровня;
  сообщение уровня 0 уже было и его же проверяют подпись и права.
