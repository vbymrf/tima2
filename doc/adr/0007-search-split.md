# ADR-0007: Раздельный поиск — приватное локально, публичное на сервере

**Статус:** принят · **Дата:** 2026-07-12

**Поправки:** [Поправка-1 (2026-09-24)](#поправка-1-2026-09-24-третий-вид--точечный-поиск-по-справочнику)
— поиск по нику не ложится ни в приватный, ни в публичный.

## Контекст

Приватный контент хранится на сервере только как ciphertext — сервер физически не может его индексировать. В исследованиях фигурировали Elasticsearch и OpenSearch одновременно.

## Решение

| Контент | Индекс | Где |
|---------|--------|-----|
| Личные чаты, личные группы, личные коллекции | **SQLite FTS5** | Только на устройстве, по расшифрованному локальному кэшу |
| Публичные группы, каналы, публичные медиа, профили, каталог | Серверный поиск | MVP: **PostgreSQL FTS**; при росте: **OpenSearch** |

- Глобальная строка поиска ([17-global-search.md](../doc_UI/17-global-search.md)) объединяет оба источника на клиенте.
- OpenSearch (не Elasticsearch): открытая лицензия, совместимый API. Триггер миграции — деградация PG FTS под нагрузкой ([scaling.md](../07-deployment/scaling.md)).

## Последствия

- Поиск по приватной истории работает только по данным, синхронизированным на устройство ([sync-offline.md](../04-data/sync-offline.md)).
- Детали схем индексации: [search-indexing.md](../04-data/search-indexing.md).

## Поправка-1 (2026-09-24): третий вид — точечный поиск по справочнику

Таблица выше делит поиск надвое: приватное ищется местным FTS5, публичное — серверным
полнотекстовым. Поиск по нику не ложится ни в одну строку и стоит рядом с ними.

| Вид | Где | По чему |
|---|---|---|
| Приватный | устройство, FTS5 | расшифрованная история |
| Публичный | сервер, PG FTS | группы, каналы, медиа, профили |
| **Точечный по справочнику** | **сервер, точное сравнение и подстрока** | **только ник** |

Предел частоты стоит **только у поиска по части ника**. У точного (`GET /nicknames/{nick}`)
его нет — он отвечает про один полный ник в 10…20 знаков, и перебирать им пространство
имён несоизмеримо дороже.

`GET /api/v1/nicknames?q=` — единственный способ найти человека, у которого номера нет
вовсе. Отдельной ручкой, а не параметром к публичному поиску: у неё другая природа ответа
и **свой предел частоты**, и смешать их значит однажды случайно распространить предел
одного на другое.

**Поиска по имени на сервере по-прежнему нет и не будет** (решение 2026-09-05): имя о
человеке пишет кто-то другой, и выдавать по нему каталог людей нельзя. Ник человек
выбирает себе сам, и ищут по нему открытым текстом — искать по зашифрованному нечем.

**Цена названа заранее: это перебор пространства имён.** Три предела — минимум три знака,
десяток в выдаче, частота по устройству вдвое строже точного поиска — не аккуратность, а
часть барьера от спама. Разбор — [ADR-0028](0028-contact-lists-and-blocking.md) §10.
