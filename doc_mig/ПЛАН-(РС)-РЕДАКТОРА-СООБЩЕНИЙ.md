### РС1. Формат разметки — **сделано** 2026-10-18 (коммит в отчёте)

`MarkupTypes` (маркер, ряд `flex`, разделитель, блок кода, виджеты, подкладка), `MarkupWidget` и
`MarkupRef` в `Markup.kt`, проверка `MarkupRules` (строго и мягко), фон блока именем палитры в
`StyleCascade`, `MessageContent.firstText()`, вектор `markup_json`. Не сделано здесь: текст для
поиска на сервере — РС3.


- Каталог `MarkupTypes`: новые типы — маркер (`==`), ряд с шириной ячеек, виджеты (картинка,
  ссылка трёх видов, облако, карта, контакт, ответ, из подборки, эмоджи), подкладка, стиль ячейки и
  ряда (фон, цвет, размер, выравнивание, отступ, разделитель). Незнакомое → `UNKNOWN`, показывается
  текстом — прямая совместимость уже заложена.
- Модель в общем коде (`messenger-crypto`): разбор и сборка разметки, **проверка** — каталог, сумма
  ширин 100, пределы (ячейки, ряды, картинки, размер разметки), палитра, ступени, защитный пол.
  Одна проверка — для отправки, приёма и вкладки JSON редактора.
- **Формат конверта не меняется**: `nodes` и `markup` уже есть, новое — только содержимое
  разметки. Если ADR из РС0 решит иначе — по правилу проекта: новая версия, новый домен в
  подписываемых байтах, новый вектор, прежняя принимается (`.cursor/rules/crypto-invariants.mdc`).
- **KAT-вектор разметки** в `schema/test-vectors/` — заводится здесь (ADR-0011 «не заведён»).
- Текст для уведомления и поиска (Решения §12) — функция «первый узел текста без знаков».

**Проверки:** разбор и сборка туда-обратно; отказ на каждое нарушение; вектор; незнакомый тип не
роняет сообщение.

### РС2. Быстрое оформление (Решения §7) — **разбор сделан** 2026-10-18; показ в строке ввода — РС5

`QuickMarkdown.parse` / `plain` в `messenger-crypto`: строки (заголовки, список с вложенностью и
прижатием, цитата, разделитель, блок кода, таблица с `^^`/`<<` и выравниванием) и оформление внутри
строки (пары знаков по правилу CommonMark, код, голые адреса, экранирование, хештег, упоминание).
Любой разбор проходит строгую проверку `MarkupRules`. Знаки серым, возврат знака стиранием и
переключатель — в строке ввода (РС5).


- Разборщик упрощённого Markdown → узлы и разметка; обратный путь — для правки и для «Знаки md»
  выключено.
- Строка ввода: знаки серым, текст оформлен; стирание сразу после превращения возвращает знак.
- Переключатель «Знаки md» — настройка, одна на всё.

**Проверки:** таблица случаев §7, включая ложные срабатывания (`__init__`, `C++`, `2*3*4`,
`#тег`, адрес с `_`), вложенность пробелами, таблица с `^^` и `<<`, экранирование.

### РС3. Сервер — **частично** 2026-10-18

**Сделано** (коммит в отчёте): предел открытого сообщения 48 КБ; предел файла 50 МБ (10 МБ чужому
— у почтальона, когда получатель известен); выдача одного сообщения по номеру — личная переписка,
группа, канал — с заглушкой `unavailable` (`level`, `missing`, `closed`); лента страницы со `stubs=1`
отдаёт заглушку вместо пропажи (без параметра — как было, установленные клиенты не задеты).

**Правка — сделана** 2026-10-18 новой версией конверта (решение заказчика «Правку делаем новой
версией конверта»; [ADR-0045](../doc/adr/0045-message-edit-envelope-v3.md)): версия 3 личного
конверта и `tima.group_message.v3` с номером исходного под подписью, векторы `canonical_bytes_v3` и
`group_message_canonical_v3`; сервер — миграция 0074, проверки (автор, не правка правки, не больше
трёх, до смены ключа), без уведомления, счёта и вершины; клиент — приём и проверка, наложение на
исходное, «изменено» (`ChatLine.edits`), `EditMessage`. **Кнопка «Изменить»** — с меню сообщения
(РС7): меню ещё нет. Коммиты — в отчёте.

**Удаление у всех — сделано** 2026-10-18: `DELETE /chats/{chat}/messages/{n}` (автор) и
`DELETE /groups/{group}/messages/{n}` (автор, модератор, админ), правки уходят с исходным, событие
`message.deleted`. **Приём версии 1 снят на сервере** (поправка к ADR-0013, заказчик 2026-10-18).

**Осталось:** пометка «только продолжение» — вместе с отправкой подкладки (РС7: пока её никто не
шлёт); `POST /media/urls`, квота; почтальон (ПФ4); текст для поиска открытых уровней.


Выкатывается **раньше** клиента (`.cursor/rules/server-compatibility.mdc`): миграции добавляющие,
API расширяется.

- Предел открытого сообщения: сейчас 16 КБ на всё (`maxPlainPayloadBytes`) → **48 КБ**, разметка
  — до 32 КБ, узлы — 4096 знаков (Решения §1).
- Предел файла: `maxMediaBytes` сейчас 2 ГБ (и `request_body max_size 2GB` у Caddy) → **10 МБ, себе
  50 МБ** (Решения §6); 2 ГБ снят.
- Медиа внутри сообщения живут, пока живо сообщение (Решения §3).
- Текст для поиска открытых уровней (Решения §12).
- Удаление у всех и правка (Решения §8): маршрут удаления, событие «удалено», запись правки
  (не больше 3, до смены ключа, без уведомления и счётчика).
- Продолжение другого уровня (Решения §11.3): открытая пометка «только продолжение» (колонка,
  миграция) — такое сообщение не попадает в выдачу ленты.
- **Один механизм доступа по ссылке** (Решения §11.3, Н9): выдача одного сообщения по номеру —
  сообщение или служебный ответ «уровень N — недоступно»; лента страницы (`ListFeed`) вместо
  молчаливого пропуска перенесённого отдаёт тот же ответ. Это **изменение поведения стенда** —
  разрешено заказчиком 2026-10-18 вместе с решением.
- `POST /media/urls` пачкой; квота загрузок.
- Почтальон для личных файлов — этап [ПЛАН-(ПФ)](ПЛАН-(ПФ)-ПЕРЕДАВАЕМЫХ-ФАЙЛОВ.md) (§2).

**Проверки:** тесты сервера (`.cursor/skills/adaptive-test-runner/`); выкатка на стенд
по `ПЕРЕУСТАНОВКА-СЕРВЕРА.md` и `ВЕРСИИ/СТЕНД.md`, установленные клиенты не ломаются.

### РС4. Показ в переписке — **текстовые блоки сделаны** 2026-10-18

- Ссылка тремя видами, блок ответа, контакт, карта, вставленное из подборки, подкладка с
  «Продолжить чтение».
- Кеш рендера (ADR-0011 §10).
- **Проверка производительности** (Решения §14) на Redmi. Не уложились — урезаем пределы.

### РС6. Редактор (Решения §10)

Срезами, каждый — живой на телефоне:

1. **Окно и текст**: шапка (назад, показать, отменить и повторить на 50 шагов, уровень со списком
   описаний, отправить), разделы и лента (шесть с половиной, стрелки на ПК), раздел «Текст»:
   Абзац, выделение, Символ, «Знаки md».
2. **Вставка**: Картинка (из исходного файла под ширину), Ссылка, Эмоджи, Облако, Карта, Контакт,
   Ответ; «С оформл.» — из HTML только текст и простое оформление, картинка из буфера сама по
   себе.
3. **Разметка**: ряд 1–4 ячейки, таблица, ячейки, объединение, выше и ниже, удаление; перенос
   виджета пальцем и мышью.
4. **Стиль**: для выбранного; отступ ступенями; JSON с проверкой из РС1.
   Проверка «99 в ячейке таблицы» для пузыря 360 dp и шрифта 22: не помещается — таблица красная,
   просьба изменить, отправить нельзя.
5. **ПК**: сочетания клавиш, перетаскивание файлов.
6. **Личная страница**: тот же редактор.

### РС7. Меню сообщения, подборка, подкладка, переходы (Решения §11) — **меню сделано** 2026-10-18

**Сделано** (коммиты в отчёте): меню по нажатию со всеми пунктами; своё — «Изменить или удалить»
с выбором; «Изменить» с полосой и «изменено»; «Удалить у себя», «Удалить у всех» с подтверждением
и строкой «Сообщение удалено»; «Ответить» — блок ответа первым в разметке тела и полоса над вводом;
«Поделиться» (Android — системное, ПК — в буфер); «Скопировать текст»; «Добавить в Подборку» —
ссылки на устройстве, до 20 на уровень; «Перенести себе» — из группы. Живьём на Honor: меню своего,
выбор, правка в строке ввода и отмена, копирование, подборка.

**Осталось:** выделение части долгим нажатием; подборка сообщества (сейчас уровень — группа:
принадлежность группы сообществу клиент ещё не знает); показ и вставка подборки — с редактором
(РС6); переход по нажатию на блок ответа и «назад/вперёд» (§11.4); `@Ник` набранным текстом —
ответ на последнее сообщение человека; «Поделиться» — картинки; подкладка.

- **Меню по нажатию — первым делом и сразу со всеми пунктами** (заказчик 2026-10-18). Чужое:
  Ответить · Поделиться · Скопировать текст · Добавить в Подборку · Перенести себе. **Своё:
  вместо «Ответить» одна кнопка с выбором — Изменить · Удалить у себя · Удалить у всех** (себе не
  отвечаем; заказчик 2026-10-18), дальше те же. Неотправленное и ждущее — по-прежнему
  `FailedMessageSheet`.
- Выделение части долгим нажатием.
- «Изменить» (Решения §8): строка ввода получает `EditMessage.source`, над ней полоса «Изменение» с
  отменой, отправка — `EditMessage.edit`; кнопки нет, когда правок три; отказы словами (другое
  строение; ключ сменился — `edit_closed`). Пометка «изменено» у строки — по `ChatLine.edits`.
- «Удалить у себя» — только на устройстве. «Удалить у всех» (Решения §8) — маршрут удаления на
  сервере (сделан, РС3) и событие `message.deleted` у получивших → строка «Сообщение удалено»;
  правки скрываются вместе с исходным; вернуть нельзя — спросить подтверждение.
- «Поделиться» наружу — всё, что можно, оформление до понятного другим (Решения §11.5); приём
  «Поделиться» в TIMA (Решения §4).
- Подборка своя у верхнего уровня, вставка только в его пределах.
- Подкладка: только в конец, списком; ряд или таблица первыми — целиком.
- «Назад» и «вперёд» над «вниз», цепочка переходов.

### РС9. Проверка и выкатка

- Модульные тесты, векторы, проверки производительности.
- Живьём на Redmi, realme и ПК: личная переписка, личная группа, публичная группа, канал,
  сообщество, личная страница, комментарии.
- Выкатка: сервер (РС3) → APK и MSI → объявление на стенде.

**Первая полезная выкатка:** РС1 + РС2 + РС3 (пределы) + РС4 (без виджетов) + РС5 — быстрое
оформление в строке ввода и его показ, без редактора.

## 3. Риски

- Разметка едет внутри шифрованного тела: ошибка формата бьёт по всем перепискам — поэтому вектор
  и проверка (РС1) раньше экрана.
- Перенос пальцем и мышью в Compose на Android и ПК — пробовать на живых устройствах в первом же
  срезе РС6.
- Буфер обмена с HTML на Android и ПК устроен по-разному.
- Нагрузка на прокрутку при тяжёлых сообщениях — проверка в РС4, до редактора.
- Объём большой: выкатывать по срезам (§1, «Первая полезная выкатка»), а не одним куском.
