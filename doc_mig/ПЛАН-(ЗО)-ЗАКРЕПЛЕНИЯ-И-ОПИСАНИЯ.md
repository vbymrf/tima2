# План: закреплённое сообщение и описание (сообщения уровня 0)

Заведён 2026-10-18 по слову заказчика: «Перед выкаткой нужно добавить закрепление сообщения… И второе
— у нас нет места для сообщений уровня 0… Сделай план», затем «Согласен со всеми предложениями…
записывай план». Делается **до выкатки** (журнал работ, Н23).

**Статус 2026-10-18: решения приняты, не начат.** Этапы ЗО1…ЗО6.

## 0. Что уже есть

- **Закрепления нет нигде** — ни на сервере, ни в клиенте.
- **Сообщения уровня 0 сервер хранит и отдаёт** — описание группы с самого начала не особое поле, а
  обычное сообщение уровня 0 (ADR-0019 §4; тест `TestКарточкаЛичнойГруппыТриСостояния`). У
  сообщества так же ([ПЛАН-(СО)](ПЛАН-(СО)-СООБЩЕСТВ.md)). **Места в клиенте для них нет**: не
  вступивший видит пустоту, хотя описание есть.
- У личных переписок своего уровня 0 нет: открывается страница человека, а её записи уровня 0 и есть
  его описание (страница и лента — все личные записи уровня 0).

## 1. Решения (заказчик 2026-10-18)

### Закрепление

| Что | Решение |
|---|---|
| Сколько | **одно** сообщение на переписку, группу, канал — сверху |
| Кто | личная переписка — **любой из двух** закрепляет, меняет и снимает; группа и канал — **модератор и выше** |
| Где хранится | **на сервере, открыто** — номер закреплённого: «иначе никто не узнает; метаданные у нас открытые». Так и для личной переписки |
| Видно | полоса под шапкой: строка закреплённого; нажатие — переход к нему (§11.4 Решений редактора, «назад» есть) |
| Служебная строка | «Аня закрепила сообщение» в ленте — **показывается**, без уведомления |
| Удалили закреплённое | закрепление снимается само |

### Описание — сообщения уровня 0

| Что | Решение |
|---|---|
| Когда забираются | **только когда человек зашёл их посмотреть**. В других случаях они **не относятся ни к уведомлениям, ни к сообщениям, которые человек видит в группе** — как страница пользователя: не зашёл — ничего не увидел |
| Сколько | **не больше 50** сообщений уровня 0 у группы, канала, сообщества. Прежнее «отдельным пределом не ограничивается» ([ПЛАН-(Г)](ПЛАН-(Г)-СОЦИУМА.md), [ПЛАН-(СО)](ПЛАН-(СО)-СООБЩЕСТВ.md) §СО) заменено |
| Где открывается | нажатие на аватар группы, канала, сообщества в разделах (Социум, Каталог); нажатие на текст в шапке открытой группы или канала |
| Порядок | **от старых к новым** |
| Личные | своего описания нет — страница человека, её записи уровня 0 |

### Суперсообщение уровня 0

- **У каждой группы, канала, сообщества по умолчанию есть место под одно суперсообщение** — пустое.
- **Настраивает владелец сам**: создаёт суперсообщение и через редактор вставляет в него сообщения
  уровня 0 — **подкладками списком**, как «Продолжить чтение» ([РЕДАКТОР-СООБЩЕНИЙ.md](РЕДАКТОР-СООБЩЕНИЙ.md)
  §11.3). За вид — как выглядят описания — отвечает владелец.
- **Суперсообщения нет** — описание показывается **списком всех сообщений уровня 0**, у каждого **три
  строки** и переход к сообщению **«без ничего»**: открывается само сообщение, одно, а не лента.
- **Сообщений уровня 0 не больше трёх** — показываются **полностью лентой**.

## 2. Этапы

### ЗО1. Сервер: закрепление

- Миграция (добавляющая): номер закреплённого у личной переписки, группы, канала; кто и когда.
- `PUT /chats/{chat}/pin`, `/groups/{g}/pin`, `/channels/{c}/pin` с номером; `DELETE` — снять. Права:
  личная — участник переписки; группа и канал — модератор и выше (403 `not_moderator`).
- Номер обязан быть сообщением этого же контейнера, не удалённым, не правкой; иначе 409.
- Событие `message.pinned` (номер или 0 — снято, кто) в той же полосе, что `message.deleted`;
  удаление закреплённого снимает закрепление и шлёт то же событие.
- Номер закреплённого — в выдаче переписки, группы, канала.

### ЗО2. Сервер: описание и суперсообщение

- Предел: **не больше 50** сообщений уровня 0 у контейнера (группа, канал, сообщество); 51-е — 409
  `showcase_full`. Правка уровень не меняет, сужение уровня 0 → 1…3 освобождает место.
- Выдача описания: `GET /groups/{g}/showcase` (и у канала, сообщества) — суперсообщение, если есть, и
  сообщения уровня 0 **от старых к новым** (до 50). Права — как у выдачи уровня 0 сейчас: получивший
  карточку и участник.
- Место под суперсообщение — у каждого контейнера по умолчанию пустое: номер суперсообщения, ставит
  и снимает **владелец** (`PUT/DELETE …/showcase/super`). Само суперсообщение — сообщение уровня 0,
  в список описаний не входит.
- **Уровень 0 не идёт в ленту**: история группы и канала принимает необязательный параметр «без
  уровня 0» (API расширяется, прежние клиенты на стенде не ломаются), новые клиенты его шлют; события
  о новом сообщении уровня 0 — без уведомления и без счёта нового.

### ЗО3. Клиент: закрепление

- Меню сообщения: «Закрепить», у закреплённого — «Открепить»; в группе и канале — только модератору.
- Полоса под шапкой: строка закреплённого, нажатие — переход (`FeedJumps`), ✕ — снять (у кого право).
- Служебная строка «… закрепил(а) сообщение» — словами читающего, без уведомления.
- Событие `message.pinned` — полоса обновляется сама; закреплённое не загружено — заглушка «Сообщение
  закреплено» и переход по номеру.

### ЗО4. Клиент: описание

- Окно «Описание»: аватар, название, содержимое, внизу «Вступить» или «Подписаться» по положению
  читателя. Метки для сценариев, строки в СЦЕНАРИИ-ПО-ОКНАМ.
- Содержимое:
  - есть суперсообщение — показывается оно (подкладки внутри — его же видом);
  - нет, сообщений уровня 0 до трёх — лентой, полностью;
  - больше трёх — списком по три строки, нажатие — само сообщение, одно.
- Открывается из разделов (аватар) и из шапки (текст); не вступившему нажатие на группу открывает
  «Описание», а не пустую переписку.
- Забирается при открытии и **нигде больше не хранится в ленте**: уровень 0 в переписку, уведомления и
  счёт нового не попадает (запрос истории — с параметром «без уровня 0», входящее уровня 0 по живому
  каналу — мимо ленты).

### ЗО5. Клиент: суперсообщение

- У владельца в «Описании» — «Создать суперсообщение» (или «Изменить»): редактор с уже вставленными
  подкладками всех сообщений уровня 0 списком; владелец меняет вид как любое сообщение; «Отправить»
  ставит его суперсообщением.
- Отправленное уходит уровнем 0; место под суперсообщение — ссылкой на него (ЗО2).

### ЗО6. Журнал, проверка, журнал работ

- Коды журнала: закрепление (кто, что, отказ), описание (открыто, сколько, есть ли суперсообщение).
- Тесты сервера и клиента; строки журнала работ с «проверить заказчику»; затем выкатка вместе с
  остальным (Н23).
