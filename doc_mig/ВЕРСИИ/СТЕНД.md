**Что приехало.** Двенадцать дней работы: звонки и аудио-комнаты, каналы, архив и
восстановление чатов, привязка по QR, разбор `Server` на регистраторы, латиница в именах

**Миграции 0030 и 0031 применились при старте**, обе аддитивные: вставка строк с
`ON CONFLICT DO NOTHING` и `ADD COLUMN IF NOT EXISTS` с индексом. Ничего не удалено и не

**Раздача v1 убрана 2026-08-26.** Решение заказчика: «клиент 1 больше не живёт нигде».
Двадцать три APK (691 МБ) унесены из `deploy/download/` в
`/root/stand-config/download-v1.2026-08-26/` — **унесены, а не стёрты**: удаление на живом
сервере не отменить, перенос отменить можно. `APP_LATEST_VERSION_CODE=0`, поэтому
`/app/version` честно отвечает `204` «обновления не настроены», а не предлагает сборку,
которой больше нет. `APP_STREAM=v2` — на случай, когда появится что раздавать.

Проверено: `204` без тела, `GET /download/TIMA-0.6.5.apk` → `404`.

**`APP_STREAM` был задан впервые в этой выкатке.** Клиент v2 сравнивает номера версий только внутри
своего потока: у v1 `version_code` 24, у v2 — 2, и без потока v2 предложил бы поставить
поверх себя прошлогоднюю сборку.

**Одна ловушка сработала при этой выкатке.** `APP_STREAM` был дописан в `deploy/.env`, но
до бэкенда не доехал: `environment` у сервиса `backend` перечисляет `APP_*` поимённо, и
новой строки там не было. Поймал это лог, добавленный в том же коммите, что и само поле:
«APP_STREAM не задан — клиенты, различающие потоки, это предложение пропустят». Починено
`f692463`. Без этой строки в журнале молчащая вкладка «Обновление» выглядела бы как
поломка клиента.

**Ловушка с LiveKit не сработала**, потому что порядок соблюдался: настоящие ключи
сохранены в `/root/stand-config/livekit.yaml.2026-08-26-1124` **до** любой операции git и
возвращены после. `grep -c REPLACE` даёт 0 — проверено дважды, после каждого
переключения. Там же лежат `.env` и патч грязного дерева

сознательно — они старше того, что в репозитории, — но восстановимы из патча.

**Проверено снаружи на выкаченном коде**, а не по журналу: `healthz`, `app/version` с

## Адреса

| Что | Адрес |
|---|---|
| Домен | `пацак.рф` → punycode `xn--80aa4ar0b.xn--p1ai` |
| **API** | `https://api.xn--80aa4ar0b.xn--p1ai` — **на поддомене `api.`** |
| Корневой домен | отдаёт 404: API там не живёт |
| По IP | TLS **не встаёт** — Caddy отдаёт сертификат по имени, для адреса его нет |

> **Домен внутренационализированный (IDN).** В TLS и в заголовке `Host` едет
> punycode. Клиент, которому `serverUrl` вводят руками, обязан переводить
> кириллическое имя в punycode сам — иначе человек введёт «пацак.рф», а соединение не
> встанет. Пункт для К3 (`core-network`).

## Проверено 2026-08-26: развёрнут по-прежнему 3c491bb

Спрошено у самого стенда, а не выведено снаружи:

```
git -C /opt/tima log -1        →  3c491bb 2026-08-14 chore: prepare Android 0.6.5
schema_migrations              →  29 строк, последняя 0029_device_platform.sql
контейнеры                     →  Up 11 days, образ tima-backend:local
```

Запись верна, тег `deploy/20260814-01` верен. **Устарело другое** — утверждение ниже,
что развёрнутый сервер совпадает с вершиной: `stand` с тех пор ушёл вперёд.

| Что | Состояние на 2026-08-26 |
|---|---|
| `git diff 3c491bb HEAD -- server/` | 43 файла, +4977/−3266 |
| миграции сверх развёрнутых | `0030_delivery_retention`, `0031_group_key_epoch` — **в базе стенда их нет** |
| `APP_STREAM` | не задан; вкладка «Обновление» у клиента v2 честно скажет, что предложение чужое |
| маршрутов | 71 и там, и там — API за это время не расширялся |
| рабочее дерево `/opt/tima` | не чисто: правки в `client/composeApp` (это ещё v1) и `server/deploy/livekit/livekit.yaml` |

**Чего снаружи не видно и почему.** 2026-08-26 была попытка определить версию стенда
пробоем маршрутов: `/api/v1/voice-rooms`, `/api/v1/channels/discover` и прочие отвечают
`401`, а не `404`. Из этого был сделан вывод «стенд новее 3c491bb» — **вывод неверный**.
Маршруты существовали и в 3c491bb; в `git diff` они выглядели добавленными потому, что
разбор `Server` на регистраторы **перенёс** их из `server.go` в файлы регистраторов, и
перенос читается как `+` в новом файле и `−` в старом.

Отсюда правило: **версию развёрнутого сервера определяет только сам сервер.** Последние
работы (регистраторы, латиница в именах) поведения не меняют по построению — никакой
пробой снаружи их не различит, а число маршрутов одинаково.

## Как было: развёрнутый сервер — актуальный

Заказчик сказал «в сети живая старая версия». Проверено: **это верно про клиента и
неверно про сервер.**

```
git diff 3c491bb HEAD -- server/   →  43 файла, +4977/-3266   (2026-08-26)
git diff 3c491bb HEAD -- schema/   →  0 строк
```

После 14 августа менялись только клиент, макет, документация и `third-party` —
серверный код и схема не тронуты. Значит **клиент v2 можно писать против того, что
развёрнуто**, без риска расхождения. Это снимает главный риск использования сетевого
стенда вместо локального.

## Режим SMS: `TIMA_DEV_SMS=1` включён

Проверено запросом, а не чтением конфигурации:

```
POST https://api.<домен>/api/v1/auth/sms/request  {"phone":"+79990000042"}
→ 200 {"dev_code":"…","request_id":"85a1bf3b-…"}
```

Код возвращается прямо в ответе. **Значит блокера для регистрации тестовых аккаунтов
нет** — харнесс К4 сможет заводить их сам, без походов за логами.

Оговорка, чтобы это не забылось: с этим флагом **зарегистрироваться может любой, кто
знает домен**. Для тестового стенда с пустой базой приемлемо; в бою флага быть не
должно.

## Как это проверялось

```bash
# состояние и коммит
ssh <стенд> 'docker ps; git -C /opt/tima log -1 --format="%h %ad %s" --date=short'

# уровень миграций (значения POSTGRES_USER/DB берутся из .env, пароли не нужны)
ssh <стенд> 'docker exec tima-postgres-1 psql -U <user> -d <db> \
    -tAc "select count(*), max(name) from schema_migrations"'

# снаружи, без SSH
curl https://api.<домен>/healthz                  # {"status":"ok"}
curl https://api.<домен>/api/v1/app/version       # version_code 24
```
