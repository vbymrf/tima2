## 1. Этапы

| Этап | Что | Где | Готово, когда |
|---|---|---|---|
| **ИФ0** | Решения записаны (§3, §6, §8 Решений), этот план; ADR «правка заменяет фото, превью из тела убрано» | `doc_mig/`, `doc/adr/` | ADR принят |
| **ИФ1** | **Правила приёма от сервера**: новый маршрут отдаёт пределы этому пользователю — размер другому и себе, сутки, виды файлов, сторону фото, сроки почтальона. Пределы — переменные сервера, а не постоянные в коде; подписка позже меняет ответ. Отказ при загрузке — с причиной, как сейчас (`postman_too_large`) | `server/internal/api/media.go`, новый маршрут, тесты | маршрут отвечает, тесты сервера зелёные с числами |
| **ИФ2** | **Клиент соблюдает правила**: спрашивает не чаще раза в сутки, хранит ответ, проверяет файл до отправки, отказ сервера показывает сообщением | `core-network`, `domain-chat` (`SendAttachments`) | тест: второй запрос в те же сутки не уходит; лишний размер не отправляется |
| **ИФ3** | **Формат тела**: `MediaRef.preview` убран (номер 10 — `reserved`); правка фото — новое поле тела: позиция файла в `media` и новый `MediaRef` целиком. Подписываемые байты конверта не меняются: `edit_of` уже в версии 3 (ADR-0045) | `schema/proto/message_body.proto`, Go и Kotlin из proto, `core-encryption` | `crypto-invariants` прочитан; тесты кодека тела |
| **ИФ4** | **Фото целиком сразу**: клиент забирает фото у почтальона при получении сообщения, не по нажатию; превью для нескольких фото делает сам и кладёт в свою папку (зашифрованным, Решения §6); одно фото в ленте — из полного по ширине места. Качается — пустое место размером из тела. Не скачалось и некому прислать — фото нет; сообщение только из фото не показывается | `domain-chat`, `feature-chat/…/Attachments.kt`, `core-media` | тесты; на телефоне одно фото в ленте чёткое |
| **ИФ5** | **Просмотр**: масштаб — щипок, двойное нажатие, колесо на ПК; увеличенное двигается, а не листается; слева внизу «Повернуть» и «Изменить» | `PhotoViewer` | тест окна; метки в `СЦЕНАРИИ-ПО-ОКНАМ.md` |
| **ИФ6** | **Редактор фото**: обрезка, кисть, стрелка, поворот; цвет и толщина; отмена внутри сеанса; «Сохранить». Прежних состояний после сохранения нет | новый экран в `feature-chat` | тест экрана; метки |
| **ИФ7** | **Досылка**: изменения копятся до закрытия просмотра и уходят **одной** правкой — новый файл к почтальону и запись правки с заменой фото. У автора фото меняется сразу; у получателя — на том же месте, «изменено». Предел 3 и «до смены ключа» — те же, что у текста (ADR-0045 §5): считается досылка. Своё фото, которое уже нельзя править, и чужое — редактор открывается, итог — «Сохранить как» или «Переслать» новым фото | `domain-chat` (правка), `ChatStore`, сервер — без изменений проверки | тесты; живьём — два телефона: поворот и обрезка, одна правка, «изменено» у получателя |
| **ИФ8** | Выкатка: сервер раньше клиента; объявление версии; проверка на телефонах; сценарии — в `flows/` навыка, если задача по тестированию | стенд, `ВЕРСИИ/` | строка журнала с хешем |

**Порядок:** ИФ0 → ИФ1 → ИФ3 → ИФ2 и ИФ4 → ИФ5 → ИФ6 → ИФ7 → ИФ8. ИФ1 раньше клиента: сервер
выкатывается первым. Без поддержки прежнего: после выкатки сообщения стенда с превью в теле не
читаются как раньше — решение заказчика.
