# Латиница в именах: план перехода

Правило заказчика 2026-08-25: **кириллицы нет в именах файлов, папок, переменных,
функций и методов**. Само правило — в [CLAUDE.md](../CLAUDE.md), «Соглашения
репозитория». Здесь только порядок работ и цена каждой партии.

Русский остаётся там, где он для человека: комментарии, текст документов, надписи на
экране, сообщения об ошибках. **Правило про имена, а не про язык.**

> Этот файл — первый по нему переименованный. Он назывался `ПЛАН-ЛАТИНИЦА.md`, и
> проверка уронила сборку на нём же: план, вводящий правило, сам его нарушал. Заголовок
> при этом остался русским — ровно так, как предлагается в §2.

## 2. Как называем

**По смыслу, а не транслитерацией.** `Переписка.kt` → `Chat.kt`, а не `Perepiska.kt`.
Транслитерация даёт имя, которое не читается ни по-русски, ни по-английски, и через
месяц никто не помнит, `Soobshenie` это `Message` или `Notice`.

| Что | Как | Пример |
|---|---|---|
| файл с классом | имя класса | `КаркасОкна.kt` → `WindowFrame.kt` |
| файл-набор функций | по содержимому | `Знаки.kt` → `Icons.kt` |
| страница макета | по окну из `§1` | `новости.html` → `social.html` |
| документ | по теме, из его же заголовка | `ПРАВИЛА-РАБОТЫ.md` → `working-rules.md` |
| папка | по разделу | `ИНТЕРФЕЙС/` → `interface/` |

**У документов заголовок остаётся русским** — первой строкой внутри файла. Заказчик
читает документы и ищет их по названию; латинское имя файла с русским заголовком
внутри находится и глазами, и поиском по содержимому. Латинское имя **и** латинский
заголовок сделали бы документы чужими для того, кто с ними работает.

## 3. Порядок партий

Каждая партия — **отдельный коммит**, только переименования, без правок содержимого.
Смешанный коммит нечитаем: в нём не видно, что было переносом, а что правкой.

Переименовывать **только `git mv`**: история файла сохраняется, и `git log --follow`
продолжает её показывать. Копирование с удалением рвёт историю навсегда.

### Партия 1 — запускалки (2 файла + 12 в архиве)

Первая, потому что самая заметная и самая опасная. `ОБНОВИТЬ-И-ЗАПУСТИТЬ-ПК.bat` →
`run-desktop.bat`.

**Ловушка:** у заказчика ярлык на рабочем столе, и он перестанет работать. Ярлык
чинится вручную, поэтому переименование делается **вместе с предупреждением**, а не
между делом. На него же ссылаются шесть мест: `.cursor/rules/runtime-launchers.mdc`,
профиль ops-скилла, два файла в `doc_add`, README архива и сам `.ps1`.

`.ps1` с кириллицей внутри остаются **с BOM** — переименование содержимого не трогает,
но проверить после партии обязательно: без BOM PowerShell 5.1 читает файл как ANSI.

### Партия 2 — макет (79 файлов, 1933 ссылки)

`doc/Layout-UI-light` и `Layout-UI-dark`. Имена окон и подокон берутся из `§1`:
`телефон.html` → `phone.html`, `новости.html` → `social.html`, `медиа.html` →
`media.html`, `общение.html` → `activity.html`, `страница.html` → `profile.html`,
`страница-гостя.html` → `profile-guest.html`; подокна — `chat`, `call`, `comments`,
`post-text`, `rating`, `transitions`, `window-switch`, `settings`, `search`.

Ссылки правятся тем же скриптом, что и имена: 1933 штуки руками не переписать.
**Проверка после — обход всех `href` и `link` с проверкой, что файл существует.**
Пока такой проверки нет, её пишем в этой же партии: без неё битую ссылку в макете
никто не заметит, страницы открывают по одной.

### Партия 3 — документы `doc/` и `ДОКУМЕНТАЦИЯ/` (около 40 файлов, 194 ссылки)

`интерфейс.md` → `interface.md`, `ДОКУМЕНТАЦИЯ/` → `documentation/`. Ссылки из
`doc_mig` и из `.cursor` правятся тем же проходом.

`Тима.docx` и второй `.docx` — исходники, их читают только люди: переименовать, ничего
внутри не трогая.

### Партия 4 — `doc_mig` (около 60 файлов, включая папки `ИНТЕРФЕЙС/*`)

Здесь и папки: `ИНТЕРФЕЙС/02-телефон/` → `interface/02-phone/`. На них ссылается
`ПРАВИЛО.md` и все четыре документа в каждой папке.

`doc_mig/arhiv` — архив: переименовать одним махом, внутренние ссылки там ведут на
файлы v1, которых уже нет, и чинить их незачем.

### Партия 5 — Kotlin (83 файла)

Переименование файла **не влияет на компиляцию**: Kotlin не требует совпадения имени
файла с именем класса. Поэтому партия делится на модули и идёт быстро.

Что ломается и требует правки в том же коммите:

- `ArchitectureTest` сверяет имя фикстуры строкой (`ОбразецUseCase.kt`);
- `ТрендTest` считает импорты в `Корень.kt` по пути;
- `ЛатиницаTest` — понизить бюджет.

### Партия 6 — Go (1 файл)

`server/deploy/СТЕК-ДЛЯ-ТЕСТОВ.md` → `test-stack.md`. Имена `.go` уже латинские.

## 4. Проверки после каждой партии

| Что | Чем |
|---|---|
| ничего не потеряно | `git status` чист, `git log --follow` показывает историю переименованного файла |
| ссылки целы | обход ссылок в `.md` и `.html`: каждый путь существует |
| сборка цела | `gradlew build`, `go test ./...` со службами |
| бюджет понижен | `ЛатиницаTest` зелёный на новом числе |

**Бюджет понижается тем же коммитом, что и партия.** Тест падает и когда число выросло,
и когда упало без правки бюджета: иначе он перестаёт что-либо значить.

## 5. Имена внутри кода — отдельная дорожка

Правило заказчика покрывает и переменные с функциями: это около **2600 имён в Kotlin**
и полтора десятка в Go. Здесь названы риски, а сроки и порядок — после решения по §6.

| Риск | В чём | Как гасится |
|---|---|---|
| публичный API модулей | `ЭкранЧата`, `ChatsState.прочитано` — их зовут из других модулей | переименовывать модуль целиком, компилятор ловит всё |
| снимки тестов | имя снимка — строка (`снять("переписки-шапка")`), файл на диске зовётся так же | эталонов в репозитории нет, снимки строятся заново; строки менять вместе |
| Go | `звонкиDeps`, `датьСлово`, `ограничитьЧастоту` — 14 имён, все внутри пакета `api` | одна партия, компилятор ловит всё |
| читаемость комментариев | комментарий объясняет `сменитьОкно`, а функция станет `switchWindow` | комментарии правятся вместе с именем, иначе они начинают врать |

Порядок предлагается обратный порядку файлов: **сначала Go** (14 имён, один пакет,
проверяется прогоном за минуту), потом Kotlin по модулям снизу вверх — `core-model`,
`domain-*`, `core-*`, `feature-*`, `shared`. Снизу вверх потому, что переименование в
нижнем модуле ломает верхние сразу и видно компилятором; сверху вниз пришлось бы
возвращаться.

   которым сейчас строятся окна. Делать их сейчас — значит на день остановить работу

   переименовать одним заходом позже. **Рекомендация: партия 1 и партия 5 сейчас**
   (они не мешают), остальное — после того, как окна 2–5 получат содержимое.
