## Ход работ

### РФ0 — замер до

Samsung SM-A405FM (Android 11), отладочная 240. Холодный запуск — 6,1 с (`am start -W`). Прокрутка переписки на
130 сообщений — около 53 кадров на росчерк, из них 3–6 дольше 16,7 мс. Список чатов на этом телефоне — четыре
строки, его прокрутку мерить нечем. ПК не мерился: у настольной сборки нет снятия кадров, сравнение — по Samsung.

Находка по ходу: системная «Назад» Android из переписки **закрыла приложение целиком** — та самая беда, ради которой в
плане МП5. Сейчас приложение «Назад» не обрабатывает.

### РФ1 — `Navigator`

`Where` (18 видов подокон) и код подокна для журнала переехали из `Root.kt` в `Navigator.kt`; окно и подокно `App()`
читает и пишет через делегат свойства `Navigator` — все 79 мест `where = …` остались как были. Поведение прежнее.

### МП1 — цепочки переходов

Решение по ходу, которого не было в плане: **запись `where = …` в 79 местах получила смысл «открыть», запись
`Where.Nothing` — «закрыть верхнее звено»**. Так цепочка встала без правки каждого места. Три правила звеньев, чтобы
прежние места работали как раньше:

- открыть **ту же сущность, что под верхним**, — это возврат (так «назад» из «Доступа» называет «Состав», а «назад»
  из «Состава» — переписку);
- **настройки — одно звено**: пункт заменяет список и обратно, иначе «назад» из пункта, открытого напрямую
  (уведомление «устройства»), ходил бы по кругу;
- **черновые подокна** (новая переписка, новая группа, привязка, передача) заменяются открытым поверх них: после
  «создать группу» «назад» ведёт не в форму, а туда, откуда её открыли.

Живьём на Samsung: открыта переписка — `NAV открыто как=open что=chat звеньев=1`; свайп «Телефон» → «Социум» и
обратно — `NAV окно как=swipe … в=point`.
