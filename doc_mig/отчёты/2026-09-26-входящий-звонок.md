## Развилки и решения по ходу

- **Групповые звонки оставлены на прежней дороге** (журнал устройства, `call.incoming` /
  `call.state`, `call.poke {call_id}`). В план они не входят, а их переделка удвоила бы срез.
- **Найдено по ходу: вебхук LiveKit объявлял личный звонок отвеченным, когда в комнату
  входил сам звонящий** — а он входит сразу. С лентой это дало бы звонящему ложное
  «ответили»; починено тем же срезом.
- **Звук играет приложение, каналы беззвучные (ВЗ3, ВЗ5).** План предполагал для звука
  сообщения пересоздание канала на каждую смену выбора. Сделано иначе, и довод сильнее:
  мелодия звонка обязана идти по кругу (звук канала — один раз), свой файл из папки
  приложения системный звук не прочитает без FileProvider, а пересоздание канала на
  каждую смену стирало бы настройки канала, сделанные человеком. Поэтому один переезд на
  беззвучные каналы `.2`, и звучит приложение само — по выбору из настроек.
- **ПК играет свой файл, только если это `wav` (ВЗ6).** mp3, ogg и m4a Java без
  сторонних библиотек не проигрывает, а своего списка стандартных мелодий у Windows для
  приложений нет. Для них и для «как в системе» звучит системный сигнал — по кругу у
  звонка. Кнопки «Из стандартных» на ПК нет.
- **`taken` как отдельное слово исчезло**: «ответили на другом устройстве» — это `answered`
  с `here = false` в ответе ленты, который составлен для спрашивающего устройства.

## Развилка — выкатка (здесь работа остановлена)

Весь код плана написан и закоммичен; дальше — **выкатка**, и это решение заказчика, а не
агента: действие наружу, и у него есть цена.

- **Сервер и клиенты — разом** (ADR-0025 Поправка-2): сервер после выкатки шлёт личный
  вызов только лентой `cts`. Клиент старше этой работы звонок **не услышит**: сейчас это
  Honor (76), раздача (79), ПК, если он на стенде. Телефоны realme, samsung, Redmi — на
  80, тоже старше.
- Порядок, предлагаемый к решению: 1) выкатка сервера `deploy/…` по
  `ПЕРЕУСТАНОВКА-СЕРВЕРА.md` (миграция 0056 аддитивная); 2) версия 81 на телефоны,
  которые скажет заказчик, и в раздачу; 3) ВЗ7 — проверки ниже на телефонах.

## Что не проверено и почему

- **Серверные тесты с базой** (`calls_unreachable_test.go`, остальные тесты пакета `api`)
  здесь не запускаются — Postgres на машине нет (`go test` показывает `ok`, но это пропуск,
  а не проверка). Пройдут на стенде.
- **Всё на телефонах (ВЗ7) — не проверено**: до выкатки сервера лента `cts` не работает
  вовсе. Что проверить после выкатки:
  - доставка: звонок realme → Redmi, у звонящего «Вызов…» → «Звонит…»; у Redmi в фоне —
    полноэкранный вызов на замке, мелодия по кругу, «Принять» из строки отвечает,
    «Отклонить» кладёт трубку без окна;
  - «не в сети»: Redmi без сети — у звонящего строка, звонок идёт; сеть вернулась до 45 с —
    «Звонит…», телефон звонит;
  - пропущенный: не ответили — уведомление «Пропущенный звонок» на всех устройствах;
    открыли «Звонки» на одном — строка снялась на остальных;
  - офлайн дольше суток — пропущенные из журнала, без звонка по мёртвым;
  - второе устройство человека замолкает, когда ответили на первом;
  - беззвучный режим, вибрация, «Не беспокоить»;
  - полоса «звонки не дойдут» на Redmi (уведомления сейчас запрещены), «Позже»;
  - звуки: стандартная мелодия, свой файл, без звука; своя мелодия контакта из журнала.
- **Журнал контактов, раздел «Звуки», полоса** — проверены сборкой и тестами правил, но не
  глазами на телефоне.
