## Развилки и решения по ходу

- **Групповые звонки оставлены на прежней дороге** (журнал устройства, `call.incoming` /
  `call.state`, `call.poke {call_id}`). В план они не входят, а их переделка удвоила бы срез.
- **Найдено по ходу: вебхук LiveKit объявлял личный звонок отвеченным, когда в комнату
  входил сам звонящий** — а он входит сразу. С лентой это дало бы звонящему ложное
  «ответили»; починено тем же срезом.
- **Звук играет приложение, каналы беззвучные (ВЗ3, ВЗ5).** План предполагал для звука
  сообщения пересоздание канала на каждую смену выбора. Сделано иначе, и довод сильнее:
  мелодия звонка обязана идти по кругу (звук канала — один раз), свой файл из папки
  приложения системный звук не прочитает без FileProvider, а пересоздание канала на
  каждую смену стирало бы настройки канала, сделанные человеком. Поэтому один переезд на
  беззвучные каналы `.2`, и звучит приложение само — по выбору из настроек.
- **ПК играет свой файл, только если это `wav` (ВЗ6).** mp3, ogg и m4a Java без
  сторонних библиотек не проигрывает, а своего списка стандартных мелодий у Windows для
  приложений нет. Для них и для «как в системе» звучит системный сигнал — по кругу у
  звонка. Кнопки «Из стандартных» на ПК нет.
- **`taken` как отдельное слово исчезло**: «ответили на другом устройстве» — это `answered`
  с `here = false` в ответе ленты, который составлен для спрашивающего устройства.

**Три беды, найденные живьём на 81 и починенные в 82:**

1. Из сна полноэкранный вызов не включал экран — ни окна, ни строки, пока человек не
   разбудит телефон. Теперь экран будится коротким удержанием до показа строки.
2. После «Принять» строка звонка оставалась, мелодия и вибрация шли весь разговор:

- **Кнопка «Позже» на красной полосе** — тёмный текст на тёмно-красном, читается хуже

## Вторая волна — решения заказчика по итогам проверки (83)

- **«Звонки могут не дойти» — подокном-событием**, как «Приложение обновилось»: шапка с
  «назад», «Включить» ведёт в «Настройки → Разрешения», «Позже» — неделя. Красная полоса
  убрана. Проверено на Redmi: событие показывается, «Включить» открывает «Разрешения».
- **Новый пункт «Разрешения»**: уведомления, канал «Звонки», во весь экран, микрофон,
  камера, контакты, работа в фоне. «Уведомления» — что показывается и звуки. Проверено на
  Redmi глазами.
- **Медленный подъём канала (74 с)** не воспроизводится: трижды подряд 2 с. В тот момент
  на 60 с повисла и служебная `dumpsys activity`, то есть тормозил телефон целиком. Найдено
  и починено настоящее: служба собирала приложение на главном потоке (~2 с, «Skipped 181
  frames», кадр 4,3 с) — теперь отдельным потоком (`a8e84156`). Запись «телефон включён» —
  не загадка: после принудительной остановки Android сам шлёт приложению BOOT_COMPLETED.
- **realme без пароля** — прежняя запись «экран заперт» была неверна: снимок был чёрным,
  пока экран спал. Звонок samsung → realme из сна: экран включился, окно входящего,
  «Принять» — разговор, строка снялась; мелодии нет — realme в режиме вибрации, как задумано.
- Тексты события — только о причине, без повтора заголовка (идут со следующей сборкой).
