# План: указатели

Заведён 2026-10-21 по слову заказчика: «Окно Общение, добавляем вкладку Указатели. Вместо Коллекции. Внутри
полностью берем механизм Разделов из Окна Телефон… Журнал контактов у нас есть — будет Журнал указателей…
Делаем единый стиль — код… Храним раздельно»; «делаем кнопку назад для вкладки Указатель окна Общение…
Помним только последний… повторные, пришедшие сразу, объединяем как одна точка»; ответы «1. каждая своей
2. да 3. да 4. да… Все верно». Опирается на [ПЛАН-(БП)](ПЛАН-(БП)-БУФЕРА-ПЕРЕХОДОВ.md) (буфер переходов).

**Статус 2026-10-21: план, работ нет.**

## 0. Что уже есть

- **«Коллекции» в «Общении»** — заглушка «Здесь будет то, что вы собрали»
  (`client/feature/feature-shell/.../Windows.kt`, `ActivityWindow`; вкладки `SOCIAL_TABS` — Ответы,
  Реакции, Коллекции).
- **Подборка** (`client/domain/domain-chat/.../MessagePicks.kt`, таблица `picks` в базе устройства):
  ссылки на сообщения, на устройстве, до 100 на ключ — сообщество, иначе группа или канал, у личных одна
  общая (`self`). Добавляется из меню сообщения (`msg:pick`), вставляет редактор («Подборка»,
  «Подкладка»). Окна, где их смотреть и убирать, нет.
- **Разделы** — общий экран `SectionsScreen` и меню «Вид» `BookViewSheet` у «Телефона» (контакты,
  `book_section`, настройки `book.*`) и «Каталога» «Социума» (`community_section`, `community.*`); разница —
  признак `forPeople`. Порт `SectionSet` есть, на нём — только сообщества.
- **«Убрать раздел»** — кликабельная строка, убирает **без подтверждения** (`SectionsScreen.kt`).
- **«Журнал контактов»** (`ContactLedger.kt`) — первым в «Виде»: фильтры, поиск, галочки, кнопки «В раздел»,
  «Убрать», «Заблокировать», «Вернуть», «Звук».
- Строки «Социума» — `GroupLine` (`feature-group/.../SocialTabs.kt`): вторая строка — моя роль.
- Попутно: надпись «В Подборке уже 20 сообщений» (`picksFull`) отстала от предела 100.

## 1. Решения (заказчик 2026-10-21)

| Что | Решение |
|---|---|
| Место | вкладка **«Указатели»** окна «Общение» **вместо «Коллекций»** |
| Указатели и подборка | **одно хранение**: указатель — ссылка на сообщение; редактор вставляет из указателей своего уровня |
| Разделы | **механизм разделов «Телефона» целиком**: Все, Общий, добавленные; добавить, убрать, вид — через меню «Вид». **Код один** — правка в одном месте меняет все окна; **хранение и выбранный вид — свои** у каждого окна или вкладки |
| Что в разделе | **сам указатель**; сущность видна в разделе, если в нём есть её указатель |
| «Убрать раздел» | **кнопка с подтверждением** (красной, как опасное в «Секретной фразе и устройствах») — у контактов, сообществ и указателей разом |
| Сущность первого уровня | сообщество, группа, канал, **каждая личная переписка своей сущностью** — у которых есть указатель. Вид — как в «Социуме», «Телефоне»; **вторая строка — что это**: «чат», «группа открытая», «канал открытый» и т. д. |
| Внутри сущности | указатели — **сообщения в полном виде**; нажали — переход в переписку; нажатие вне сообщения — выделение, как в ленте |
| Действия | убрать сущность (все её указатели) или указатель; перенести указатель в раздел; у сущности — долгим нажатием |
| Журнал указателей | как «Журнал контактов»; кнопки **«В раздел», «Убрать», «Перейти»** |
| Переходы | **у каждой сущности свой буфер** ([ПЛАН-(БП)](ПЛАН-(БП)-БУФЕРА-ПЕРЕХОДОВ.md)); переход по указателю пишет первой точку «из Указателей»; «назад» до неё — во вкладку «Указатели», в ту же сущность. Между сущностями — только через «Указатели» |
| «Назад» во вкладке | своя кнопка вкладки (не системная): **повторяет последний переход** по указателю — та же переписка, то же сообщение; помнится **только последний** |
| Повторный приход | одинаковые точки подряд не дописываются — **общее правило всех переходов** (ПЛАН-(БП)) |
| Хранение | на устройстве, на сервер не уходит; буфер переходов переживает закрытие приложения |
| Сообщение-цель с сервера | **хранится на устройстве** зашифрованным ключом устройства, как свои (`body_enc`): вкладка открывается без сети и не спрашивает сервер каждый раз |
| Индекс ссылок «кто на кого ссылается» | **открытыми колонками — нет** (заказчик 2026-10-21) |
| Ссылки метаданными на сервере | **нет** — ни для закрытых, ни для открытых: у открытых сервер и так читает тело; вопрос — вместе с [ПЛАН-(УО)](ПЛАН-(УО)-УПОМИНАНИЙ-И-ОТВЕТОВ.md) |

## 2. Этапы

Порядок: **БП1–БП3 → УК1…УК7 → БП4**. Переходы между сущностями идут только через «Указатели», поэтому
БП4 (между переписками сообщества) — после.

### УК1. Хранение: подборка становится указателями

- Миграция базы устройства (добавляющая): у `picks` — колонка раздела `section_id` (пусто — «Общий»);
  ключ личной — **своя переписка** `personal:<chatId>` вместо общего `self` (номер переписки у каждой
  записи есть — переносится без потерь).
- Таблица разделов указателей `pointer_section` — как `community_section`; порт `SectionSet` для неё.
- `MessagePicks` → указатели: добавить, убрать, в раздел, список по сущности и по разделу; предел 100 на
  сущность. Редактор в личной переписке вставляет из всех личных (как сейчас — одна подборка на все).
- Сообщение-цель, полученное с сервера по номеру, — в базу устройства, зашифрованным ключом устройства
  (тот же `body_enc`); показ указателя берёт его оттуда, сервер спрашивается, только когда его там нет.
- Надпись предела — по `MAX`, а не «20».
- Тесты: перенос `self` по переписке, раздел, предел, уборка.

### УК2. Разделы: единый код, кнопка «Убрать раздел»

- `SectionsScreen` и `BookViewSheet` — третий набор: указатели (свой ключ вида `pointers.*`, свои
  разделы). Признак `forPeople` — в вид набора (люди, сообщества, указатели).
- «Убрать раздел» — кнопка, по нажатию — подтверждение красной кнопкой; что лежало в разделе — в «Общий».
  Сразу у всех трёх наборов.
- Тесты экрана: подтверждение, отмена.

### УК3. Вкладка «Указатели»

- `SOCIAL_TABS`: «Коллекции» → «Указатели» (ключ, слова на трёх языках, метка для сценариев).
- Второй ряд — разделы (`SectionsRow`), «Вид» — как у «Телефона».
- Список сущностей: строка как в «Социуме», вторая строка — вид сущности, справа — число указателей в
  разделе. Долгое нажатие — «В раздел» (все её указатели), «Убрать» (с подтверждением).
- Внутри сущности: сообщения пузырём ленты, только для чтения; у сообщества — подпись группы над
  сообщением. Нажатие — переход; нажатие вне — выделение; «В раздел», «Убрать». Нет на устройстве —
  догрузить; удалено или недоступно — «недоступно», остаётся до уборки.
- Строки окна — в [СЦЕНАРИИ-ПО-ОКНАМ.md](ФУНКЦИОНАЛ/АВТОТЕСТЫ/СЦЕНАРИИ-ПО-ОКНАМ.md).

### УК4. Переходы из указателей

- Нажатие на указатель — открыть переписку (окно остаётся «Общение»), перейти к сообщению; буфер
  сущности — точка «из Указателей» и «куда».
- «Назад» в переписке до точки «из Указателей» — во вкладку «Указатели», открыта та же сущность.
- Кнопка «назад» вкладки (↩ справа внизу, как в ленте) — видна, когда есть запомненный переход;
  повторяет его. Помнится один, новый заменяет. Повторный приход в буфер сущности точек не прибавляет.

### УК5. Журнал указателей

- Первым в «Виде» вкладки. Фильтры: раздел, вид сущности (чаты, группы, каналы, сообщества), поиск по
  тексту. Строка — сообщение в две строки, ниже «раздел · сущность»; галочки, «Выделить все».
- Кнопки: «В раздел», «Убрать», «Перейти».

### УК6. Меню сообщения и редактор

- Пункт подборки в меню сообщения — «В указатели» (метка `msg:pick` остаётся).
- «Подборка» и «Подкладка» редактора берут указатели своего уровня; правило «вставлять только в пределах
  уровня» — без изменений.

### УК7. Журнал, сценарии, проверка

- Коды журнала: указатель добавлен, убран, в раздел, переход из указателей, повтор перехода.
- Тесты модели и экрана; сценарий Maestro — указатель → переписка → «назад» → «Указатели» → «назад» вкладки
  → снова в переписке; строка журнала работ.
- Только клиент: сервер не меняется.

## 3. Открыто

- Вид сущности во второй строке для закрытых групп и каналов — «группа закрытая», «канал закрытый» (по
  аналогии; проверить при приёмке).
- Канал: окна канала в клиенте нет — переход по указателю на запись канала откроет то, что есть сейчас;
  полноценно — вместе с окном канала.
