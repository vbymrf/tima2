# План: Передаваемые файлы

Заведён 2026-09-26 по решению заказчика. Сначала он спросил про аватар: «Обрезка у нас
512 на 512, аватар меньше гораздо на телефоне. Как мы храним тогда?». Затем решил:
«Будем уменьшать по большой стороне до 1280. Этот размер — параметр. В конечном счёте это
станет стандартом для всех передаваемых фото через приложение».

Статус: **обсуждается**. Кода по плану нет.

---

## 0. Как сейчас

Проверено по коду 2026-09-26.

**Клиент грузит в медиа ровно одно — свой аватар.** Вложений в переписке, аватаров групп,
лент с картинками, превью нет.

| Что | Где | Как |
|---|---|---|
| Выбор картинки | `core-media/…/ImagePicker.kt` | байты как есть + mime; на iOS заглушка |
| Раскодирование | `ImageCodec.android.kt` | ужимает **степенями двойки** до `MAX_SIDE = 2048` и поворачивает по EXIF |
| Обрезка аватара | `SquareCrop.kt` | квадрат `OUTPUT_SIDE = 512` |
| Кодирование | `ImageCodec.kt` | JPEG, качество 85 |
| Загрузка | `MediaOverHttp.kt` | `init` → PUT → `complete`, одним куском, без шифрования |
| Сервер | `server/internal/api/media.go` | до 2 ГБ на файл; тип и размеры картинки не проверяются |

Что из этого следует:
- **Аватар хранится одним квадратом 512×512.** Показывается он не больше чем 42 dp в
  списках и ≈80 dp крупным (профиль, «Я», страница человека), то есть при плотности ×3
  примерно 126 и 240 точек. 512 — лишнее вдвое по стороне и вчетверо по весу.
- **Оригинал нигде не хранится.** Посмотреть аватар целиком нельзя.
- **Точно уменьшить до заданной стороны клиент не умеет.** На Android есть только грубое
  уменьшение степенями двойки при раскодировании, на десктопе нет никакого.

---

## 1. Стандарт: одна большая сторона

**Фото, которое уходит из приложения, уменьшается по большой стороне до 1280.**

- Пропорции сохраняются, картинка не искажается и не обрезается.
- Меньше 1280 — не увеличивается.
- Ориентация не важна: горизонтальное 4000×3000 станет 1280×960, вертикальное 3000×4000 —
  960×1280.
- **1280 — параметр, а не число в коде.** Одно место на клиенте, откуда его берут все,
  кто отправляет фото.

Раньше в обсуждении звучала рамка 1792×828. Заказчик заменил её одной стороной 1280.

## 2. Задачи

### Ф1. Параметр и уменьшение

- Параметр «большая сторона передаваемого фото» = 1280, в `core-media`.
- Функция: байты картинки → поворот по EXIF → уменьшение по большой стороне → JPEG. Нужна на
  Android и на десктопе, iOS — позже вместе с выбором картинки.
- Тест на пропорции: 4000×3000 → 1280×960, 3000×4000 → 960×1280, 800×600 остаётся 800×600.

### Ф2. Аватар: малая копия и полное изображение

Задача, с которой план начался. Заказчик 2026-09-26: «по нажатию увидим полное изображение.
Полное храним в соответствии с тем, что загрузили. Обрезка создаёт её малую копию».

- **Полное** — выбранная картинка без обрезки, уменьшенная по Ф1.
- **Малая копия** — обрезанный квадрат. Именно она показывается в списках, шапках, на
  страницах.
- На сервере: колонка `persons.avatar_full_media_id` (миграция 0056, аддитивная). В
  `PATCH /users/me/avatar` необязательное поле `full_media_id`, в `GET /users/me` — поле
  `avatar_full_media_id`. Черновик написан 2026-09-26, не закоммичен, остановлен
  заказчиком до обсуждения.
- На клиенте: нажатие на аватар в профиле и на странице «Я» открывает полное. Полного нет
  (аватар поставлен раньше) — открывается малая копия.

### Ф3. Все остальные фото

Когда появятся вложения в переписке, аватары групп и прочее — они уменьшаются по тому же
параметру, а не своим числом.

## 3. Открытые вопросы

1. **Сторона малой копии аватара.** Сейчас 512. Предложено 240 — крупный аватар 80 dp при
   плотности ×3. Или оставить 512 ради будущих мест крупнее?
2. **Качество JPEG.** Сейчас 85. Сделать его параметром рядом с 1280?
3. **PNG с прозрачностью.** При переводе в JPEG прозрачное станет чёрным или белым.
   Оставлять PNG как есть или заливать фон?
4. **Где живёт параметр.** Только на клиенте или приходит с сервера (`/version` или
   настройки)? С сервера можно поменять без выпуска приложения, но это ещё одна
   зависимость.
5. **Что делать с оригиналом больше 1280, если человек хочет отправить «как есть».**
   Отдельная отправка «файлом» без уменьшения или никогда?
