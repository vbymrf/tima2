### Ф2. Перечень кодов

Коды ставятся **до** наполнения: раз попавший в журнал код не меняется.

- Источник — код приложения, а не `doc/01…07` (они о первом приложении): окна
  (`Call`…`Bench` → `call`…`bench`), подокна (`whereCode` в `Root`: `chat`, `profile`,
  `settings.<пункт>`…), пункты настроек в порядке экрана, кнопки окон и подокон.
- Сверка с `ИНТЕРФЕЙС/<раздел>/ФУНКЦИОНАЛ.md`: там описано, что сделано, по датам.
- Итог этапа — список кодов по разделам ведомости, показанный заказчику до наполнения.

### Ф3. Ведомость телефона

- По разделам в порядке экрана. Строка: код, что делает (одной фразой), ссылка на
  описание в `ИНТЕРФЕЙС/`, чем проверяется.
- «Чем проверяется» — по тому, что есть сейчас: автотесты в коде (`jvmTest`, по классу и
  имени), сценарии `maestro/`, тесты словами из `АВТОТЕСТЫ/СЦЕНАРИИ/`. Нет ничего — **нет**.
- Функция в нескольких местах — туда, где её вероятнее будут искать; ни в одном — «Без
  места».

### Ф4. Ведомость ПК

То же для ПК. Общее с телефоном — своими строками: реализация другая, и проверена она
может быть по-разному.

### Ф5. Коды в тестах словами

Коды вида «Д-Т1», «Я-Д1» в `АВТОТЕСТЫ/СЦЕНАРИИ/` заменить кодами функций; таблица
«прежний → новый» — здесь, чтобы старые отчёты в `отчёты/` находились.

### Ф6. Пробелы

Список функций с «**нет**» в столбце проверки — очередь на автотесты. Порядок, в каком их
покрывать сценариями Maestro, выбирает заказчик.

## Не входит

- Прежние проверки из `отчёты/` в журнал не переносятся: журнал начинается с первой
  проверки по новому формату.
- Прогон автотестов — как и прежде, только по просьбе заказчика.
