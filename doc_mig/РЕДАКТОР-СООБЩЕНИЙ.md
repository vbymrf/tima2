## 1. Тело сообщения: узлы и разметка

Формат уже есть — [ADR-0011](../doc/adr/0011-message-content-model.md): текст — массив узлов
(`MessageBody.nodes`), структура — разметка JSON (`MessageBody.markup`), вложения — `MediaRef`
(`schema/proto/message_body.proto`). Обычное сообщение — один узел без разметки (ADR-0011 §3).
Редактор не заводит новый формат, а **наполняет разметку**:

| Что | Как | Решено |
|---|---|---|
| **Узел** | текст **вне** ряда и таблицы — до, между и после них — отдельные узлы; **каждая ячейка** ряда и таблицы — свой узел: ниже ячейки оформление не идёт | 2026-10-18 (Н2) |
| **Ряд** | блок разметки `flex`: **строки × столбцы** — до 20 строк и до 7 столбцов; ширины столбцов в процентах (сумма 100), высоту строки задаёт содержимое; ячейки сливаются с левой и с верхней; свой стиль у ряда и ячейки. Однострочный ряд без слияний пишется прежним видом (`flex` → ячейки), многострочный — `flex` → строки `row` → ячейки | 2026-10-17; строки, столбцы и слияние — 2026-10-18 (вечер) |
| **Таблица** | **в редакторе её больше нет — таблица стала рядом** (2026-10-18, вечер). Блок `table` из быстрого оформления остаётся: старые сообщения с таблицей показываются как раньше; строкой ввода таблица по-прежнему набирается знаками | 2026-10-16; 2026-10-18 |
| **Ячейка** | место в ряду или таблице, свой стиль | 2026-10-17 |
| **Виджет** | сущность внутри ячейки: Текст, Картинка, Ссылка, Облако, Карта, Контакт, Ответ, Из подборки, Эмоджи (§10.4) | 2026-10-17 |
| **Стиль** | имена палитры и ступени, не коды и не пиксели; указано только изменённое — остальное по умолчанию; защитный пол действует всегда (ADR-0011 §9) | 2026-10-17 |
| **Предел текста** | 4096 знаков (ADR-0019 §3) — **на массив узлов**; у разметки JSON **свой предел** | 2026-10-18 (Н1) |
| **Предел разметки** | **32 КБ** JSON до сжатия; открытое сообщение целиком (узлы, разметка, ссылки на медиа) — **48 КБ** вместо нынешних 16 КБ. Числа выбраны с запасом под 20 рядов × 4 ячейки, правятся на живых примерах | 2026-10-18 (РС-В1: «ставь оптимальное, подправим») |
| **Уровень** | у конверта, не в теле; в JSON редактора не входит | 2026-10-17 |

Слова «ряд», «ячейка», «таблица», «виджет» — **приняты** (2026-10-18, В24). На экране вместо «виджет» — его вид: «Текст», «Картинка».

**Правка — по узлам** (§8): изменённые узлы уходят новой записью; ячейка — узел, поэтому
правка ячейки не трогает соседние.

## 2. Пузырь и вне пузыря

**Есть текст — пузырь. Иначе — отдельный формат вне пузыря** (2026-10-15).

| | Личная переписка | Группа, канал |
|---|---|---|
| Внутри пузыря | текст и разметка; картинки под ширину места (§3) | то же |
| Вне пузыря | сообщение **без текста**: одно или несколько фото (§3), файлы, аудио, видео — **почтальон** (§6), до 10 МБ; себе — до 50 МБ | **нет**: файлы, альбомы, звук, видео |
| Файл, документ, аудио, видео | почтальон | **ссылкой** на файл вне телефона (облако); кнопки скрепки есть, но просят ссылку (2026-10-17) |
| Голосовое | есть | **нет**, справа всегда «отправить» (2026-10-17) |
| Контакт | карточкой | карточкой (2026-10-17) |
| Сообщение только из эмодзи | крупно, анимацией (`СТИКЕР-В-ТЕЛЕ-СООБЩЕНИЯ.md`) | то же |

## 3. Картинки: два вида сообщения (решено 2026-10-18, РС-В9)

**Сообщений с картинками два вида — без текста и с текстом через редактор**, и живут они по-разному:

| | Без текста (вне пузыря, личная переписка) | С текстом, через редактор (внутри пузыря) |
|---|---|---|
| Сколько за раз | **одно или несколько** фото | **по одной** картинке на вставку |
| Размер | по [ПЛАН-(ПФ)](ПЛАН-(ПФ)-ПЕРЕДАВАЕМЫХ-ФАЙЛОВ.md): большая сторона 1280 | под место: ширина места в долях от 720 — ряд целиком 720, ячейка 67 % — 482, 33 % — 238; высота по пропорции |
| Превью | **нет в теле** (2026-10-22): приходит всё фото, превью делает получивший клиент; одно фото — в ленте из полного | **нет**: картинка подрезается под место на лету |
| Раскрытие | по нажатию: масштаб, «Повернуть», «Изменить» (2026-10-22) | нет |
| Сколько живёт | почтальон (§6): клиент забирает фото сразу, не по нажатию | пока живёт сообщение (Н4) |

**Фото без текста — целиком, превью у получателя** (заказчик 2026-10-22, заменяет решение
2026-10-18 о превью в теле, ниже зачёркнутое):

- **Клиент забирает фото у почтальона целиком и сразу**, как сообщение. Превью для нескольких фото
  в ленте делает сам из полного. **Одно фото** в ленте — из полного, в качестве по ширине места.
- **Превью в теле нет.** Поддержки прежних сообщений с превью нет: бета, только тестеры.
- **Фото встаёт на своё место.** Место в ленте задаёт сообщение, а размеры (`width`, `height`)
  едут в его теле. Пока фото качается — пустое место его размера, лента не прыгает.
- **Не скачалось и уже не скачается** (срок почтальона вышел, повторную просьбу исполнить некому)
  — **фото нет**, как нет нечитаемого сообщения. Сообщение только из фото не показывается; текст
  рядом с фото, если есть, остаётся.
- **Повторная просьба** опоздавшего устройства (§6) остаётся.
- **Мобильная сеть** (2026-10-22): «Память и трафик» → «Качать файлы по мобильной сети», **по
  умолчанию включено**: фото и файлы скачиваются сами, без входа в переписку. Выключено — по мобильной
  сети ждут Wi-Fi, и **на месте фото надпись «Ждёт Wi-Fi…»**: иначе человек видит пустое место и не
  знает почему.
- **Группы — отложено** (2026-10-22): фото без текста в группе нет (§2), картинка внутри пузыря не
  раскрывается.
- **Исходного качества нет**: отправитель ужимает до 1280, как прежде.
- **Что принимает, задаёт сервер** (2026-10-22): пределы, виды файлов, сроки. Клиент спрашивает
  правила **не чаще раза в сутки** и соблюдает их до отправки, в том числе сторону фото: файл
  зашифрован, и сервер видит только размер и заявленный вид. Прислали не то — отказ, клиент
  показывает его сообщением. Дальше подписка будет давать больший размер и другой срок — тем же
  ответом сервера.

- **Во всех случаях, если изображения нет** (не загрузилось, не докачалось, удалено) — **заглушка с
  крестиком размером с фото**: размеры едут в `MediaRef` (`width`, `height`), поэтому место под
  картинкой известно до загрузки и лента не прыгает. *Для фото без текста заменено 2026-10-22:
  фото нет, выше.*
- Прежнее «превью делает принявший клиент» (2026-10-16) заменено: превью шлёт отправитель.
  *Возвращено 2026-10-22: превью делает получивший клиент.*
- ~~**Превью фото без текста** (2026-10-18)~~ — *отменено 2026-10-22, выше*: лежит **внутри зашифрованного тела**, а не у почтальона —
  поэтому живёт, пока живёт сообщение, и у опоздавшего устройства после срока почтальона остаётся
  превью, а не заглушка. **До 10 фото в одном сообщении**, превью каждого — **до 20 КБ**, всё
  вместе — до 200 КБ в теле.
- **Размер превью — что влезает в 20 КБ** (заказчик: «проверить, что влезет, то и делаем»). Замер
  2026-10-18 на пяти фото от 1280×720 до 9052×4965 (JPEG, сжатие Java, у телефона числа будут
  немного другими):

  | Большая сторона | Качество 0,6 | 0,7 | 0,8 |
  |---|---|---|---|
  | 240 | 7–12 КБ | 9–14 КБ | 11–17 КБ |
  | **320** | 12–21 КБ | **14–24 КБ** | 17–29 КБ |
  | 400 | 17–32 КБ | 20–37 КБ | 25–45 КБ |

  **Выбрано: большая сторона 320, качество 0,7**; не влезло в 20 КБ — качество 0,6, затем сторона
  280 и 240, пока не влезет. Детальная панорама 9052×4965 на 320 весит 24 КБ при 0,7 и 20,7 КБ при
  0,6 — ей понадобится шаг вниз, обычным фото — нет. Проверить тем же замером на телефоне при
  внедрении (РС8).
- **Перенесли виджет или сменили ширину ячейки — картинка заново сделана из исходного файла**, а
  не растянута из ужатой (2026-10-17). Исходный файл держит отправитель, пока жив черновик;
  уходит готовый размер (предложение).
- **Всё, что внутри сообщения, живёт, пока живёт сообщение** (2026-10-18, Н4); удалено сообщение —
  удалено и то, что внутри.
- **Не больше 10 картинок в одном сообщении** (2026-10-18, РС-В2).
- Показ — через загрузчик Sketch ([ПЛАН-(ЗК)](ПЛАН-(ЗК)-ЗАГРУЗЧИК-КАРТИНОК.md)).
- **Просмотр фото без текста** (заказчик 2026-10-18): во весь экран на сплошном тёмном фоне; слева
  сверху «≡» — Сохранить как, Удалить у себя, Удалить у всех (своё отправленное), Переслать (выбор
  переписки — фото уходит там отдельным сообщением), Поделиться (системное, на ПК нет — сохранить и
  отправить файлом), Информация (имя, размер, точки, кто прислал); справа «✕». «‹» и «›» по краям и
  смахивание вбок — соседние фото переписки от старых к новым, вниз — закрыть; «3 из 12» сверху.
  Кнопки — на сплошном круге темы, без прозрачности: на светлом фото прозрачная не видна. Удалить —
  сообщение, в котором фото пришло.
- **Масштаб, поворот и редактор фото** (заказчик 2026-10-22), порядок работ —
  [ПЛАН-(ИФ)](ПЛАН-(ИФ)-ИЗМЕНЕНИЯ-ФОТО.md):
  - **Масштаб** в просмотре: щипок и двойное нажатие, на ПК колесо. Увеличенное фото двигается
    пальцем, а не листается.
  - **Слева внизу две кнопки: «Повернуть» и «Изменить».** «Изменить» открывает редактор: обрезка,
    кисть, стрелка; поворот есть и там.
  - ~~**Поворот — правка**, а не настройка на устройстве: после неё фото досылается.~~ — **заменено
    2026-10-22 (вечер)**: поворот кнопкой просмотра — **только у себя**; при первом повороте над кнопкой —
    «Изменённая здесь — только у вас. Измените через редактор — отправим собеседнику (кнопка
    «Изменить»)», закрывается нажатием мимо. Собеседнику уходит сохранённое в редакторе.
  - **Досылка одна на сеанс просмотра.** Сохранил в редакторе, вернулся, сохранил ещё, закрыл просмотр —
    уходит **одна** правка, в момент закрытия просмотра.
  - **Править уже нельзя** (не своё, не отправлено, три правки, ключ сменился) — «Изменить» погашена; по
    нажатию над ней — почему и совет «Отправьте фото заново или нажмите «Переслать»», закрывается
    нажатием мимо.
  - **Получатель видит готовый результат.** Место в ленте то же, пометка «изменено». Редактор
    прежних состояний не хранит, прежнюю версию никто не видит.
  - **Чужое фото** — правка только у себя: «Сохранить как» или «Переслать» новым фото в чат.
  - **Вид, правки 2026-10-22 (вечер):** в шапке просмотра — дата и время отправки; внизу «Повернуть»
    слева, «Изменить» справа, «3 из 12» между ними. **Закрытия смахиванием вниз нет** — ни в просмотре,
    ни в редакторе. Двойное нажатие: увеличенное — к исходному; короткий сдвиг считается нажатием
    («два быстрых коротких сдвига или сдвиг и клик — двойной клик»). Увеличенное не уводится краем за
    край экрана.
  - **Редактор:** внизу закреплены значки «Повернуть», «Обрезать», «Кисть», «Стрелка»; над ними при
    выборе — пояснение и что нужно: цвета, толщина, «Выполнить». «Повернуть» — сразу; обрезка, кисть,
    стрелка — нарисовал, «Выполнить» — осталось. Сверху «Отменить», «Повторить». Кисть и стрелку можно
    начинать за краем фото; рамку обрезки тянут за любой угол.
  - **Ещё правки того же вечера:** увеличенное фото в просмотре сдвигается по высоте **до кнопок**, а не
    до края экрана — между кнопками и краем видно чёрное, зато кнопки не закрывают фото; меню «≡»
    закрывается нажатием мимо него. В редакторе — масштаб двумя пальцами. Окно инструмента (обрезка,
    кисть, стрелка) встаёт **поверх** ряда значков и не больше его: «✕» — закрыть, галочка — выполнить.
    Плитки нескольких фото в ленте — в точном размере места (размеры те же, качество выше).
  - **Редактор, ещё правки:** увеличенная картинка не заходит на верхние кнопки и значки — они видны
    всегда; окно инструмента закрывает ряд вместе с подписями; у кисти и стрелки текста нет; двойное
    нажатие работает при любом выбранном инструменте (короткое касание — нажатие, оно не рисует).
  - **Поле у края фото** (2026-10-22): при кисти, стрелке и обрезке фото чуть меньше, вокруг — поле для
    пальца внутри области рисования; след и рамку начинают с него.
  - **Перья кисти** (2026-10-22): тонкое и толстое — сплошные; два полупрозрачных (пустой круг) —
    размером с толстую кисть и шире, как маркер. У стрелки — только сплошные.
  - **Граница сдвига в просмотре** — по краю самих кнопок (низ верхних, верх нижних), без отступов их
    полос.
  - **Одно фото перед отправкой** (2026-10-22): выбрано одно фото или снято камерой — открывается тот же
    редактор, главная кнопка «Отправить» вместо «Сохранить»; «Отмена» — не отправлять. Несколько фото
    уходят сразу, как прежде. Уходит изменённое, по правилам приёма (1280).
  - **Слоями** (2026-10-22): фото не трогается, рисунки — свой слой, поворот и рамка — на всю стопку. Итог
    сводится по «Отправить» на исходнике нужного размера и только потом уменьшается до 1280 — обрезанное
    не мельчит. Рамку можно поправить после рисования.
  - **Кисть, ещё** (2026-10-22): полупрозрачные следы — **одним слоем**, как закрашено, пересечения не
    темнеют; **ластик** малый и большой — стирает нарисованное (кисть, маркер, стрелку), фото не трогает;
    в палитре последним — **наш зелёный** (шапки), для кисти и стрелки. Подсказка над «Повернуть»
    закрывается любым касанием и его не съедает — второе нажатие поворачивает.
  - **Листание лентой** (2026-10-22): смахивание ведёт ленту фото — текущее уезжает, соседнее приезжает;
    дальше трети ширины или быстрым движением — к соседнему, иначе обратно; у первого и последнего — тянется
    с сопротивлением и пружиной возвращается; «‹» и «›» — тем же движением.
    **Листание пропускает фото, которого нет** (2026-10-23): удалённое у почтальона, ждущее Wi-Fi, не
    загрузившееся. «Файла на сервере уже нет» — только у открытого прямо нажатием, пока оно на экране; ушли с
    него — в ленте его больше нет. Счёт «3 из 12» — по оставшимся.
  - **«Текст» вместо «Стрелки»** (2026-10-22): кнопка «А». В окне — цвета, «Обычный / Жирный / Курсив»,
    «Текст / Фон» (фон по умолчанию без цвета). Надпись — в рамке, своим слоем выше рисунков (ластик её не
    трогает); заливка рамки со скруглёнными углами, как у пузыря; текст по середине рамки — по ширине и по высоте (2026-10-23; прежде — по левому краю), размер букв — по рамке.
    Три состояния: нет выбора (сохранённые — серые рамки, видны только при «Тексте»; нажатие в рамку —
    правка, мимо — новая рамка: угол в точке нажатия, 60 % ширины, две строки); набор — своя область между
    кнопками сверху и окном «Текста» над клавиатурой, нажатия мимо не действуют; положение и размер — углы и
    маркер в центре, нажатие внутрь — снова набор. Первая галочка — к положению, вторая — сохранено; при выборе
    галочка и крестик зелёные; крестик снимает выбор (новая пропадает, сохранённая остаётся); стёрли весь
    текст — надпись убирается. «Сохранить» вверху — как обе галочки сразу.
    **Рамка надписи — как у обрезки** (2026-10-22, вечер): сразу, без задержки — у угла тянется угол, в
    остальной рамке — перенос целиком (маркера в центре нет); текст едет прежним размером, размер букв
    подбирается после отпускания; долгое нажатие внутрь — снова набор; затемнения нет.
    Кнопки начертания — первые буквы слов: «А» — абзац, «Ж» — жирный, «К» — курсив.
    Снова к набору — двойное нажатие внутри рамки или долгое (0,9 с).
    **Мимо рамки палец двигает фото** (2026-10-23): при «Тексте», есть рамка или нет, движение одним пальцем вне
    рамки сдвигает увеличенное фото, как без инструмента; рамку ставит только нажатие.
  - **Прежний файл** после досылки отправитель убирает у почтальона сразу (2026-10-22, ИФ-В2).
  - Формат и сервер — [ADR-0052](../doc/adr/0052-photo-whole-no-preview-photo-edit.md).

## 4. Ссылки (решено 2026-10-15)

**Ссылку открывает браузер, а не приложение.** Кроме видео и звука: их ссылки открываются окном
проигрывания TIMA, а название и картинку их пузыря загружает устройство получателя при прокрутке
(заказчик 2026-10-23, [ПЛАН-(ВМ)](ПЛАН-(ВМ)-ВОСПРОИЗВЕДЕНИЯ-МЕДИА.md) §3). Три режима вставки:

| Режим | Что видит получатель | Сеть у отправителя |
|---|---|---|
| без оформления | текст ссылки | нет |
| кнопка | наша картинка: крупно домен, ниже обрезанный путь без `http://` | нет |
| карточка со страницы | название, описание, картинка с сайта | да |

**Карточку делает клиент отправителя**, получатель ничего не скачивает: карточка едет внутри
тела. Клиент читает только служебные строки страницы (`og:title`, `og:description`,
`og:image`; запасные — `<title>`, `<meta name="description">`), страница не исполняется.

| Риск | Правило |
|---|---|
| сайт видит адрес отправителя | принимается: запрос делает только отправитель |
| `og:title` врёт | **домен берётся из самой ссылки, показывается всегда и не обрезается**; обрезается только путь |
| домен из похожих букв разных алфавитов | показывается как `xn--…` |
| огромная страница, зависание | не больше ~512 КБ HTML и ~5 МБ картинки, 5–10 с, только `http`/`https` (числа — при реализации) |
| ссылка во внутреннюю сеть | запрос запрещён |
| вредная картинка | раскодируется и перекодируется у отправителя |
| `http` без шифрования | пометка на кнопке |
| человек не хочет запросов | карточка выключается в настройках |

- **Поделиться в TIMA** из браузера и других приложений: Android объявляет приём текста и
  картинок → выбор чата → редактор. Сейчас не принимает. На ПК — вставка и перетаскивание.
- **Из TIMA**: долгое нажатие на кнопку ссылки — «Открыть в браузере», «Скопировать», «Поделиться».
- **Все ссылки в сообщении нажимаются** (заказчик 2026-10-19): вставленный в текст адрес **не
  показывается** — на его месте под абзацем синий пузырь «Перейти · домен» (длинный домен обрезан).
  Ссылка кнопкой без названия выглядит так же; с названием — название вместо «Перейти». Текстом с
  названием — название цветом ссылки; карточка — как была, домен цветом ссылки.
- **Окно перехода** — как меню сообщения: сверху домен крупно и «✕» справа, под ним **адрес целиком
  — только здесь он и виден**; строки «Перейти» и «Скопировать ссылку». Так у **всех** ссылок (в
  тексте, кнопкой, карточкой, облако).
- **Цвет ссылки** — цвет её узла в разметке (стиль блока `color`); не задан — клиент рисует **цветом
  ссылок из «Настройки → Цвета» («Ссылки»)**, по умолчанию синим. В «Вставить ссылку» — выбор цвета
  из палитры; выбранный запоминается до следующего раза.
- **«Скрепка → Ссылка»** — то же окно, что «Вставить ссылку» в редакторе (вид, название, цвет); ссылка
  уходит отдельным сообщением в своём пузыре, черновик редактора не трогается.

## 5. HTML

- HTML **не кладётся** в тело сообщения; скрипты запрещены; страница — это кнопка-ссылка
  (2026-10-15).
- **Файлы `.html` и `.svg` запрещены** как вложения (2026-10-15).
- **Вставка из системного буфера** «С оформл.»: из HTML берётся **только текст и простое
  оформление** — заголовки, жирный, курсив, подчёркнутый, зачёркнутый, маркер, списки, цитаты,
  код, таблица. **Картинок и ссылок из HTML нет — никаких**: от ссылки остаётся текст без адреса
  (2026-10-18, В32). Цвет, шрифт, размер, фон отбрасываются.
- **Картинка, лежащая в буфере сама по себе** (не в HTML) вставляется виджетом «Картинка»,
  ужатая по нашим правилам (2026-10-18, В35).
- Обычная вставка — только текст.

## 6. Файлы вне пузыря — почтальон (решено 2026-10-16…17)

**Только для личных сообщений.** **Голосовые — не почтальон**: и в личной, и в группе сервер держит
их срок, заданный на сервере, не отслеживая скачиваний (заказчик 2026-10-23,
[ПЛАН-(ВМ)](ПЛАН-(ВМ)-ВОСПРОИЗВЕДЕНИЯ-МЕДИА.md) §2.3). Сервер держит файл, пока его не заберут:

| Первое скачивание | Файл удаляется |
|---|---|
| в течение часа после загрузки на сервер | когда час истёк |
| позже часа | сразу после этого скачивания |
| никто не скачал | через неделю |

- **Час — с момента загрузки на сервер.** Скачал — **любое устройство получателя**; свои устройства
  отправителя не забирают.
- **Нажатия не ждём**: «приди и получи», как у сообщения. **Опоздавшее устройство** просит файл
  повторно — его снова загружает устройство, у которого файл есть.
- **О скачивании — галочками**, как у сообщения: две — приложение забрало, три — человек увидел.
- На сервере: время первого скачивания и срок удаления у записи файла; сборщик раз в минуту;
  страховка — правило жизненного цикла MinIO на 7 дней. **Шестимесячный пол на файлы не
  распространяется.**
- **Пределы:** 10 МБ на файл (переменная сервера); **себе — 50 МБ**: получатель — другое наше
  устройство, нет его — файл просто лежит в своей папке. Аудио и видео в личной — до 10 МБ.
  **Прежний предел «2 ГБ на файл» снят** (2026-10-18, РС-В8).
- **Запреты:** исполняемые, `.html`, `.svg` — проверка на клиенте после выбора, отказ с причиной.
  **Архивы и `.apk`** — предупреждение, не запрет; внутрь не смотрим; TIMA их не открывает —
  только «Сохранить как».
- **Пересылка удалённого** — только новой загрузкой с устройства, где файл остался. Запросить не у
  кого — пустышка: имя файла и «недоступен».

**Файл на устройстве:**

- **Хранится в своей папке приложения**, имя на диске — по номеру сообщения, латиницей; имя файла
  — в сообщении. **Хранится зашифрованным** (2026-10-18, РС-В7): расшифровывается при показе и
  воспроизведении, как требует [ПЛАН-(ВМ)](ПЛАН-(ВМ)-ВОСПРОИЗВЕДЕНИЯ-МЕДИА.md) ВМ-В1. «Сохранить
  как» отдаёт расшифрованную копию туда, куда укажет человек.
- Файл почтальона после срока **не докачивается**: удалили у себя — вернуть можно, только если
  его ещё держит сервер или другое устройство ([ПЛАН-(ПМ)](ПЛАН-(ПМ)-ПАМЯТИ.md) §1 считал медиа
  перекачиваемым всегда).
- **«Сохранить как»** у файла и фото — копия туда, куда укажет человек; правилам хранения TIMA не
  подчиняется.
- **Настройки «Память и трафик → Медиа и другие файлы»** (принято 2026-10-16):

| Тип | Что | Держать | Но не больше | Если удалено |
|---|---|---|---|---|
| Фото | вне пузыря, личная | 3 месяца | 1 ГБ | у отправителя пустышка; у получателя — повторный запрос, пока можно прислать |
| Файлы | вне пузыря, личная | 1 месяц | 1 ГБ | то же |
| Картинки в сообщениях | внутри пузыря | — | 300 МБ | докачиваются, пока живо сообщение: это кеш |

Строки раздела: «Занимает» (всего и по типу), «Держать» (недели, месяцы, «Всегда»), «Но не
больше» (300 МБ … 5 ГБ), «Очистить сейчас». Признак «докачивается» у каждого файла; удаление
недокачиваемого — с предупреждением.

**Фото вне пузыря** — по [ПЛАН-(ПФ)](ПЛАН-(ПФ)-ПЕРЕДАВАЕМЫХ-ФАЙЛОВ.md) (большая сторона 1280),
~~превью отправляет отправитель, полное — по нажатию~~ — *с 2026-10-22 фото забирается целиком
сразу, превью делает получатель (§3)*.

## 7. Быстрое оформление — упрощённый Markdown (решено 2026-10-16…17)

Знаки превращаются в оформление на лету. В сообщение уходят узлы и разметка, а не текст
Markdown.

| Что | Как |
|---|---|
| Заголовки | `# `, `## `, `### ` в начале строки, с пробелом |
| Список | `- ` в начале строки — **единственный вид списка**; нумерованного нет: `- 1.1` — имя пункта, текст |
| Вложенность | **только пробелами**, любое число; **два вложения**; вложенный — отступ больше, чем у предыдущего; по умолчанию раскрыты, сворачиваются |
| Жирный | только `**текст**` |
| Курсив | `*текст*`; `_текст_` — ничего |
| Подчёркнутый | `++текст++`; `__текст__` — ничего (из-за `__init__`) |
| Маркер | `==текст==` (новый тип в каталоге `MarkupTypes`) |
| Зачёркнутый | `~~текст~~` |
| Код | `` `текст` ``; блок кода — три обратные кавычки на отдельных строках, разметка внутри не действует |
| Цитата | `-->` в начале строки |
| Разделитель | `---` или `***` на отдельной строке |
| Перенос строки | один Enter — новая строка |
| Ответ | `@Ник` — блок ответа (ниже) |
| Ссылка, картинка, карта и прочее | **только через редактор**, знаков нет |

**Экранирование:** `\` перед знаком — текст (`\#`, `\*`, `\_`, `` \` ``, `\+`, `\=`, `\-`, `\|`,
`\\`); внутри кода разметка не действует; **стирание сразу после превращения возвращает знаки**.

**Против ложных срабатываний:** парные метки — по правилу CommonMark (открывающая перед
непробельным, закрывающая после непробельного); `*` внутри слов — по CommonMark; одиночная метка
без пары — текст (`C++`, `a == b`, `--force`); `#тег` без пробела — хештег; внутри голого адреса
разметка не действует; нумерованных списков нет, поэтому `2024. Год` не срабатывает.

**Вложенность пробелами:** пункт вложен в ближайший выше с меньшим отступом; третье вложение
прижимается ко второму уровню. Перед знаком в начале строки — любое число пробелов или табуляций
(табуляция с ПК — 4 пробела).

**`@Ник` — ответ:** блок внутри сообщения — имя на цветном фоне человека с полосой, вторая строка
— что влезло из его сообщения; нажатие — переход к нему (§11.5). Набрано текстом — ответ на
**последнее** сообщение человека в переписке; через «Ответить» — на указанное. У того, кому
ответили, — в «Свободном общении». Сообщений нет — только имя; сообщение удалено — «Сообщение
удалено».

**Таблица** — как в GFM, выравнивание `:---`, `---:`, `:---:`. **Объединение: `^^` — с верхней,
`<<` — с левой**; знак считается, только если ячейка состоит из него одного. Пустая ячейка
остаётся. **Горизонтальной прокрутки нет** — ни у таблицы, ни у ряда (§10.3).

**Переключатель «Знаки md»** — один на все сообщения, включён по умолчанию, **действует и в
строке ввода**: выключен — знаки экранируются и уходят как есть (2026-10-18, В31).

**В строке ввода знаки видны серым**, текст уже оформлен; в редакторе знаков нет — показано готовое.

## 8. Удаление и правка (решено 2026-10-16)

**Уровни 8 и 9 не вводятся, `deleted`/`deleted_by` не расширяется.** В личной переписке уровни
−1 и 0.

| Удаление | Как |
|---|---|
| у себя | только на устройстве |
| у всех | новый маршрут ставит `deleted`, `deleted_at`, в группе `deleted_by`; право — автор, в группе ещё модератор и админ |
| уже получившие | событие «сообщение удалено» → строка «Сообщение удалено» |
| содержимое | на сервере до конца срока эпохи, как все сообщения |
| что внутри | удалено вместе с сообщением |
| вернуть | **нельзя** |

**Правка — новая запись, не замена.** Одно взломанное устройство иначе переписало бы историю без
следа.

| Что | Как |
|---|---|
| запись правки | обычный конверт; открыто — пометка «правка» и номер исходного; без уведомления, без счётчика, не последняя строка в списке |
| внутри | только изменённые **узлы** (§1): «узел № → новый текст»; номера те же, разметка на месте |
| видит человек | исходное с применёнными правками и «изменено»; цепочку правок можно посмотреть |
| кто | только автор (проверяет сервер) |
| сколько | **не больше 3 правок** на сообщение; четвёртую сервер не примет, клиент прячет «Изменить» |
| до когда | **до первой смены ключа**; когда «Изменить» пропадёт — сказать на экране |
| вступивший после | правку без исходного не показывает |
| удаление | правки скрываются вместе с исходным |
| фото (2026-10-22) | правка **заменяет фото** целиком: новый файл, ключ, размеры; считается **досылка** — одна на сеанс просмотра (§3), предел тот же — 3; цепочки нет — видно только готовое |

## 9. Строка ввода (решено 2026-10-17…18)

| Слева направо | Что |
|---|---|
| **Редактор** | три полосы; серый; **зелёный** — сообщение собрано в редакторе |
| **Пузырь ввода** | серые кнопки внутри: Эмоджи, Галерея (системная), Скрепка; набран символ — остаётся Эмоджи |
| **Справа** | голос, пока не введён хоть один символ, потом «отправить» (вид — проба 05 `doc/Layout-UI-light/пробы-редактор/подокна.html`); в редакторе — всегда «отправить»; ~~в группе и канале всегда «отправить»~~ — *с 2026-10-23 голос и в группе ([ПЛАН-(ВМ)](ПЛАН-(ВМ)-ВОСПРОИЗВЕДЕНИЯ-МЕДИА.md) Р2); в канале голосовых нет — только виджет «Аудио» (Р19)* |

- **Эмоджи, Галерея, Скрепка, Голос убирают клавиатуру** и открывают свою область с крестиком.
  При пустой строке вставляют **отдельным сообщением** вне пузыря; внутрь сообщения — только через
  редактор.
- **Скрепка — девять пунктов:** Файл, Документ, Картинка, Камера, Аудио, Видео, Контакты, Карта,
  Ссылка; ярлычок и подпись — одна нажимаемая плитка. Карта — координаты и кнопки «Яндекс
  Карты», «Google Карты». Как каждый пункт делается на Android и ПК — таблица в
  `ВЫБОР-РЕАЛИЗАЦИИ.md` §11.2а (предложение, сверяется при реализации): системные окна выбора,
  Photo Picker без разрешения, камера с разрешением, местоположение — новое разрешение.
- **Группа и канал**: кнопки те же, файл, документ, аудио, видео, карта — ссылкой.
- **Выбора уровня над строкой нет.** Быстрая отправка: зашифрованное **−1**, нешифрованное **2**;
  другой уровень — только в редакторе (2026-10-17).
- **Собрано в редакторе**: чип «Оформлено в редакторе · N рядов», строка ввода показывает первую
  строку и не даёт печатать в разметку; «отправить» шлёт собранное. **Корзина** в чипе сбрасывает
  редактор — строка как пустая; **5 секунд «Вернуть»** (2026-10-18, В36).
- **Черновик у каждой переписки свой**, хранится на устройстве **зашифрованным** и переживает
  перезапуск (2026-10-18, Н7). В очередь исходящих он не попадает: черновик живёт в редакторе
  ([ADR-0020](../doc/adr/0020-outgoing-queue.md)).
- **Комментарии — только строка ввода** со знаками, без редактора (2026-10-18, Н5).

## 10. Редактор (решено 2026-10-17…18)

Окно поверх переписки; сообщение показано так, как увидит получатель, ввод прямо в нём.

### 10.1. Шапка

‹ назад (черновик сохраняется) · **название** — нажатие показывает сообщение глазами получателя ·
**↶ ↷** отменить, повторить — значками без подписи · **цифра уровня** · ➤ отправить.

- **Уровень** — на кнопке только цифра; нажатие — список, где у каждой строки **описание перед
  цифрой**: название круга и строка последствия (слова `MessageCircle`). Личная переписка — только
  −1, кнопка серая; личная группа — −1 и 0; публичная группа и канал — 0, 1, 2, 3.
- **Отменить** — 50 шагов на черновик (2026-10-18, Н10).
- **У отправленного сообщения уровень виден, только если он не стандартный**: −1 и 2 —
  стандарт, метки нет; иначе — **цифра в кружке перед временем** (2026-10-18, В29).
- **Сузить уже отправленное** — та же кнопка-цифра и тот же список «описание перед цифрой», только
  уровни уже нынешнего; чипов со словами нет (2026-10-18, В29).

### 10.2. Разделы и лента кнопок

Названия разделов — по настройке «Шрифты и размеры», группа «Вкладки»; подписи под значками —
постоянного размера. На телефоне шесть кнопок и половина седьмой; на ПК — стрелки в разделителе
между кнопками и сообщением. Последний открытый раздел запоминается.

| Раздел | Кнопки |
|---|---|
| **Текст** | Абзац ▾ · Жирный · Курсив · Подчёрк. · Зачёрк. · Маркер · Код · Символ · С оформл. |
| **Вставка** | Картинка · Ссылка · Эмоджи · Подборка · Подкладка · Облако · Карта · Контакт · Ответ |
| **Разметка** | Ряд · +Столбец · −Столбец · +Строка · −Строка · С левой · С верхней · Разъедин. · Выше · Ниже · Удалить |
| **Стиль** | Виджет · Фон · Цвет · Размер · Выровн. · Отступ · Раздел. · Сброс · JSON |

- **Абзац ▾** — абзац, заголовок 1–3, цитата, список, список второго уровня, блок кода.
- **Вставка — на строку курсора** (заказчик 2026-10-21): виджет, подборка, подкладка, список, ряд.
  Курсор на пустой строке — вставленное встаёт вместо неё; в начале непустой — над ней; иначе — под
  строкой курсора; в последней строке — за куском. Кусок текста режется надвое. Выбран виджет — под
  ним. Подкладка и ответ в ячейку ряда не встают — за ряд. Убрали или увели вставленное — два сошедшихся
  куска текста сливаются в один, курсор на стыке (куски одного вида; разный фон — не сливаются).
- **Оформление части текста — кнопками ленты Ж, К, Ч, З, М, код, «нажата — отжата»** (заказчик
  2026-10-18, вместо прежней чёрной полоски над выделенным: она ложилась на системное «Вырезать ·
  Копировать · Выделить всё»). Выделено — оформляется выделенное; кнопка нажата, если оно уже такое,
  повторное нажатие снимает. Не выделено — как в Word: оформление ждёт следующей буквы, повторное
  нажатие в конце оформленного его закрывает, другая кнопка закрывает прежнее и начинает своё. Цвета
  и размера у части текста нет.
- **Упрощённый формат (знаки) в редакторе не используется** (заказчик 2026-10-18, вечер):
  набранные `*`, `#`, `|`, `-` остаются знаками и ничего не оформляют; оформление — только кнопками
  ленты и «Абзац ▾»; кнопки «Знаки md» нет. «С оформл.» (вставка из браузера) переносит оформление.
  В строке ввода переписки знаки работают, как прежде (РС5). Уже набранное оформление показано без
  знаков; стёртый спрятанный знак стирает видимую букву.
- **Пустое место под сообщением** — нажатие ставит курсор после всего, как Enter в конце: после
  виджета и ряда — новым текстом.
- **Стиль куска виден в самом редакторе** — фон, поля, цвет, размер, выравнивание, разделитель.
- **Черновик пишется по ходу правки** (через полсекунды после последней), а не только по «‹»: уход
  из приложения и закрытый процесс его не теряют.
- **Символ** — область: Недавние, Знаки, Стрелки, Валюта; неразрывный пробел; вставленный кнопкой
  знак разметки экранируется сам.
- **Стиль действует на выбранное** — ряд, ячейку или виджет; что выбрано, написано в разделителе.
  Отступ — у ряда и ячейки, ступенями (нет, малый, обычный, большой). JSON — та же разметка
  текстом, только изменённое, с проверкой до «Применить» (каталог, ширины, палитра, ступени,
  защитный пол). **JSON — стиль выбранного** (ряда, ячейки, куска), а не вся разметка сообщения
  (подтверждено заказчиком 2026-10-18).
- **ПК**: Ctrl+B и прочие сочетания, перетаскивание файлов в редактор (2026-10-18, Н11). Кнопки ленты
  — постоянной ширины (заказчик 2026-10-19): на широком окне не расползаются; помещаются все —
  стрелок нет, нет — стрелки в разделителе.
- **Редактор есть и на личной странице** (2026-10-18, Н5).

### 10.3. Ряд, ячейка, перенос

- Нажали на ячейку — пишем; переключились — написанное стало **виджетом «Текст»** с ручкой.
- В ячейке несколько виджетов друг под другом.
- **Перенос**: палец — долгое нажатие и вести; мышь — за ручку. В другую ячейку, между рядами,
  порядок внутри ячейки. Опустевшая ячейка остаётся.
- **Пустая ячейка — ячейка** (заказчик 2026-10-18, вечер): уходит в сообщении, её фон виден, ряд из
  одних пустых ячеек тоже уходит. Прежнее «пустые при отправке не уходят» отменено.
- **Ряд создаётся с числом строк и столбцов**: «Разметка → Ряд» спрашивает строки (до 20) и столбцы
  (до 7). Дальше — «+Столбец», «−Столбец», «+Строка», «−Строка»; новые и убранные столбцы делят
  ширину поровну.
- **Ширина столбца — передвижением рамки** между столбцами, ступенями по 5 % (заказчик 2026-10-18:
  «Проще. Создаём ячейки одинакового размера, перегородка перераспределяет между соседними»): ряд
  создаётся с равными столбцами; рамка меняет только два соседних столбца, их сумма та же. Наименьшая и
  наибольшая доля зависят от числа столбцов: 2 — 20…80 %, 3 и 4 — от 15 %, 5–7 — от 14 %; рамку не
  сдвинуть уже, чем нужно содержимому (картинке, карточке). Пункта «Ширина» в «Стиле» нет; ширину в
  JSON стиля не задать.
- **Слияние в оба направления**: «С левой» и «С верхней» — выбранная ячейка сливается с соседней,
  её содержимое переходит в ту; слитое всегда прямоугольник (захватывает нужные ячейки само).
  «Разъедин.» — снова отдельные ячейки, содержимое остаётся в первой.
- **Первая строка ничем не отличается от других**: вид задаёт стиль редактора.
- **Ряд всегда на одной строке — у получателя тоже** (заказчик 2026-10-18, вечер): столбиком он не
  встаёт, горизонтальной прокрутки нет (В25). **Не помещается — не сохраняется**: ряд в редакторе
  красный, отправить нельзя, пока рамку не раздвинут. Проверка — для самого узкого пузыря (260 dp
  содержимого): текстовой ячейке нужно 35 dp («99» шрифтом 22, РС-В10), картинке 96, карточке
  ссылки и вставленному 140, облаку, месту и контакту 120, эмоджи 48.
- **У каждого виджета — строго определённое место и минимальный размер.** Картинка может быть
  хоть с ноготь — отправитель это и так видит, — но **невидимого содержимого быть не должно**:
  минимумы есть у всего. Числа минимумов — предложение РС4 (например: картинка не уже 48 dp,
  кнопка-ссылка — 120 dp, карта и контакт — 160 dp); **числа ставятся на пробах** (2026-10-18,
  РС-В11).
- *Прежнее, до 2026-10-18 (вечер), — для таблиц быстрого оформления в старых сообщениях:*
  **Таблица — где угодно, в том числе в ячейке ряда, если в её ячейку помещается число «99»**
  (2026-10-18, В26). **Проверяется для самого узкого телефона (пузырь около 360 dp) и шрифта
  сообщений 22** — самого крупного в «Шрифты и размеры» (2026-10-18, РС-В10): влезло там — влезет у
  любого получателя. **Считается от самого пузыря: он не шире 290 dp, содержимое — 260 dp; во всю
  ширину помещается 7 столбцов** (360 dp — ширина телефона; подтверждено заказчиком 2026-10-18). Не помещается — запрет: в редакторе таблица (виджет) **красная** и просьба
  изменить; отправить такое нельзя.
- **Текст в ячейке таблицы переносится на новую строку без правил переноса** — где кончилась
  ширина, там и разрыв, хоть посреди слова (2026-10-18, В26).
- **Пределы**: до 7 столбцов и до 20 строк в ряду (заказчик 2026-10-18, вечер); до 20 рядов в
  сообщении.

### 10.4. Виджеты

| Виджет | Что |
|---|---|
| Текст | быстрое оформление внутри |
| Картинка | §3 |
| Ссылка | §4 |
| Облако | кнопка-ссылка на файл вне телефона; в группе и канале файлы — только так |
| Карта | координаты, кнопки «Яндекс Карты», «Google Карты»; картинку карты не рисуем |
| Контакт | карточка человека |
| Ответ | `@Ник` (§7) |
| Из подборки | вставленное сообщение: галочка «имя владельца»; «полностью» или «обрезать» — по высоте соседа в ряду, нет соседа — три строки |
| Эмоджи | крупный, в том числе анимированный |
| Видео | видеоссылка: рамка или картинка, название или без него, **описание обязательно** — заглавие и привязка меток (2026-10-23, [ПЛАН-(ВМ)](ПЛАН-(ВМ)-ВОСПРОИЗВЕДЕНИЯ-МЕДИА.md) §3.6) |
| Метки | к виджету «Видео» или «Аудио» этого сообщения: время и текст, до 30, одна на видео или аудио, без него убираются сами (2026-10-23, там же) |
| Аудио | каждый файл — свой виджет; описание обязательно (вставка списком из буфера — имя файла); только прямая ссылка на файл, без сервисов и потоков; играет в сообщении, без нового окна, и дальше — после ухода из переписки; следующее «Аудио» сообщения — само; картинки — средствами редактора; вид — в обсуждении (2026-10-23, там же §3.7) |
| Поток | прямой эфир m3u8, только звук (радио): играет в сообщении по правилам «Аудио», после паузы — с эфира; m3u8-запись — «Аудио», m3u8 с видео — «Видео» (2026-10-23, [ПЛАН-(ВМ)](ПЛАН-(ВМ)-ВОСПРОИЗВЕДЕНИЯ-МЕДИА.md) §3.8) |

Виджетов «Видео», «Аудио», «Поток» и «Метки» в одном сообщении — **не больше 30** вместе.

Видео, Метки, Аудио и Поток вставляются кнопкой **«Виджет»** раздела «Вставка».

**Не виджеты:** разделитель — стиль ряда (и `---`); подкладка — только в конце (§11.3); файлы,
альбомы, голос, аудио, видео — вне пузыря (видео и аудио **по ссылке** — виджет «Видео»).

## 11. Меню сообщения, подборка, подкладка, переходы (решено 2026-10-18)

### 11.1. Меню сообщения

- **Нажатие — меню:** Ответить · Поделиться · Скопировать текст · Добавить в Подборку сообщений ·
  Перенести себе. Это у **отправленного**; у неотправленного и ждущего нажатие по-прежнему
  открывает `FailedMessageSheet` ([ПЛАН-(Ч)](ПЛАН-(Ч)-ЧАТА.md) Ч9, Ч10).
- **У своего сообщения** вместо «Ответить» — **одна кнопка с выбором: Изменить · Удалить у себя ·
  Удалить у всех** (заказчик 2026-10-18: «самому себе не отвечаем»; «Изменить — одна кнопка с
  выбором для своих сообщений»). Дальше те же: Поделиться · Скопировать текст · Добавить в Подборку
  сообщений · Перенести себе. Меню — **сразу со всеми пунктами** (заказчик 2026-10-18). «Изменить» —
  правка по §8; «Удалить у себя» — только на устройстве; «Удалить у всех» — по §8.
- «Перенести себе» — перенос по [ПЛАН-(К)](ПЛАН-(К)-КАНАЛОВ.md) К2: ссылка без содержимого, уровни
  3 и −1 не выносятся.
- *Прежнее, до 2026-10-19:* долгое нажатие — выделение части сообщения и «Скопировать».
- **«Скопировать текст» в меню — окно: выделить часть или скопировать всё** (заказчик 2026-10-19:
  туда переехало прежнее долгое нажатие).
- **Долгое нажатие — выбор нескольких** (заказчик 2026-10-19): галочка у своих слева, у чужих
  справа; пока выбрано хоть одно, обычное нажатие ставит и снимает галочку (у фото тоже). Внизу на
  месте строки ввода — «Выбрано: N», «В Подборку», «Скопировать» (тексты подряд), «Переслать» (выбор
  переписки — каждое уходит там отдельным сообщением: знаками, документом редактора, фото файлом;
  файлы вне пузыря не пересылаются), «Удалить» — выбор «у себя» или «у всех» (у всех — только если
  выбраны свои отправленные; вопрос один на все), «✕» — выйти. ПК: меню — правой кнопкой.

- **Файлы и фото** (заказчик 2026-10-22): в меню сообщения и в полосе выбора вместо «Скопировать текст» —
  «Сохранить как»; несколько файлов — группой в выбранную папку. Выбраны и файлы, и сообщения с текстом —
  есть оба пункта: «Скопировать» берёт только сообщения с текстом, «Сохранить» — только файлы и фото.
- **«Скопировать текст» — целиком** (заказчик 2026-10-22): блоки по порядку; ссылка со своим текстом — «текст
  адрес» одной строкой, без текста или карточкой — только адрес (так же ссылка в абзаце и облако); вставленное
  из подборки и подкладка — целиком, строкой автор (если показан), ниже текст; вставка во вставке не
  разворачивается; недоступное — «[сообщение недоступно]». Ответ, картинки, файлы в копию не идут.

### 11.2. Подборка сообщений

- **Ссылки на сообщения**, а не копии; удалил автор — в подборке «удалено».
- **Своя у верхнего уровня**: у сообщества; нет его — у группы или канала; у личной переписки и
  личной группы — только своя (2026-10-18, В27). **Вставить — только в пределах уровня.** Вне
  уровня — только «Перенести себе» (ADR-0019 п. 7).
- В редакторе — кнопка «Подборка» (раздел «Вставка»): окно на месте клавиатуры, выбрать,
  «Вставить», «Очистить подборку». Вставленное остаётся в подборке.
- **С 2026-10-21 подборка — это указатели** ([ПЛАН-(УК)](ПЛАН-(УК)-УКАЗАТЕЛЕЙ.md), ADR-0051): у личной
  переписки — своя у каждой (редактор личной вставляет из всех личных); пункт меню сообщения —
  «В указатели»; смотрят, раскладывают по разделам, убирают и переходят — во вкладке «Указатели» окна
  «Общение». Предел — 100 на уровень.
- Живёт **на устройстве**, на сервер не уходит, до 20 ссылок на уровень (предложение). Поэтому
  подборка сообщества — не его содержимое на сервере и правило [ПЛАН-(СО)](ПЛАН-(СО)-СООБЩЕСТВ.md)
  §3 («своё содержимое — ровно одно») не задевает.

### 11.3. Подкладка

- Кнопка «Подкладка» (раздел «Вставка»), источник — подборка.
- **Показ:** число строк и «Продолжить чтение»; галочка «автор первым».
- **Ставится так же, как виджет** — на строку курсора (заказчик 2026-10-21; прежде — только в конец
  сообщения); несколько — одна под другой или **списком**. В ряд не встаёт.
- **У получателя**: часть сообщения-источника **приклеена ниже, без пузыря**, форматирование —
  как у источника; автор первым, если указан; ниже «Продолжить чтение».
- **Источник начинается с ряда или таблицы** — показывается целиком только он и «Продолжить
  чтение»; число строк не действует.
- Подкладка — ссылка: удалил автор — исчезла, сузил круг — сузилась.

**Доступ к подложенному — один механизм везде** (заказчик 2026-10-18, Н9). Отдельной проверки
ссылок нет:

- клиент просит сообщение **по номеру**; сервер применяет обычное правило выдачи (`уровень ≤ право
  читателя`) и отдаёт **либо сообщение, либо служебный ответ «уровень N — недоступно»**;
- клиент рисует «Недоступно — что сделать» (ниже);
- подложенное судится **по своему уровню**, а не по уровню сообщения, в которое его вставили;
- **так же — везде**, где показывается чужое сообщение по ссылке: подкладка, вставленное из
  подборки, ответ, «Перенести себе». В ленте страницы перенесённое сейчас **молча исчезает**
  (`ListFeed`), станет строкой «Недоступно»;
- уже показанное и лежащее на устройстве — с пометкой «недоступно», при следующем запросе
  заменяется ответом сервера (ADR-0019 §7: кеш — не копия).

**Продолжение другого уровня — та же подкладка** (заказчик 2026-10-18, РС-В3). Прежний замысел
«одно сообщение — две записи, часть А уровня 1 и часть Б уровня 2» (обсуждение 2026-10-16, кода
не было) заменён:

- **Одна запись — один уровень.** Закрытая часть — **отдельное сообщение** своего уровня,
  подложенное в конец открытого. Сервер не знает пар: каждую запись отдаёт по её уровню.
- **Недоступно читателю** — на месте подкладки строка «**Недоступно** — что сделать» и ниже
  «Продолжить чтение».
- **«Что сделать» составляет клиент читателя** по его положению, а не автор: не вступил —
  «Вступить в группу», нужен уровень 3 — «Попросить доступ», вне сообщества — «Подписаться».
- **Пометка «только продолжение»**: такое сообщение в ленте само по себе не показывается — только
  через подкладку и прямой переход. Пометка открытая, значит колонка на сервере (ADR-0011 §5).
- **Порядок отправки**: сначала продолжение, потом основное со ссылкой на него — иначе ссылка в
  пустоту.
- −1 и 3 подкладываются в пределах своего уровня (§11.2) — это не вынос наружу (ADR-0019 п. 7).
- Так же лягут будущие публичные сообщения с двойным содержанием.

### 11.4. «Продолжить чтение» и переходы

- **«Продолжить чтение» — переход к самому сообщению**; оно коротко подсвечено (2026-10-18, В34).
- **Появляется «назад»** — справа, над кнопкой «вниз»; значительный переход — «назад» возвращает к
  исходному сообщению.
- **Переходов несколько — помнятся все**; после «назад» появляется **«вперёд»**. Снизу вверх:
  «вниз», «вперёд», «назад».
- Предложения: значительный — исходное ушло с экрана; механизм общий для ответа, подборки,
  подкладки, поиска; переход в другую группу сообщества открывает её окно, «назад» возвращает;
  долгое нажатие на «назад» убирает цепочку.
- **Это местная история прокрутки внутри переписки, а не «назад» приложения**
  ([ПЛАН-(ПЖ)](ПЛАН-(ПЖ)-ПОЛОЖЕНИЯ.md): стека переходов у приложения нет, и этот его не заводит).
  Сохранение между окнами и после перезапуска — [ПЛАН-(МП)](ПЛАН-(МП)-СОХРАНЕНИЯ-МЕСТОПОЛОЖЕНИЯ.md).

### 11.5. Поделиться наружу

**Уходит всё, что можно** (текст, картинки); **оформление сбрасывается до текста** с тем
оформлением, которое понимают другие приложения (2026-10-18, Н6).

## 12. Уведомление, список чатов, поиск

- **Текст строки в списке чатов и поиска — из первого узла текста**, без знаков; у открытых
  уровней — его же сервер берёт для поиска (2026-10-18, Н3). Нет текста — «Фото», «Ссылка: домен»,
  «Файл».
- **В уведомлении текста нет никогда** — [ADR-0029
  §5](../doc/adr/0029-notifications-and-channel-ownership.md) остаётся в силе (2026-10-18, РС-В6).
- Поиск зашифрованного — только на устройстве, по узлам.

## 13. Палитра и тема

**Таблица «имя цвета → светлая тема, тёмная тема»** заводится (2026-10-18, Н8); в разметке —
только имена.

## 14. Нагрузка

- **Сервер:** байты мимо бэкенда (presigned, уже так); ссылки пачкой `POST /media/urls` до 100 id
  (новое, API расширяется); квота загрузок на человека; дедупликации приватного нет.
- **Клиент:** только видимое плюс экран запаса, ушедшее с экрана отменяется; раскодирование под
  размер места; кеш в памяти по байтам; на диске — только зашифрованное; 3–4 загрузки разом;
  кеш рендера оформленных сообщений (ADR-0011 §10).
- **Проверка после постройки:** сообщение 20 рядов × 4 ячейки с картинками на Redmi — разбор и
  первая отрисовка, прокрутка ленты без пропуска кадров. Не уложились — урезаем пределы, а не
  кнопки.
