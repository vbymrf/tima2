# Заглушки интерфейса

**Что это.** Список мест, где экран показывает не то, что обещает макет: пусто, «пока
нет», выдуманное имя вместо настоящего. У каждой заглушки названо, **что должно быть** и
**чем она держится** — иначе через месяц заглушка неотличима от готового.

**Как этим пользоваться.** Нарисовал заглушку — записал сюда в тот же час. Убрал —
вычеркнул строкой «снята» с датой. Файл дописывается, а не переписывается: история
заглушек показывает, где интерфейс отстаёт от макета дольше всего.

**Чего здесь нет.** Того, что просто не начато: ненарисованный экран — не заглушка, а
работа из дорожной карты. Заглушка — это когда человек **видит** нечто и может принять
его за настоящее.

## Действующие

### 1. Присутствие: «онлайн», «была 5 минут назад»

| | |
|---|---|
| Где | вкладка «Контакты» (`02-phone-home.md §Вкладка «Контакты»`), шапка личной переписки |
| Что сейчас | не показывается ничего |
| Что должно быть | состояние словами: «в сети», «была 5 минут назад», «была вчера», «нет в сети» |
| Чем держится | **сервер не отдаёт присутствие**: `internal/api/ws.go` — «typing/receipt/presence — следующие итерации» |
| Решение по смыслу | принято в А3: маркер несёт время, видят все, выключается взаимно |

Рисовать «онлайн» сейчас нельзя: это выдуманное состояние живого человека. Ошибка такого
рода не выглядит ошибкой — она выглядит работающим интерфейсом.

### 2. Вкладка «Звонки»

| | |
|---|---|
| Где | окно «Телефон», третья вкладка |
| Что сейчас | вкладки нет вовсе |
| Что должно быть | список вызовов, кнопки «позвонить» и «видео» у контакта |
| Чем держится | LiveKit-клиента на клиенте нет (К7); сервер токены выдаёт, звонить нечем |

Когда вкладка появится, до К7 она обязана быть **честно пустой** — «звонков пока нет», —
а не показывать придуманные вызовы.

### 3. Окна 2–7 и переключатель между ними

| | |
|---|---|
| Где | оболочка приложения (`01-app-shell.md`) |
| Что сейчас | окно одно — «Телефон»; переключателя нет |
| Что должно быть | семь окон и рейка: лента, медиа-лента, соц, личная страница, два блогерских |
| Чем держится | социального слоя на сервере нет (С4–С6), а он упирается в решения заказчика |

Когда рейка появится, заглушки окон обязаны говорить «здесь будет лента», а не показывать
выдуманные записи: нарисованные данные однажды уезжают в сборку и принимаются за
работающее.

### 4. Имя участника группы = его идентификатор

| | |
|---|---|
| Где | `ЭкранСостава` — список участников |
| Что сейчас | вместо имени показан `user_id` |
| Что должно быть | имя человека, как в контактах |
| Чем держится | состав приходит идентификаторами; имён на всех участников разом сервер не отдаёт |

### 5. Название группы «Группа» у пришедшего сообщения

| | |
|---|---|
| Где | список переписок, если группа впервые встретилась во входящем сообщении |
| Что сейчас | строка заводится с именем `Группа` |
| Что должно быть | настоящее название с сервера |
| Чем держится | приёмник не ходит за составом группы ради имени; нужна сверка `SyncGroupChats` |
| Код | `shared/Приёмник.kt`, `принятьГрупповое` |

Это самая коварная из списка: она выглядит как настоящее имя и не отличается от него на
экране. Человек с двумя такими группами увидит две строки «Группа».

### 6. Имя автора реплики в группе: «Участник»

| | |
|---|---|
| Где | окно переписки группы |
| Что сейчас | «Участник», если имя не найдено |
| Что должно быть | имя человека |
| Чем держится | имена подтягиваются по одному через справочник; пока их нет — подставляется общее слово |

Это **осознанная** заглушка, а не недоделка: показать чужое имя хуже, чем никакого —
человек решит, что писал не тот, кто писал.
