## Открытые

## Закрытые

### И-1. Вход по фразе отвечал «код неверен или просрочен»

Нашёл заказчик 2026-08-25. Код одноразовый: `/auth/verify` гасит его первым обращением, а
клиент начинал с проверки кода каждый раз — второй шаг приходил с погашенным. Вход по
фразе не мог сработать никогда, ни через секунду, ни через час.

Починено `9eeeb4c`: второй шаг идёт с `registration_token`.

### И-2. Из ввода фразы не было выхода

Нашёл заказчик 2026-08-24. Оставались «вспомнить фразу» и «начать заново», второе стирает
личность — то есть опечатка в номере стоила бы аккаунта.

Починено `7cab1e9`: кнопка «Другой номер», номер сохраняется.

### И-3. «+7» выглядел введённым, а был подсказкой

Нашёл заказчик 2026-08-24. Номер уходил без кода страны.

Починено `489fa33`: код страны отдельным полем. Тесты попутно поймали вторую беду — первая
редакция склейки ломала вставку номера из буфера.
