# Вопросы к заказчику по интерфейсу

**Что это.** Развилки, где макет допускает больше одного прочтения, а цена прочтений
разная. Только про интерфейс: вопросы про сервер, крипту и хранение живут в
[ВОПРОСЫ-К-ЗАКАЗЧИКУ.md](../ВОПРОСЫ-К-ЗАКАЗЧИКУ.md).

**Правило то же, что у общего файла.** У каждого вопроса названы варианты и **цена
каждого**; у каждого ответа обязателен блок «что это меняет» — экраны, состояния, тексты,
поведение. Решение без названных следствий проверить нечем.

**Область запирает только себя** (`ПОРЯДОК-РАБОТ §2`): неотвеченный вопрос про вкладку
«Звонки» не мешает делать «Контакты».

## И1. Что показывать вместо присутствия, пока сервер его не отдаёт

**Что измерено.** Сервер присутствие не отдаёт: `internal/api/ws.go` — «typing/receipt/
presence — следующие итерации». Макет рисует «онлайн» и «была 5 минут назад» у каждого
контакта и в шапке переписки.

**Почему вопрос.** Строка присутствия занимает место в раскладке. Если её сейчас нет, а
потом она появится, список контактов подпрыгнет и станет другим по высоте строки.

| Решение | Цена |
|---|---|
| Не показывать ничего | Список плотнее, но при появлении присутствия раскладка меняется у всех |
| Держать место пустым | Раскладка не изменится, но пустое место под именем выглядит как недогруженное |
| Показать «неизвестно» | Честно и место занято, но у каждого контакта висит слово, которое ничего не значит |

**Моё предложение:** не показывать ничего. Присутствие придёт вместе с серверным
механизмом, и тогда же переснимутся снимки — это одна работа, а не две.

## И2. Вкладка «Звонки» до появления звонков

**Что измерено.** LiveKit-клиента нет (К7). Сервер токены выдаёт, звонить нечем.

| Решение | Цена |
|---|---|
| Вкладки нет вовсе до К7 | Человек не видит того, чего нет. Но при появлении вкладок их станет три вместо двух — привычка ломается |
| Вкладка есть и честно пуста | Видно, что будет; рейка сразу в финальном виде. Но пустая вкладка раздражает, если в неё зашли |

**Моё предложение:** второе, с текстом «звонки появятся позже» — рейка вкладок делается
один раз, и её состав меняться не должен.

## И3. Имена участников в составе группы

**Что измерено.** Состав приходит идентификаторами; имён на всех участников разом сервер
не отдаёт — только поиск по номеру и имя по одному пользователю.

| Решение | Цена |
|---|---|
| Спрашивать имя каждого по очереди | Список из ста человек даёт сто запросов при каждом открытии |
| Показывать идентификатор | Работает всегда, но человек не узнаёт соседа по строке `u-7f3a…` |
| Ручка «имена по списку идентификаторов» на сервере | Правильно и дёшево в работе, но это правка API и решение по нагрузке |

**Моё предложение:** третье. Пока её нет — показывать имя для тех, кто уже в контактах, а
для остальных идентификатор.
