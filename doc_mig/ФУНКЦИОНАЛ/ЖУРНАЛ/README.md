# Журнал тестирования

Когда и как проверяли функции из ведомостей. Решение заказчика 2026-09-29.

Две папки — по ведомости: [ТЕЛЕФОН/](ТЕЛЕФОН/README.md) и [ПК/](ПК/README.md). Коды в обеих
одинаковы с журналом приложения, платформу видно по папке.

## Имя файла

**Коды проверенных функций через `+`, пробел, дата:**

```
call.speaker+call.camera.switch 2026-09-29.md
```

- Кодов много — в имени общее начало: `call 2026-09-29.md` значит «всё окно 0».
  Иначе путь упрётся в ограничение Windows на длину.
- Два прогона одного дня — к дате добавляется время: `call 2026-09-29 1430.md`.
- Код в имени — ради поиска: все проверки функции находятся поиском файла по её коду.
  Поэтому даты последней проверки в ведомости нет — её источник здесь.

## Внутри

Первым — всегда версия и чем тестировали:

```markdown
# call.speaker+call.camera.switch 2026-09-29

**Версия:** 2.0.87-dev-v2, вершина `7e5b7c90`
**Чем:** Redmi 23129RN51X (Android 16), realme RMX3269 (Android 11); стенд — сервер 0.9.x;
Maestro `maestro/call-window.yaml` · вручную · автотесты `:core:core-call:jvmTest`

| Код | Что проверяли | Как | Итог |
|---|---|---|---|
| `call.speaker` | переключение громкая ↔ разговорный | вручную, звонок Redmi → realme | прошло |
| `call.camera.switch` | передняя ↔ задняя, при выключенной камере | Maestro | не прошло: … |
```

**Итог** — `прошло`, `не прошло` или `частично`, и для двух последних — словами, что
именно. Были отчёты о проблеме или прогоны стенда — ссылки на них в той же строке.
