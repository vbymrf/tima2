# План: выход из аккаунта, вход по QR на вошедшем устройстве, обновление токена без петли

Заведён 2026-09-30 по решению заказчика (1а — всё вместе). Этапы А1…А9.

**Статус 2026-09-30: А1–А8 сделаны** (`9a6afc83`, `7e002967`), А9 — проверено тестами, на ПК и Samsung живьём; не проверены живьём А2 на сбитых часах и вход ПК по QR (нужен телефон заказчика). Отчёт — [отчёты/2026-09-30-выход-из-аккаунта.md](отчёты/2026-09-30-выход-из-аккаунта.md), беда — [БЕДЫ/2026-09-30-пк-отключён-токен-часы.md](БЕДЫ/2026-09-30-пк-отключён-токен-часы.md).

## Почему

**Случай 2026-09-30, ПК.** В «Настройки → Фраза и устройства» висело «Смотрим…» и больше
ничего. Журнал ПК (`%LOCALAPPDATA%\TIMA\logs\2026-09-30.txt`) показал:

1. **Часы машины спешат на 3 мин 10 с** против сервера (ПК 13:51:19 UTC, сервер 13:48:09,
   Samsung 13:48:49); служба времени Windows не запущена.
2. Токен доступа живёт сутки (`auth.AccessTTL`), обновляется **подписью ключа устройства**
   (`POST /api/v1/auth/device/token`, `server/internal/api/device_token.go`). Подпись несёт
   метку времени, и сервер принимает её при расхождении часов **не больше 2 минут**
   (`DeviceTokenWindow`). Всё дальше — `401 stale_signature`, «подпись просрочена —
   проверьте часы устройства». **Устройство никто не отключал** — ему не дают новый токен.
3. **Петля:** обновление токена идёт через тот же сетевой клиент, где на `401` стоит
   «обнови и повтори» (`HttpClientFactory.kt`, плагин «ОбновлениеТокена»). Отказ на
   обновление запускает новое обновление — **12 231 попытка** за ~17 минут работы,
   24 тысячи строк журнала. Код отказа сервера (`stale_signature`) клиент не читает.
4. Список устройств ждёт токен, которого не будет, — вечное «Смотрим…».
5. **Выйти из аккаунта на устройстве нельзя**, а экран входа с «Подключить к аккаунту»
   (QR) виден только на устройстве без аккаунта. Войти по QR на вошедшем устройстве — никак.

## Решения заказчика 2026-09-30

| # | Решение |
|---|---|
| 1а | всё одним планом: выход, возврат, отключённое устройство, обновление без петли, предел у экрана устройств |
| 1в | прежний аккаунт при выходе **откладывается, а не стирается**; вернуться — кнопкой |
| 3а | и на ПК, и на телефоне |
| — | последнее устройство аккаунта — только предупреждение: вход по номеру, SMS и фразе у нас есть |

Сервер не меняется (решение 5 `Plan.md §0.0`: API не трогаем, пока v2 не заработает) — время
сервера берётся из заголовка `Date` любого ответа.

## Этапы

| # | Что | Готово, когда |
|---|---|---|
| **А1** | **Обновление токена без петли.** Запрос обновления идёт мимо плагина «обнови и повтори». Одно обновление на всё приложение: остальные запросы ждут его, а не запускают своё. После отказа — пауза с ростом (30 с, 1 мин, 5 мин), без шквала. Код отказа сервера (`stale_signature`, `device_revoked`, `bad_signature`) — в журнал | на ПК с отказом — единицы попыток в минуту, а не сотни в секунду |
| **А2** | **Часы.** Клиент хранит поправку «сервер минус устройство» по заголовку `Date` ответов и подписывает обновление временем сервера. На `stale_signature` — переподписать с поправкой один раз. Расхождение больше минуты — строка журнала и событие «часы устройства спешат/отстают на N мин» | ПК с часами +3 мин получает токен, всё работает |
| **А3** | **Отключённое устройство** (`device_revoked`). Запросы под токеном останавливаются; вместо вечных `401` — экран «Это устройство отключено от аккаунта» с кнопкой «Войти снова» → А4 без вопроса про прежний аккаунт | отзыв с телефона → на ПК экран «отключено», не петля |
| **А4** | **Кнопка «Выйти из аккаунта на этом устройстве»** в «Фраза и устройства». Вопрос-подтверждение: «Это устройство выйдет из аккаунта <имя>. Аккаунт будет отложен — вернуться можно кнопкой на экране входа». Последнее устройство аккаунта — добавить: «или по номеру, SMS и фразе». На сервере устройство **не отзывается** (1в: вернуться теми же ключами) | после выхода — экран входа |
| **А5** | **Отложить аккаунт.** ПК: папка данных `%LOCALAPPDATA%\TIMA` (база, `secrets`) → `TIMA.old-<дата-время>`. Телефон: база и файлы — в отдельную папку внутри приложения; ключи Keystore — привязать к аккаунту (имя ключа с `device_id`), способ выяснить при работе и записать сюда. Затем перезапуск в экран входа | на обоих — экран входа, прежние данные на месте в отложенном |
| **А6** | **«Вернуть прежний аккаунт»** на экране входа, когда отложенный есть (несколько — списком с именем и номером). Вернуть — обратная перестановка и перезапуск | вернулся тот же аккаунт с перепиской |
| **А7** | **Экран устройств с пределом.** Нет ответа за 20 с — «Список не пришёл» и «Повторить», а не вечное «Смотрим…» | при отказе сети — понятный отказ |
| **А8** | **Журнал** — в реестр `ЖУРНАЛ-И-ОТЛАДКА/РЕЕСТР.md`: причина отказа обновления (`код=` сервера), «часы расходятся с сервером на N с», «выход из аккаунта — отложен», «возврат аккаунта», «устройство отключено» | строки видны в журнале при каждом случае |
| **А9** | **Проверка:** ПК с часами +3 мин (А2); отзыв устройства с телефона (А3); выход и возврат на ПК и на телефоне (А4…А6); вход по QR после выхода | всё по пунктам, отчёт с хешем |

## Сейчас, до правок

ПК можно вернуть к работе, **синхронизировав часы машины** (служба времени Windows) —
это настройка машины, делать по слову заказчика. Войти на ПК по QR без правок можно,
переименовав `%LOCALAPPDATA%\TIMA` при закрытом клиенте.
