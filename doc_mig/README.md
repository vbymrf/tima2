### Интерфейс — отдельной папкой

[`ИНТЕРФЕЙС/`](ИНТЕРФЕЙС/) — четыре файла про состояние работы над экранами, а не про
задуманный продукт. Разница принципиальна: `doc/` описывает, каким приложение должно
быть, и на вопрос «что сегодня умеет сборка» не отвечает вовсе.

Состав и правила — [ИНТЕРФЕЙС/README.md](ИНТЕРФЕЙС/README.md). Коротко: сквозные файлы
(заглушки, связи, вопросы, ошибки) лежат в корне папки, функционал дробится по окнам.

Заведено 2026-08-25 по решению заказчика. Причина названа им же: существующая
документация не описывает **текущие задачи**, и мануал в `doc/` (кроме макетов и
`интерфейс.md`) в этой работе скорее мешает, чем помогает.

## 2. Правило, из которого всё вытекает

Документация разошлась с кодом не потому, что её плохо писали, а потому что
**у документов не было источника, к которому их можно пересверить.** Их писали
вперёд кода — и когда код пошёл другим путём, узнать об этом было неоткуда.

Один документ в проекте от этого свободен — [doc/интерфейс.md](../doc/интерфейс.md).
Он здоров ровно потому, что первой строкой называет источник: «источник — только
Layout-UI-light», и этот источник лежит рядом.

Отсюда правило на всё дальнейшее:

> **Документ обязан называть источник своей правды и дату сверки с ним.**
> Источник должен быть проверяемым: код, миграции, тест-векторы, макет.
> Документ без источника — это мнение, и его место в решении (ADR), а не в
> описании системы.

Следствие: **«удалить» здесь означает «переписать из источника», а не «стереть».**
Документ, описывающий факт, застывший в данных — деривации ключей, метки HKDF,
канонические байты, 27 применённых миграций, — переписать «заново» нельзя, его
можно только вычитать из кода. Удалить такой документ значит потерять карту, а не
ограничение: ограничение останется в отправленных данных.

> **Очерёдность — не здесь.** Что делать следующим и по какому правилу —
> [ПОРЯДОК-РАБОТ.md](ПОРЯДОК-РАБОТ.md). Здесь только зависимости между дорожками.

## 3. Две дорожки и их зависимости

```
Д. Документация   Д1 инвентарь ─→ Д2 doc_UI ─→ Д3 пересборка из кода ─→ Д4 правило
                                      │
                                      │ 20 файлов §12 — задание на рисование
                                      ▼
К. Клиент  К1 каркас ─→ К2 крипто KMP ─→ К3 сеть/БД/Outbox ─→ К4 срез «текст» ─→
           К5 auth и интерфейс по макету ─→ К6 группы и файлы ─→ К7 звонки и
           обновления ─→ К8 ферма, приёмка, удаление v1
```

**Дорожки «Интерфейс» больше нет — она внутри К5.** Так вышло из решения строить
клиент заново: структура модулей есть с первого коммита, поэтому экраны сразу
пишутся туда, куда нужно. Прежний запрет «не начинать экраны до К1» отменён вместе
с миграцией — он существовал ровно потому, что экран мог попасть в `App.kt`.

Жёстких зависимостей осталось две:

1. **К5 после К4.** Экраны рисуются на работающем сквозном пути, а не поверх
   заглушек: иначе первый же настоящий обрыв связи переделывает половину состояний.
2. **Д2 перед К5 в части 20 файлов.** В них лежит спецификация экранов, которых в
   макете нет (регистрация, восстановление, редактор, мастера создания) — и К5 без
   них рисовать нечего.

**Дорожка Д в остальном не блокирует К.** Полная пересборка `doc/` — недели, и она
не должна съесть время, отведённое на клиент.

## 4. Дорожка Д — документация

Объём: `doc/` вне макета и `doc_UI` — **41 файл, 4912 строк**. Плюс `doc_UI` —
**36 файлов, 3314 строк**. Плюс `интерфейс.md` — 1247 строк, здоров.

### Д1 — инвентарь с вердиктом

Для каждого из 41 файла: источник правды, вердикт (**подтверждён кодом /
расходится / непроверяем**), дата сверки. Механическая работа: источники
машиночитаемы.

| Что описывает документ | Источник сверки |
|---|---|
| модель данных | `server/migrations/0001…0027` |
| поверхность API | роуты `server/internal/api` |
| крипто-протокол, конверт | `CanonicalBytes.kt` ↔ `canonical.go` + `schema/test-vectors` |
| сроки, удаление, escrow | таблица `retention_policy`, воркеры, реестр `escrow_keys` |
| интерфейс | макет (уже сделано) |
| замысел, продукт | ничего. **Источник — заказчик**, и это значит «переписать», а не «сверить» |

Вход в Д1 — галочки [arhiv/ПЛАН-РЕФАКТОРИНГА.md](arhiv/ПЛАН-РЕФАКТОРИНГА.md): они
перечисляют, что **заявлено** сделанным на сервере, и это готовый список
утверждений для проверки.

**Выход:** таблица из 41 строки с вердиктами. Ни один документ после этого не
читается без вердикта.

### Д2 — снять doc_UI

`интерфейс.md` объявил себя заменой `doc_UI` (§13), и §13 сопоставляет **все 36
файлов**. Но замена неполная, и это главное:

| Группа | Файлов | Что с ними |
|---|---|---|
| Впитаны в `интерфейс.md` целиком | **16** | удалить, ссылки перевести на §-разделы по таблице §13 |
| Замена целиком или частично — §12 | **20** | **§12 их только называет, текста не содержит.** Удалять нельзя |

§12 так и написан: «без него замена `doc_UI` тихо потеряет треть объёма». Это
регистрация и вход, восстановление доступа, привязка по QR, редактор контента,
мастер создания, страница сообщества, глобальный поиск, пересылка и репост, QR и
инвайты, уведомления, просмотр историй, экран коллекции, карточка атрибута.

Порядок:

- **Д2а.** 20 файлов с неполной заменой → `doc_mig/непокрытое-макетом/`. Это не
  архив, а **вход в работу**: по ним рисуются недостающие экраны макета (У2/У4), и
  только после этого их содержание переезжает в `интерфейс.md` и они исчезают.
- **Д2б.** 16 впитанных — удалить.
- **Д2в.** Переписать ссылки: **82 ссылки в 23 файлах `doc/`** плюс одна в
  `client/.../App.kt`. Работа механическая, потому что §13 — это готовая таблица
  переадресации.
- **Д2г.** Три ADR (`0001`, `0006`, `0007`) ссылаются на `doc_UI`. **Правка ADR
  разрешена только в ссылках**, содержание решения не трогаем: ADR — журнал, и
  переписанный журнал перестаёт быть доказательством.

**Выход:** `doc/doc_UI/` нет; ни одной битой ссылки; 20 файлов лежат в
`непокрытое-макетом/` как задание на рисование.

### Д3 — пересобрать фактовые документы из кода

**Два расхождения найдены и подтверждены — правятся первыми, до общего инвентаря:**

| Документ | Что не так | Чем стало |
|---|---|---|
| `02-architecture/module-boundaries.md` §5 | описывает содержимое постов как `text + entities` со смещениями, в стиле Telegram | отменено [ADR-0011](../doc/adr/0011-message-content-model.md): `nodes` + `markup` по идентификаторам узлов. Пока не исправлено — редактор проектируется по отменённой модели |
| `02-architecture/tech-stack.md` | обещает «SQLite FTS5 для локального поиска» | не действует: принят вариант A шифрования покоя, поиск — расшифровкой на лету ([Plan.md](Plan.md) §3.4.3) |

Дальше — по тому, что нужно раньше:

1. `05-api` — нужна дорожке К: интерфейс вызывает API.
2. `02-architecture/data-model.md` — из миграций.
3. `03-security` — из крипто-кода и тест-векторов.
4. `04-data`, `06-realtime`, `07-deployment` — по остаточному принципу.

`01-product` (концепция, дорожная карта, разделы) — **переписать, а не сверять**:
у них источник в голове заказчика, и старый текст ценности не имеет.

**ADR не переписываются вовсе.** Устаревшее решение перекрывается новым со
ссылкой «Superseded by» — так история решений остаётся читаемой. Именно её потеря
и превратила документацию в то, что есть сейчас.

### Д4 — закрепить правило

Шапка каждого документа: источник + дата сверки. Плюс перенос правила, которое в
проекте уже есть для тестов, на документы: **«проверено» относится к коммиту,
никогда к ветке.**

## 5. Дорожка К — клиент заново

Полный план — [Plan.md](Plan.md). Задача изменилась 2026-08-20: поддержка прежних
клиентов снята, серверные данные стираются, значит клиент **строится заново**, а не
рефакторится.

| Этап | Что | Выход |
|---|---|---|
| **К1** | каркас: модули, **iOS-таргет компилируется с первого коммита**, Koin, Konsist, CI | пустые сборки Android/ПК зелёные, `compileIosMainKlib` проходит |
| **К2** | `messenger-crypto` → KMP, перенос файл в файл | тест-векторы сходятся **байт в байт** на JVM и iOS-симуляторе |
| **К3** | `core-network`, `core-database` (SQLDelight, схема заново), `core-outbox` | смена прокси — конфигом; Outbox не теряет и не дублирует ни в одном состоянии |
| **К4** | срез: текстовое сообщение туда-обратно. Auth — водопроводом, без экранов | работает на **Android и ПК**; iOS компилируется |
| **К5** | `core-ui` из макета, `feature-auth`, экраны по [интерфейс.md](../doc/интерфейс.md), три формата | каждый экран — чистый рендер `State` |
| **К6** | группы, файлы, медиа, бюджет памяти | файл 100 МБ без выхода за бюджет; обрыв на 90 % продолжает с места |
| **К7** | звонки (маршрут для ПК выбирается замером) и обновления | звонок Android ↔ ПК состоялся |
| **К8** | ферма, прогон инвентаря поведения, удаление v1 | каждый пункт инвентаря закрыт тестом |

**Порядок экранов внутри К5 — по частоте использования, а не по номеру окна:** чат,
список чатов, лента, страница. Редактор последним: он самый большой, и от него
меньше всего зависит остальное.

**Что переносится из старого клиента, а не пишется заново:** крипто-ядро и схема
(с доказательством векторами) и инвентаря поведения на десять пунктов — признаки
блокировки из журналов мобильной сети, потолок zstd-бомбы, расхождение
`livekit_url`/`url`, стабильная подпись APK. Список — [Plan.md](Plan.md) §5.
Порядок работ с v1: вычитать инвентарь → тег `ref/client-v1` → новый `client/`.

## 6. Чего делать нельзя

| Нельзя | Почему |
|---|---|
| Удалять `client/` до вычитки инвентаря поведения | десять пунктов знания, которого нет ни в одном документе: признаки блокировки из живой мобильной сети, потолок zstd-бомбы, повадки `DownloadManager`. Собирать те же грабли заново — дороже всего остального в этом списке ([Plan.md](Plan.md) §5) |
| Переписывать крипто «раз уж всё равно с нуля» | доказательство дороже кода: векторы порождены внешними реализациями, оракул уже поймал молчащий дефект ML-KEM в Kodium. Крипто **переносится**, а не пишется |
| Менять формат конверта или API до работающей v2 | они единственное заведомо верное, пока всё остальное новое. Иначе упавшее сообщение не говорит, где сломалось |
| Держать два клиентских дерева одновременно | две сборки Gradle, два пути в CI и соблазн оставить оба. v1 живёт тегом `ref/client-v1`, не папкой |
| Удалять 20 файлов `doc_UI` из группы §12 | §12 их называет, но не описывает. Удаление = потеря спецификации регистрации, восстановления, редактора, мастеров создания |
| Править содержание ADR | журнал решений; перекрывается новым ADR, а не редактируется |
| Править применённую миграцию | правило репозитория: миграции append-only, даже когда база пересоздаётся |
| Менять деривации крипто при переносе файлов | `KodiumPrivateKey.fromRaw`, метки HKDF, канонические байты. Перенос обязан быть побайтово нейтральным, и это проверяют тест-векторы, а не глаза |
| Считать галочку в старом плане фактом | там же сказано, что часть кода писалась вслепую и не собиралась. Галочка — заявка |

## 8. Сделано 2026-08-20

**Корень репозитория очищен от документации:** 13 файлов разложены по `doc_mig/`,
`doc_mig/arhiv/` (с вердиктом по каждому), `doc_mig/отчёты/`; в корне остался
`CLAUDE.md`. Ссылки переписаны и внутри перенесённых файлов, и снаружи (`CLAUDE.md`,
`doc/adr/0010`, `ДОКУМЕНТАЦИЯ/README.md`); битых нет, перенос через `git mv`.

**Задача изменена по решению заказчика:** поддержка прежних клиентов снята,
серверные данные стираются, clean install подтверждён. `Plan.md` переписан: вместо
миграции К1…К5 — постройка заново К1…К8. Из семи ограничений осталось три
(`Plan.md` §0.1).

**Решено в обсуждении:** звонки на ПК — требование (три маршрута, выбор замером на
К7); алгоритм сжатия остаётся zstd, iOS получает cinterop к `libzstd`; срез К4
закрывается на Android и ПК, iOS держится компилируемым.

**Измерено:** удаление `doc_UI` рвёт 82 ссылки в 23 файлах; 20 файлов из 36 не
имеют полной замены в `интерфейс.md`.

Ничего не коммичено.
