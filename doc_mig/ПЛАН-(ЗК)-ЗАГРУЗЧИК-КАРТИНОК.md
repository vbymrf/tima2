# План: загрузчик картинок — Sketch 4.4.0

Заведён 2026-10-17 по решению заказчика: «Берём Sketch 4.4.0, напиши план… Пока как
внедрение и для чего».

Статус: **решено, не начато.** Здесь только внедрение загрузчика и его назначение. Что именно
показывают вложения, превью, редактор — отдельная задача: выбор реализации сообщений ещё не
оформлен полностью (`doc_add/редактор-сообщений/ВЫБОР-РЕАЛИЗАЦИИ.md`, вне git) и в план пока не
превращён. Когда превратится — будет опираться на этот загрузчик.

---

## 0. Для чего

Приложению нужно показывать много картинок: вложения в переписке, превью фото, картинки внутри
сообщений, аватары, анимированные эмодзи. Сейчас загрузчика нет вовсе — есть только аватары,
которые `shared/People.kt` качает и раскодирует сам: без кеша с вытеснением, без отмены, без
очереди, без анимации. Для ленты с картинками этого мало.

Загрузчик должен:

| № | Требование | Почему |
|---|---|---|
| 1 | Источник — **номер файла**, а не адрес: своя папка → наше хранилище → расшифровка ключом из сообщения | шифрование вложений |
| 2 | **Никаких запросов по адресу** из сообщения: загрузчик ходит только к нашему источнику | приватность |
| 3 | **Не класть расшифрованное на диск** своим кешем | на диске лежит только то, чем распоряжаемся сами |
| 4 | Раскодирование под размер места, вне главного потока, кеш в памяти по байтам | нагрузка при прокрутке |
| 5 | Отмена ушедшего с экрана, ограниченное число одновременных загрузок | нагрузка |
| 6 | **Анимированный WebP** на Android и ПК | набор анимированных эмодзи (`СТИКЕР-В-ТЕЛЕ-СООБЩЕНИЯ.md`) |
| 7 | Общий код Android и ПК, iOS потом | KMP |

## 1. Почему Sketch и почему 4.4.0

Сравнены по исходникам Sketch, Coil 3, Kamel, Landscapist (копии — `third-party/reference/`,
вне git). Все четыре — Apache-2.0.

| | Sketch | Coil 3 | Kamel | Landscapist |
|---|---|---|---|---|
| Ядро без сети | да | да | нет | нет |
| Свой источник | да, своя схема адреса | да | да | да |
| Кеш готовых картинок на диске отключается | да | — | — | — |
| Анимированный WebP на ПК | **да** | нет | в главном потоке | нет |

**Только Sketch закрывает все требования.**

**Почему не свежая 4.6.0.** Проверено на сборке 2026-10-17 (ветка `work/sketch-probe`, коммит
`8e2176e5`):

- 4.6.0 — Android-часть требует `compileSdk 37` и новый плагин сборки (у нас 35 и 8.13.2, он не
  выше 36), тянет `kotlin-stdlib 2.4.0` и `lifecycle 2.11.0-beta01`;
- 4.5.0 — тянет `androidx-core 1.18`, а тот требует `compileSdk 36`;
- **4.4.0 собирается как есть**: `compileSdk 35`, Compose остаётся 1.11.1, `kotlin-stdlib`
  поднимается до 2.3.21.

Переход на 4.6+ — вместе с подъёмом `compileSdk` и плагина сборки, отдельной задачей по своим
причинам, а не ради загрузчика.

**Что проба показала на 4.4.0:**

| Что | Итог |
|---|---|
| Свой источник `tima-media://<номер>` с расшифровкой | работает |
| Сетевых классов в сборке нет | тест |
| ПК, отрисовка без окна | фото показано, эмодзи — 39 разных кадров за 6 с |
| Android, Redmi (Android 16) | фото показано, эмодзи анимирован, ~30 кадров/с |
| Размер APK | +1,2 МБ |

## 2. Шаги

### ЗК1. Зависимость

- `libs.versions.toml`: `sketch = "4.4.0"`, модули **только** `sketch-compose-core` и
  `sketch-animated-webp`. Ни `sketch-compose` (там общий экземпляр), ни `sketch-http*`.
- `gradle/verification-metadata.xml`: внести новые артефакты по sha256. Проба собиралась с
  `--dependency-verification=lenient` — так в основной ветке нельзя. Список артефактов смотреть
  глазами: среди них не должно быть сетевых модулей Sketch.
- Сверить, что поднялось вместе с ним: `kotlin-stdlib` 2.3.21, `kotlinx-coroutines` — записать
  в коммит.

### ЗК2. Один загрузчик на приложение

- В `core-media`: сборка загрузчика под наш формат —
  - автоподключение модулей **выключено** (`componentLoaderEnabled(false)`): сетевой модуль не
    подключится сам, даже если его потянет другая зависимость;
  - компоненты — только наш источник и анимированный WebP;
  - кеш готовых и скачанных картинок на диске **выключен** (`resultCachePolicy`,
    `downloadCachePolicy` — `DISABLED`);
  - не больше 4 загрузок и 4 раскодирований разом;
  - кеш в памяти — Sketch, размер по умолчанию.
- Экраны получают загрузчик через `CompositionLocal`, а не создают свой.

### ЗК3. Источник `tima-media://<номер>`

- Загрузчик по схеме `tima-media`: номер файла → байты. Сами байты даёт порт, который
  подставляет `shared`:
  1. своя папка приложения (когда появится хранение файлов — ПЛАН-(ПМ), ПЛАН-(ПФ));
  2. наше хранилище — существующий `Media.download`;
  3. расшифровка ключом из тела сообщения — когда появятся зашифрованные вложения. Аватары
     сейчас открыты: шаг пропускается.
- `core-media` о сети и шифровании не знает — только порт.

### ЗК4. Проверки

- Тест: классов сетевого загрузчика Sketch в сборке нет.
- Тест: файл по номеру проходит цепочку «байты → расшифровка → картинка».
- Тест на ПК без окна: анимированный WebP даёт разные кадры (из пробы, `SketchProbeTest`).
- Живьём на Android: эмодзи анимирован, фото показано.

## 3. Что известно заранее

- **Android 8 (API 26–27)** анимированный WebP не играет — ни в Sketch, ни в остальных: там
  эмодзи будут неподвижными. Тестовые телефоны все новее.
- **На ПК** раскодировщик Skia медленно отдаёт кадры в конце длинной анимации; у Sketch есть
  настройка `cacheDecodeTimeoutFrame` ценой памяти. Для коротких эмодзи — проверить при
  внедрении.
- **iOS** Sketch поддерживает, включая анимацию, — проверяется вместе с клиентом iOS.
