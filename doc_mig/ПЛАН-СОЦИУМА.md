| **Крипта** | вся: групповой ключ, ротация по ADR-0017, escrow, догон версий |
| **Клиент** | `feature-group`: создание (`NewGroupScreen`), состав (`MembersStore`); `feature-chat`: групповая переписка. Оболочка с окнами 1–5 (`feature-shell/Windows.kt`) |
| **Макет** | светлый и тёмный: `подокна/создание-группы.html`, `уровень-сообщения.html`, `доступ.html` |

**Чего нет:** входа в создание группы (убран из окна 1 как придуманный, нового места ещё
нет), списка групп в окне 2, сообщений уровня 0, аудитории карточки, заявок, уровня
сообщения, доступа по разрешению, размещения группы на своей странице.

### Два разных предмета, и путать их дорого

| | Обычная группа | Личная группа |
|---|---|---|
| Кто видит | участники | участники **и** контакты того, кто положил её себе на страницу |
| Где на экране | окно 2, «Каталог» | там же — **когда вступил** |
| Как находят | каталог, поиск | **никак**: в индекс не попадает, раздаётся по цепочке знакомств |
| Что видно до вступления | ничего, 404 | карточка: название и сообщения уровня 0 |
| Как вступают | вступают сами | **заявка админу** — единственное доступное действие |

Личная группа — не «группа с флажком приватности». Она вводит два понятия, которых в
сервере нет вовсе: **кому карточка открыта** и **заявка на вступление**.

## 2. Решения заказчика 2026-09-04

Развилки закрыты до начала работ. Записаны здесь как основание плана; канонически живут в
[ADR-0019](../doc/adr/0019-message-level.md).

| Вопрос | Решение |
|---|---|
| Уровни разграничивают шифрование или показ | **только показ, ключ у группы один.** Шифрование — отдельная ось: −1 шифр, 0…3 открытые |
| Предел текста | **4096 знаков UTF-16 на сообщение, 1024 на подпись к медиа.** Особых пределов для уровня 0 нет, число сообщений не ограничено |
| Срок участия в группе | **делаем, эпохами.** Срок в месяцах, выбытие в конце эпохи escrow — там ключ и так меняется, новой фоновой подсистемы не нужно |
| Оси доступа | **две оси плюс уровень.** `preview` / `open` / `restricted` отменены |
| Мастер против ТЗ | **правим ТЗ** под четыре раздела |
| Отказ по заявке | **виден просившему.** То же для просьб о доступе к уровню 3 |
| Перенос записи «Друзьям» дальше | **да, разрешён.** Уведомления автору **не делаем** — оно лишнее. Учёт охвата для владельца контейнера (блогер, канал) — позже, страницы блогера сейчас не реализуем |

## 3. Порядок работ

**Сервер раньше клиента, без исключений** (`ПРАВИЛА-РАБОТЫ.md §2–§4`). Каждый этап —
отдельный коммит с проверяемым результатом.

**Аддитивность здесь не про старых клиентов.** Их не существует: `Plan.md §0.0` решение 3
отменило поддержку прежних клиентов, решение 2 стирает серверные данные. Причина другая и
записана решением 5: **формат конверта и API не меняются, пока v2 не заработает** — иначе
при отладке окажется три неизвестных сразу. Мы добавляем маршруты и колонки, но не
переделываем существующие.

```
Г1 сервер: уровень сообщения           ← основание всего
   ↓
Г2 сервер: описание = уровень 0, аудитория карточки
   ↓
Г3 сервер: заявка на вступление
   ↓
Г4 сервер: доступ по разрешению, срок участия
   ↓
Г5 клиент: мастер создания — четыре раздела
   ↓
Г6 клиент: окно 2 «Социум» — каталог, друзья, вход создания
   ↓
Г7 клиент: круг сообщения — выбор, метка, сужение
   ↓
Г8 клиент: перенос к себе — кнопка и стена
   ↓
Г9 клиент: доступ по разрешению — состав, выдача, просьбы
   ↓
Г10 группа без ключа говорит об этом словами
   ↓
Г11 проверка живьём на трёх телефонах
```

### Г1 — сервер: уровень сообщения

Основание модели. Всё остальное — следствия.

| Что | Как |
|---|---|
| Хранение | миграция: `group_messages.level SMALLINT NOT NULL DEFAULT -1` |
| Выборка | `GET /groups/{id}/messages?max_level=N` — граница считается по правам просящего |
| Смена уровня | `PATCH /groups/{id}/messages/{msgID}` — **только сужение**, расширение отклоняется |
| Право менять | своё сообщение — автор; чужое — админ и владелец |
| Предел текста | 4096 знаков UTF-16, подпись к медиа 1024 |
| Индексация | **только `уровень ≥ 0 И контейнер публичный`** |

**Условие индексации записать явно и покрыть отдельным тестом.** Иначе первый, кто
напишет индексацию по одному уровню, выложит личные группы в поиск.

**Проверяется:** посторонний получает 0 и 1; вступивший — до 2; с разрешением — до 3;
попытка расширить уровень отклонена; личная группа не попадает в индекс ни на каком
уровне; текст длиннее 4096 не принимается.

---

### Г2 — сервер: описание как обычное сообщение

Витрина перестаёт быть особым полем (ADR-0019 §4).

- **не заводим** `groups.showcase` и `PUT /groups/{id}/showcase` — минус сущность, минус
  маршрут, минус миграция;
- аудитория карточки: `group_card_audience(group_id, user_id, updated_at)`;
- `PUT /groups/{id}/audience` — **список целиком, не дельта**: книга контактов живёт
  только у клиента, и помнить чужое прошлое состояние сервер не должен;
- `GET /groups/{id}` отвечает **двумя видами**: участнику — как сегодня, поле в поле;
  не-участнику из аудитории — карточка с сообщениями уровня 0; вне аудитории — 404.

**Цена, названная прямо:** после Г2 существование, название и описание личной группы лежат
на сервере открытыми и расходятся по цепочке контактов. Принято сознательно (ADR-0018).

**Проверяется:** участник не замечает изменений; не-участник из аудитории получает
карточку без переписки; вне аудитории — 404.

---

### Г3 — сервер: заявка на вступление

Единственное действие с чужой личной группой (ADR-0018 п. 7).

- `group_join_requests(group_id, user_id, state, asked_at, answered_at, answered_by)`;
- `POST /groups/{id}/join-requests` — право: быть в аудитории карточки;
- `GET /groups/{id}/join-requests` — админу;
- `PATCH /groups/{id}/join-requests/{userID}` — принять или **отказать; отказ виден
  просившему**.

**Принятая заявка обязана ротировать ключ** тем же путём, что обычное добавление
участника: инвариант ADR-0017 не знает, откуда пришёл участник.

**Проверяется:** заявка вне аудитории отклонена; принятие двигает версию ключа; повторная
заявка не плодит строк; отказ виден просившему.

---

### Г4 — сервер: доступ по разрешению и срок участия

- `group_level_grants(group_id, user_id, level, until_epoch, granted_by, granted_at)` —
  выдача, отзыв, список; просьбы и ответы на них;
- **срок закрывает будущее, а не прошлое:** прочитанное остаётся у человека;
- **срок участия в группе** — в месяцах, хранится эпохой; выбытие происходит **при
  плановой смене эпохи**, когда ключ и так меняется.

Отдельной фоновой задачи не заводится: обработчик смены эпохи уже существует и уже
ротирует ключ — к нему добавляется выборка «у кого срок истёк».

**Ротация ради уровня 3 не нужна:** он существует только в публичной группе, а она не
шифруется.

**Проверяется:** после истечения срока новые сообщения уровня 3 не отдаются, прочитанные
остаются; отзыв действует немедленно; участник со сроком выбывает ровно на смене эпохи и
ключ меняется один раз, а не дважды.

### Г5 — клиент: мастер создания

Макет: `телефон/подокна/создание-группы.html`, описание — `doc_UI/33` (переписан).

- четыре раздела на входе, три серых;
- шаг 2 — вид: личная или публичная; **вид не меняется после создания**;
- шаг 3 — вступление: **у личной только закрытая**, и сказано почему;
- шаг 4 — значок, название, описание = **первое сообщение уровня 0**;
- круг слева у каждой строки — он же кнопка «?».

Заменяет нынешний `NewGroupScreen`.

**Проверяется:** снимки всех шагов; тест, что для личной группы «открытая» недоступна.

---

### Г6 — клиент: окно 2 «Социум»

- **«Каталог»** — свои группы; личная появляется **после вступления**;
- **«Друзья»** — чужие карточки: то, что положили себе контакты;
- карточка чужой личной группы: название, описание, одна кнопка — «попросить админа»;
- **сюда переезжает вход в создание** — плюс в салатовом кружке.

Вход в группы стоял в окне 1 и был придуманным; 2026-08-26 его отделили от круга
«Написать» (он читался как часть этой кнопки), а затем убрали вовсе. Здесь он получает
своё место.

**Личные группы не ищутся** — ни поиском окна, ни глобальным. В коде это должно быть
видно как решение, иначе «починят».

**Проверяется:** снимки вкладок; тест, что личная группа не попадает в выдачу поиска.

---

### Г7 — клиент: круг сообщения

Макет: `подокна/уровень-сообщения.html`, разделы 1–4.

- выбор круга рядом с «Отправить», а не в настройках;
- «сузить можно, расширить нельзя» — сказано **до** отправки;
- предупреждение перед сужением: у тех, кто унёс, запись останется;
- метка со стрелкой вправо у сообщений группы; **по умолчанию выключена**;
- оповещение о сужении приходит строкой в саму группу.

**Слова «уровень» на экране нет нигде.**

**Проверяется:** снимки; тест, что расширение недоступно в интерфейсе, а не только на
сервере.

---

### Г8 — клиент: перенос к себе

Макет: `подокна/уровень-сообщения.html`, разделы 5–6.

- кнопка «Добавить себе» в конце сообщения: полная и без слова, переключение по остатку
  строки;
- в переписке — серый знак над кнопкой эмоции; у своих сообщений его нет;
- стена: принесённое живёт **от лица группы или канала**, отклики идут оригиналу;
- **переносится ссылка, копий нет нигде**; уведомления автору не шлём;
- «нельзя унести» — знак пропадает, метка остаётся серой.

**Проверяется:** снимки ленты и стены; тест, что перенос создаёт ссылку, а не запись;
тест, что удаление оригинала убирает принесённое.

---

### Г9 — клиент: доступ по разрешению

Макет: `подокна/доступ.html`.

- состав глазами админа с метками доступа;
- выдача: бессрочно, до даты (кнопка «Календарь»), на срок;
- «срок вышел» с кнопкой «Попросить»;
- очередь просьб со счётчиком; **отказ виден просившему**;
- тег доступа в описании группы.

**Проверяется:** сквозной путь «попросил — дали до даты — срок вышел — попросил снова».

---

### Г10 — группа без ключа говорит об этом словами

Отдельным этапом, потому что это **не украшение экрана, а условие пользуемости**.

Устройство, подключённое по QR-коду, не имеет ни одной версии группового ключа. Пока ключ
не сменится, группа для него молчит — не открываются даже сообщения, пришедшие минуту
назад. Появление устройства смену не запускает: её запускает вход, выход или новая эпоха,
то есть раз в месяц.

| Состояние | Что сказать |
|---|---|
| есть нечитаемые сообщения, фраза есть | как сейчас: «запросить ключ» |
| фразы на этом устройстве нет | **оба выхода**: написать с другого своего устройства (ключ сменится) или войти здесь по фразе |
| ключа нет вовсе, группа пуста для устройства | **сказать прямо**, что это не пустая группа, а отсутствующий ключ |

Первые два сделаны 2026-08-26 (`ChatNotice.KeysNeedPhrase`). Третье не сделано: нужен
признак «у этого устройства нет ни одной версии GK» и полоса поверх списка. Пустая группа
и группа без ключа сегодня выглядят одинаково — та же ошибка, что была с «Устройств нет».

**Проверяется:** снимок группы без ключа с полосой; снимок правда пустой группы — без неё.

---

### Г11 — проверка живьём

Три телефона, три аккаунта. Сквозной путь: создать личную группу → положить на страницу →
второй увидел карточку → попросил → приняли → написал → третий не видит ничего.

**Живьём группы ещё не проверялись ни разу** (`ИНТЕРФЕЙС/05-группы/ФУНКЦИОНАЛ.md`: «два
аккаунта заведены, до групп не дошли»). Это не формальность: ротация ключа при вступлении
и догон версий на новом устройстве — те места, где тесты зелёные, а живьём бывает иначе.

## 4. Как строим интерфейс

**Решение 2026-08-25, действует:** полный интерфейс телефона с **честными заглушками**
(`ДОРОЖНАЯ-КАРТА К5.4(б)`).

> рейка строится с ЧЕСТНЫМИ заглушками — «здесь будет лента», а не выдуманные записи.
> Нарисованные данные однажды уезжают в сборку и принимаются за работающее; этим проект
> уже болел.

| Делаем | Не делаем |
|---|---|
| все окна телефона существуют и открываются | подокна сверх нужных этапу |
| вкладки внутри окон нарисованы и переключаются | планшет и ПК (отдельная дорожка) |
| пустое окно говорит словами, чего в нём нет | выдуманные ленты, посты, счётчики |

**Правило одной строки:** каждая заглушка в тот же день получает строку в
`ИНТЕРФЕЙС/<окно>/ЗАГЛУШКИ.md` — что стоит, что должно быть, чем держится. Заглушка без
записи — незамеченная неправда в приложении.

**Макет светлый и тёмный правятся вместе:** `стиль.css` в них побайтово одинаков,
различие только в `тьма.css`.

| Этап | Макет | Записи `ИНТЕРФЕЙС` |
|---|---|---|
| Г5 | `подокна/создание-группы.html` | `05-группы/ЗАГЛУШКИ.md` — снимается «экран создания придуман» |
| Г6 | окно 2 в `окна/новости.html` | `04-социум/`, `05-группы/СВЯЗИ.md` |
| Г7 | `подокна/уровень-сообщения.html` | `03-переписка/`, `05-группы/ФУНКЦИОНАЛ.md` |
| Г8 | там же, разделы 5–6 | `14-страница/` |
| Г9 | `подокна/доступ.html` | `05-группы/ФУНКЦИОНАЛ.md` |
| Г10 | — | `05-группы/ЗАГЛУШКИ.md` |

## 6. Чего этот план не делает

- **Каналы, сообщества, звуковые чаты.** В мастере серые. Каналы на сервере есть,
