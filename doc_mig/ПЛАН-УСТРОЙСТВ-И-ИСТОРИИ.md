# План: доверие к устройствам и история на новом устройстве — Б

Заведён 2026-10-02 по решению заказчика после разбора ключей. Две беды одного корня: **устройство
в аккаунте ничем не подтверждено**, и **новое устройство не получает прежнюю переписку** («на ПК
не видно чатов с телефона»).

Родственное: [ADR-0010](../doc/adr/0010-history-recovery-multidevice.md) — восстановление истории,
[ADR-0014](../doc/adr/0014-identity-chain.md) — цепочка личности,
[ADR-0017](../doc/adr/0017-group-key-rotation.md) — смена ключа группы,
[key-lifecycle.md](../doc/03-security/key-lifecycle.md), [ПЛАН-КЛЮЧЕЙ-ГРУПП.md](ПЛАН-КЛЮЧЕЙ-ГРУПП.md),
[ПЛАН-ВЫХОДА-ИЗ-АККАУНТА.md](ПЛАН-ВЫХОДА-ИЗ-АККАУНТА.md) — вход по QR,
[ДОРОЖНАЯ-КАРТА.md](ДОРОЖНАЯ-КАРТА.md) К5.1б–К5.1г.
Перед правкой `messenger-crypto/**`, `core-encryption`, `schema/**` — `.cursor/rules/crypto-invariants.mdc`.

## 0. Как устроено сейчас (по коду, 2026-10-02)

| Ключ | Сколько | Откуда | Где закрытая часть | Для чего |
|---|---|---|---|---|
| Ключ личности | один на аккаунт | из фразы, 12 слов (`AccountMnemonic.kt`) | нигде: выводится из фразы на время подписи | «это я, хозяин аккаунта»: восстановление, перенос |
| Ключи устройства | пара на устройство: шифрование X25519, подпись Ed25519 | устройство само, случайно (`DeviceIdentity.kt`) | на устройстве | получать зашифрованное, подписывать своё |
| Ключ группы | один на версию группы | участник при смене (`GroupKeyManager.kt`) | у участников | сообщения группы |

- **Шифруем ключами устройств.** Ключ сообщения упаковывается для каждого устройства получателя и
  своих других устройств (`PersonalMessageSealer.kt`); сообщение подписано ключом устройства.
  Ключ личности в шифровании не участвует.
- **Устройство никто не одобряет.** `/auth/register`: код SMS и открытые ключи — устройство сразу
  рабочее. Ключ личности при регистрации необязателен; не прислан — проверка совпадения не
  делается вовсе (`store/identities.go:150`).
- **Клиенты верят списку устройств сервера** (`Sender.kt:166`, `Receiver.kt:954`, `GroupKeyRotation.kt`):
  нет ни подписи устройств, ни знания ключа личности собеседника, ни предупреждения о смене.
- **Отсюда:** укравший SIM регистрирует устройство без фразы и получает **новые** личные
  сообщения сразу, ключ группы — при следующей смене. Старая история закрыта: её восстановление
  подписывается фразой. Взломанный сервер может подложить своё устройство так же.
- **Новое устройство** получает только новые сообщения и список групп; личных чатов не видит до
  следующего сообщения в них; старых сообщений не получает ни личных, ни групповых — в первом
  приложении это было, в новое не перенесено (К5.1в «не начато»; экран QR сам предупреждает:
  «Прежняя переписка туда не переедет», `Words.kt:3360`).
- **Отзыв устройства не меняет ключ группы:** сервер шлёт причину `device_revoked`, которую сам не
  принимает (`groups.go:460`); клиент делает из неё плановую смену, а плановую сервер отклоняет
  без новых сообщений и чаще 15 минут.

## 1. Решения заказчика (2026-10-02)

| # | Решение |
|---|---|
| Р1 | **Ключи устройств из мастера (HKDF) не выводим.** Ключи устройств случайные и независимые; доверие даёт обязательная подпись, а не вывод |
| Р2 | **Схема В — промежуточный ключ аккаунта.** Фраза подписывает «ключ подписи устройств»; он лежит на доверенных устройствах и подписывает новые. Украден телефон — по фразе выпускается новый промежуточный ключ, остальные устройства переподписываются, подписанное старым у всех перестаёт быть доверенным |
| Р3 | **QR — главный путь нового устройства:** его подписывает доверенное устройство, фраза не нужна |
| Р4 | **Сначала часть 2 (доверие), потом часть 1 (история)** |
| Р5 | **Часть 2 — раньше v2**, вопреки решению 5 `Plan.md §0.0` (формат не меняем до v2): заказчик решил, что дыра важнее |
| — | Беда «вор SIM читает новые сообщения» — **обсуждается** |

## 2. Часть 2 — доверие к устройствам (первой)

| | Что | Состояние |
|---|---|---|
| **ДУ1** | Промежуточный ключ аккаунта — «ключ подписи устройств»; фраза подписывает его открытую часть, сервер хранит подпись; закрытая часть — на доверенных устройствах | не начато |
| **ДУ2** | Подпись устройств: первое — при регистрации (фраза есть — промежуточный ключ выпускается сразу), следующие — по QR доверенным устройством (Р3), без старого устройства — по фразе. **У аккаунта с фразой только SMS — отказ** | не начато |
| **ДУ3** | Клиент знает ключ личности собеседника: запоминает при первой встрече (`/users/identities` есть), проверяет цепочку «личность → промежуточный → устройство», **не шифрует для неподписанного устройства** — ни личное, ни ключ группы; при смене личности — предупреждение (ADR-0014) | не начато |
| **ДУ4** | Отзыв: украденный телефон — по фразе новый промежуточный ключ, переподпись остальных; отзыв устройства **меняет ключ группы** (починить причину `device_revoked`) | не начато |
| **ДУ5** | Экран «Устройства»: список, какое чем подписано, отзыв (К5.1г) | не начато |

**Где нужна фраза:** первое устройство; новое без старого под рукой; кража телефона. Всё
остальное — QR.

| Случай | Что нужно |
|---|---|
| Первое устройство | фраза — создаётся или вводится, как сейчас |
| Новое устройство, старое под рукой | QR |
| Все устройства потеряны | фраза |
| Ни старого устройства, ни фразы | только «Начать заново» — новая личность; собеседники видят «сменил ключ» |
| Только SMS у аккаунта с фразой | отказ |

## 3. Часть 1 — история на новом устройстве

| | Что | Состояние |
|---|---|---|
| **ИУ1** | Новое устройство узнаёт свои личные чаты — список чатов аккаунта (ручка сервера) | не начато |
| **ИУ2** | «Доверить» по QR: доверенное устройство перезаворачивает ключи личных сообщений для нового страницами (К5.1в) | не начато |
| **ИУ3** | Новое устройство загружает старые сообщения страницами — личные и групповые | не начато |
| **ИУ4** | Вход по фразе без старого устройства: подписанный запрос восстановления (ручки сервера есть: `chats/{id}/recover`, `recover/provide`); своё устройство помогает само, собеседник — с согласием на экране; защита процесса из ADR-0010 («это вы?», пределы, объём) | не начато |
| **ИУ5** | Ключи групп запрашиваются сами, помощники ищутся не только по серверной копии ключей (она удаляется через 90 дней) | частично: кнопка «Запросить ключ» руками |
| **ИУ6** | Срок 90 дней: копия ключей своих чатов под ключом из фразы (ADR-0010 этап 4) — история не теряется вместе со сроком | частично: сервер есть, клиент не вызывает |

## 4. Часть 3 — долги

- Смена ключа группы, пропустившая устройство участника, — отказ, а не запись в журнал (ADR-0017 §6).
- Проверка версии ключа депозитария у входящего конверта (ADR-0012).
- Привязка ключа (key commitment) у сообщений группы (ADR-0013).
- Плановая месячная смена ключа группы — по расписанию, а не по первому сообщению (ADR-0017 §3).

## 6. Переход — обсуждается

Вопросы заказчика 2026-10-02, ответы — в разговоре, решения нет:

- **Прочитает ли клиент свои сообщения после правок.** Сообщения зашифрованы ключами устройств,
  а не личности; подпись устройств их не трогает — уже работающие устройства читают всё, что
  читали. Им нужна только подпись: устройство, получившее промежуточный ключ по фразе, подписывает
  остальные свои устройства (подтверждение «это мои устройства» или QR).
- **Не отрежем ли доступ.** Устройство со старой версией подписи не получит; как только клиенты
  собеседников начнут отказывать неподписанным (ДУ3), оно перестанет получать новые сообщения до
  обновления. Отсюда предложение: сначала мягкий режим — подписи собираются, неподписанным пишем
  предупреждение, но шифруем; строгий — когда подписаны все устройства живых аккаунтов.
- **Аккаунты без фразы** (на стенде 35 из 49, все старые): при входе — завести фразу (сервер
  позволяет установить личность, если её нет), а не отказ.
