# Учёт ошибок

Заведён 2026-11-20 (заказчик: «Нужно завести журнал. Где мы будем вести учёт ошибок и рассматривали их или нет»).
**Здесь — каждая пришедшая ошибка и её судьба: рассмотрена или нет, и где разобрана.** Не разбор (он — в
[БЕДЫ](../../БЕДЫ/README.md), отчётах и планах), а опись: чтобы ни одна ошибка не потерялась между заходами.

## Откуда приходят ошибки

| Источник | Где лежит | Как забрать |
|---|---|---|
| **Отчёты о проблемах** из приложения («Настройки → помощь, баги», падение) | стенд, таблица `problem_reports`; номер — 4 знака (`A9A6`) | выгрузка ниже, раздел «Отчёты о проблемах» |
| **Логи служб стенда** | `docker logs` у `tima-backend-1`, `tima-worker-1`, `tima-livekit-1`, `tima-caddy-1`, `tima-postgres-1` | раздел «Логи стенда» — проверка с датой и вердиктом по каждой строке |
| **Журналы устройств** | `files/logs/<дата>.txt` на телефоне, отчёт о проблеме несёт его хвост | по [ПОДКЛЮЧЕНИЕ.md](../ПОДКЛЮЧЕНИЕ.md); найденное — сюда строкой |

## Как вести

Папка: эта опись (`README.md`) и разборы по заходам — `РАЗБОР-<дата>.md`, первый —
[РАЗБОР-2026-11-20.md](РАЗБОР-2026-11-20.md).

- **Статус** — один из пяти, тот же в описи и у отчёта на стенде (`problem_reports.review_status`, миграция `0089`):

  | В описи | На стенде | Когда |
  |---|---|---|
  | **не рассмотрено** | `NULL` | никто не смотрел |
  | рассмотрено | `reviewed` | причина найдена: ссылка на беду, коммит, разбор |
  | проверить | `check` | причина вероятна, но не доказана — нужна живая проверка или уточнение |
  | не беда | `not_bug` | связь, отметка проверки, ошибка проверяющего |
  | устарело | `stale` | старая сборка на месте, переделанном с тех пор; повторов нет |

  На стенде к статусу — `review_note` (словами), `review_ref` (путь или коммит), `reviewed_at`.
- **Разобрал — поставь ссылку здесь же, тем же коммитом, и отметку на стенде тем же заходом.** Номер отчёта пишется в
  разборе как есть (`A9A6`): по нему связь и проверяется (поиск номера по `doc_mig`).
- **Заход к стенду** — новые отчёты дописываются сверху (по дате), логи — новой проверкой с датой.
- Выгрузка нерассмотренных (только чтение):
  `select number, kind, model, build, created_at, left(body, 80) from problem_reports where review_status is null order by created_at desc;`
- Отметка (запись на стенде — только по задаче заказчика):
  `update problem_reports set review_status='reviewed', review_note='…', review_ref='…', reviewed_at=now() where number='A9A6';`
