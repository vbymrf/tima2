# Запись ленты канала уходила описанием (2026-11-23)

Поняли 2026-11-23 на живой проверке сборки 274 на realme (ПЛАН-(СЦ) СЦ18, СЦ22).

## Что было видно

Канал «kanal 274»: две записи, опубликованные полем ленты («post 274…» и «rich 274» из редактора), оказались в
«Управление → Сообщения» — списке **сообщений уровня 0** — с кнопками «Сделать суперсообщением», «Править», «Удалить».

## Чем это казалось

- **«Список сообщений берёт всю ленту»** — нет: выдача `GET /channels/{id}/showcase` отбирает по `level = 0` и
  `parent_post_id IS NULL` (`ChannelShowcase`), чужих уровней в ней нет.
- **«Новый экран путает записи»** — нет: строки экрана — ровно выдача описания.

## Доказательство

`InvitesOverHttp.channelPublish` с СЦ3 (2026-11-19) слал `"level": 0` — комментарий так и говорил: «уровень 0 — всем
подписчикам». Но уровень 0 — это **описание** (ПЛАН-(ЗО) ЗО1–ЗО2, ADR-0019): его забирает окно «Описание», вершину он не
поднимает, а у сущности их не больше 50 (`showcase_full`). Значит, каждая запись ленты канала с 2026-11-19 ложилась в
описание, не поднимала строку канала у подписчиков и съедала предел 50.

## Настоящая причина

Слово «всем» у уровней два: 0 — «всем и всегда» (описание), 1 — «всем» (в ленты). Поле ленты взяло первое по смыслу
слова, а не по уровню.

## Как починено

`1b2f0b2b` (275): `channelPublish` по умолчанию — уровень 1; запись из редактора ленты — тоже 1. Описание пишется только
из «Управление → Сообщения» (`ShowcaseOverHttp.addChannel`, уровень 0). Уже опубликованные уровнем 0 записи остаются в
описании — их можно удалить там же.

## Чем проверено

realme, 275: «post 275» из поля ленты — в ленте есть, в «Управление → Сообщения» нет; прежняя «post 274» — там, где
была.

## Чему учит

Уровень — число, а не слово: в запросе на запись его ставят по таблице уровней (ADR-0019), а не по надписи на кнопке.
