# Личная группа без ключа: «ключа этой группы на устройстве нет»

Понято 2026-09-18. Починено в тот же день, четыре правки в одном коммите.

---

## Что было видно

Владелец открывает свою группу «наша новая» на Redmi и видит полосу: **«Ключа этой группы
на устройстве нет — поэтому она пуста. Сообщения есть, но открыть их нечем. Попросите
ключ у участников»** и кнопку «Запросить ключ». Написать в группу нельзя. Кнопка не
помогает. В первом клиенте такого не было.

## Чем это казалось

**«Ключ есть, но не на этом устройстве»** — так говорил экран, и так устроена модель:
групповой ключ (GK) заворачивается на каждое устройство каждого участника, устройство без
обёртки читать не может. Логичное следствие — «попросить у того, у кого есть». Неверно:
ключа не было **ни у кого**.

**«Беда шифрования»**. Нет: шифрование работало, до него не доходило.

## Доказательство

База Redmi (`run-as`, `exec-out` — не `shell`, тот портит двоичный вывод переводами строк):
таблица `group_keys` **пуста**, сообщений в группах **ноль** — даже нерасшифрованных.

Сервер (`psql`): обе группы созданы самим Redmi 16 сентября; `group_key_history` —
**пусто**, `group_wrapped_keys` — **пусто**, `group_messages` — **пусто**. Ключ не
существовал.

Журнал приложения после первой починки (лечение при открытии):

```
GET  /api/v1/groups/{id}/keys      200
GET  /api/v1/groups/{id}/members   200
GET  /api/v1/keys/devices          200
GET  /api/v1/escrow/key            200
POST /api/v1/groups/{id}/keys      400   ← ротация отвергнута
```

`groups.go`, `reasonAllowed`: принимаются `epoch · periodic · member_join · member_leave ·
compromise`. `GroupKeyRotation.kt:123`: клиент слал `"member_change"`.

## Настоящая причина — четыре, одна за другой

1. **Создание группы не выпускало ключ.** В v1 (`ref/client-v1`,
   `TimaChatService.createGroup`) сразу после добавления участников шёл
   `rotateGroup(groupId, currentVersion = 0)` — группа рождалась с ключом версии 1. При
   переписывании на `CreateGroupChat` вызов потерялся. Отправка без ключа отвечает
   `NoKey`; просить ключ у владельца свежей группы не у кого. Тупик без выхода.

2. **Ни одна ротация с клиента v2 не проходила никогда.** Причина `member_change` не из
   списка сервера → 400 `bad_reason`. Это касалось приглашения, исключения, ротации по
   счётчику — всего. Ошибка была видна только в журнале сетевых вызовов.

3. **Публичная группа считалась зашифрованной.** Сервер на любой вопрос о ключах группы
   вида `public` отвечает `not_e2e: «GK есть только у private-групп»` — у неё ключа нет по
   замыслу, сообщения идут открытыми уровнями 0…3. Клиент рода группы не знает и показывал
   тот же баннер «ключа нет». Группа «родная» на стенде — публичная.

4. **Поле ввода уезжало за экран.** Пять чипов круга и пояснение в одном `Row`: пятый чип
   ужимался до одной буквы, пояснение вытягивалось столбиком на весь экран, поле ввода —
   ниже края. Даже с ключом написать было нельзя. Найдено, когда ключ уже вылечили.

## Как починено

| | Где | Что |
|---|---|---|
| 1 | `CreateGroupChat` | после добавления участников — первый выпуск ключа (только личной группе), как в v1 |
| 1 | `HealGroupKey` (новое), `ChatStore` | открытие группы без ключа: забрать обёртки; если у сервера версия 0 — выпустить первый; публичной — снять баннер и слать «Всем» |
| 2 | `RotationReason` (новое), `GroupKeyRotator` | причина — перечнем из списка сервера, по назначению: вход `member_join`, выход `member_leave`, счётчик `periodic`, эпоха `epoch` |
| 3 | `HealGroupKey`, `ChatStore.openGroup` | `not_e2e` → род группы «открытая», баннера нет |
| 4 | `ChatScreen` | ряд кругов — `FlowRow`, пояснение отдельной строкой |

## Чем проверено

Redmi, сборка 21: открытие «наша новая» → сервер `group_key_history: 1 | member_join`,
обёртка для устройства Redmi; баннер снят; сообщение отправлено — на сервере
`group_messages: 1, gk_version 1`, на экране галочка.

**Не проверено:** realme открывает публичную «родная» (ожидается: баннер снят через
`not_e2e`); приглашение и исключение с новой причиной — тестами зелёные, живьём нет.

## Чему учит

**Сообщение об ошибке описывало модель, а не факт.** «На устройстве нет» — правда о
модели ключей, ложь о состоянии: ключа не было нигде. Экран, который называет причину,
обязан знать её, а не выводить из устройства системы.

**Несовпадение перечней клиента и сервера молчит годами.** Строка `member_change`
компилировалась, тесты с заглушками её принимали, сервер отвечал 400 — и никто не читал
журнал сетевых вызовов группы, потому что группы «просто не работали». Перечень вместо
строки — единственная защита: строку не с чем сверить.

**Одна видимая беда — четыре настоящие.** Каждая следующая открывалась, когда чинили
предыдущую. Остановиться после первой значило бы «починить» и получить тот же экран.
