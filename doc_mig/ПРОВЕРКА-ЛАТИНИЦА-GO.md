# Задание на проверку: латиница в именах Go

Проверяется коммит переименования 78 имён внутри пакета `server/internal/api`.
Поведение не менялось — ни одной строки кода не добавлено и не удалено, только имена.

**Проверять надо не то, что собирается.** Это уже проверено на машине разработки, и
проверено сильно: компилятор Go видит каждое имя пакета. Проверять надо то, чего
отсюда не видно: **отвечает ли сервер так же, как отвечал**. Для этого нужны живые
службы, а на машине разработки их нет.

---

## Коротко

```
git pull --rebase
check-server.bat -Clean
```

Дальше прислать файл `doc_add\otchet-proverki-go.txt`. Всё.

Ключ `-Clean` нужен, если на докере висят старые контейнеры TIMA. Без него скрипт их
покажет и **остановится**, не начиная прогон, — потому что прогон рядом со старым
стеком ничего не доказывает.

Остальное в этом документе — на случай, если что-то пойдёт не так.

---

## 1. Что должно быть на машине

| Что | Зачем | Проверка |
|---|---|---|
| **Go** 1.24+ | собрать и прогнать | `go version` |
| **Docker Desktop** | Postgres, Redis, MinIO | `docker info` |
| **git** | вписать вершину в отчёт | `git --version` |

Ставится обычными установщиками с сайтов проектов; ничего специфичного для TIMA не
нужно. После установки Docker Desktop **дождаться, пока он скажет «running»** — до этого
движок команд не принимает, и выглядит это как «докер сломан».

Скрипт всё это проверяет сам и называет, чего не хватает. Ставить заранее «на всякий
случай» ничего не нужно: запустите и прочитайте, что он скажет.

---

## 2. Старые версии сервера на докере

Это не мелочь, поэтому отдельным разделом.

У боевого стека (compose-проект `tima`) контейнеры подняты с `restart: unless-stopped`.
Значит **после каждого запуска Docker Desktop они поднимаются сами** — молча, без вашего
участия. Они держат порт 8080 и память, а увидеть их можно только списком контейнеров,
не по симптомам.

Скрипт печатает инвентарь и помечает чужое словом `СТАРОЕ`:

```
== Инвентарь докера: контейнеры TIMA ========================================
  СТАРОЕ [tima] tima-backend-1   tima-backend:local   Up 6 days
  СТАРОЕ [tima] tima-postgres-1  postgres:16          Up 6 days (healthy)
         [tima-test] tima-test-postgres-test-1  postgres:16  Up 13 days (healthy)
```

Наши — `tima-dev` и `tima-test`. Всё остальное с `tima` в имени — старое.

С ключом `-Clean` скрипт их **останавливает**. Тома не трогает: данные остаются,
останавливаются процессы. Вернуть старый стек обратно — обычным
`docker compose -f server/deploy/docker-compose.prod.yml up -d`.

Если хотите разобрать руками:

```powershell
docker ps -a --filter name=tima          # что вообще есть
docker compose -p tima stop              # остановить боевой проект
docker volume ls --filter name=tima      # тома; удалять НЕ надо
```

## 3. Что делает скрипт и почему сам

`check-server.ps1` в корне репозитория, `check-server.bat` — обёртка над ним.

| Шаг | Что делает |
|---|---|
| 1 | находит корень репозитория от собственного расположения; пишет ветку и вершину |
| 2 | проверяет `go`, `docker`, движок докера |
| 3 | печатает инвентарь контейнеров TIMA, помечает старые |
| 4 | поднимает `tima-test` (Postgres на 55432) и `tima-dev` (Postgres, Redis, MinIO) |
| 5 | **ждёт, пока службы ответят** — а не пока докер скажет «создан» |
| 6 | `go build`, `go vet`, `gofmt -l` |
| 7 | `go test -count=1 -v ./...` в журнал |
| 8 | считает RUN / PASS / FAIL / SKIP и выносит вердикт словами |
| 9 | пишет `doc_add\otchet-proverki-go.txt` |

**Почему считает скрипт, а не человек.** Прогон без служб выходит с нулём и печатает
`ok`, пропустив 72 теста пакета api из 120: `internal/api/api_test.go:52` делает `t.Skipf`, когда
база недоступна. Отсутствие окружения выглядит как пройденная проверка. Увидеть подмену
можно, только считая строки `--- SKIP`, а строки руками никто не считает.

**Почему ждёт, а не спит фиксированно.** «Контейнер создан» и «служба отвечает» — разные
события, у Postgres между ними десятки секунд. Прогон, начатый в этом промежутке, уйдёт
в `Skipf`, то есть в тот же ложный успех.

Ключи:

| Ключ | Когда |
|---|---|
| `-Clean` | на докере висят старые контейнеры TIMA |
| `-NoDocker` | службы подняты иначе — портативный способ, `server/deploy/СТЕК-ДЛЯ-ТЕСТОВ.md` §2 |
| `-Down` | погасить оба проекта после прогона (по умолчанию остаются подняты) |

## 4. Как читать вердикт

Скрипт говорит одним из двух:

```
ПРИНЯТО. Все проверки зелёные, пропусков нет.
```

```
ЧИНИТЬ. Замечаний: 2
  - Пропущено тестов: 8. Служба не поднялась, прогон НЕДЕЙСТВИТЕЛЕН.
  - Упало тестов: 1. Имена — в журнале по строкам «--- FAIL».
```

Ожидание тира `server-full` — **120 из 120, SKIP = 0**. Число берётся не с потолка:
`grep -rc '^func Test' server` — столько в репозитории тестовых функций.

Проверено 2026-08-26 на машине сборки, вершина `54b249c`: 120 из 120, SKIP = 0.

**`SKIP` больше нуля означает не «почти прошло», а «прогон не состоялся».** Чаще всего
не поднялась одна из трёх служб; строка `t.Skipf` в журнале сама называет, какая.

Три ловушки, на которых здесь уже теряли время — пароль Redis, команда MinIO и это самое
`ok` — разобраны в `server/deploy/СТЕК-ДЛЯ-ТЕСТОВ.md`.

## 5. Что прислать

Файл `doc_add\otchet-proverki-go.txt` целиком. В нём уже всё: дата, ветка, вершина,
версии `go` и `docker`, инвентарь контейнеров, результат каждой проверки, четыре числа и
вердикт. Пересказывать своими словами не нужно.

Рядом лежит `doc_add\go-test-latin.txt` — полный вывод `go test -v`. Нужен, только если
что-то упало.

Если что-то чинили — префикс коммита по правилам: `fix(build)`, `fix(test)`,
`fix(behavior)`. **`fix(behavior)` обязан прочитать пишущий**: переименование не имело
права менять поведение, и если поменяло — это дефект, а не мелочь.

## 6. Вариант со стендом в сети

Стенд уже держит `tima-test-postgres-test-1` — тестовый Postgres на `127.0.0.1:55432`
самого сервера. До него дотягивается туннель:

```bash
ssh -N -L 55432:127.0.0.1:55432 <стенд>
```

и дальше, в другом окне:

```powershell
.\check-server.ps1 -NoDocker
```

**Чего этот вариант не даёт.** У боевого compose Redis и MinIO **не опубликованы
наружу** — они видны только внутри сети докера, и туннелем до них не добраться:

| Вариант | Что получится |
|---|---|
| локальный докер | **120 из 120**, SKIP = 0 |
| туннель к стенду | все, кроме **8 SKIP** — шесть тестов ждут Redis, два MinIO |

Восемь пропусков — это ровно то, что скрипт назовёт недействительным прогоном. И назовёт
правильно.

Сделать стенд полноценным можно, но это **правка боевого compose** (опубликовать 6379 и
9000) на живом сервере с реальными данными. Без отдельного решения так делать не стоит:
локальный докер даёт тот же результат и ничем не рискует.

Отдельно, чтобы снять опасение: сам развёрнутый сервер **актуален** —
`git diff 3c491bb HEAD -- server/` даёт ноль строк (`doc_mig/arhiv/СТЕНД.md`). Старая
версия в сети — это про клиента, не про сервер.

## 7. Что именно могло сломаться

Переименование трогает только идентификаторы, но три вещи, если бы их задело, сломались
бы **молча**: компилятор их не проверяет, и старый клиент на телефоне узнал бы первым. На
машине разработки они сверены программно (93 файла, расхождений ноль); здесь их проверяет
живой сервер.

| Что | Чем ломается | Где увидим |
|---|---|---|
| теги структур `json:"user_id"` | имя поля в JSON уехало | любой REST-тест: клиент не найдёт поле |
| пути маршрутов `mux.HandleFunc` | 404 вместо ответа | `TestArchitectureBudgets` и REST-тесты |
| SQL и ключи событий в строках | запрос не тот | тесты групп, звонков, WS |

`TestArchitectureBudgets` заодно пересчитывает бюджеты: 65 маршрутов, 22 метода `Server`,
132 метода `Store`. Не сошлось — это не про переименование, скажите отдельно.

## 8. Живая проверка руками (не обязательна)

Единственное, что смотрит на систему целиком.

1. Службы подняты скриптом; сервер поднять на хосте (`go run ./cmd/tima` с переменными
   dev-стека), десктоп — `ОБНОВИТЬ-И-ЗАПУСТИТЬ-ПК.bat`.
2. Вход по телефону, код приходит прямо в ответе (`TIMA_DEV_SMS=1`).
3. Сообщение себе на второе устройство — **проверяет WS-доставку**, а `Notifier` и его
   шина переименованы (`уведомитель` → `notifier`, `шина` → `bus`).
4. Создать группу, позвать участника — **проверяет ротацию ключа** (`группыDeps`,
   `причинаВход`, `порогРотации`).
5. Позвонить — **проверяет LiveKit** (`LiveKitНастройки` → `LiveKitSettings`, поля
   `Выдача`/`Комнаты`/`Адрес` → `Issuer`/`Rooms`/`URL`).

Пункты 3–5 выбраны не случайно: это места, где переименование затронуло поля, читаемые
**на каждый запрос, а не при регистрации**. Ошибка там выглядит как «звонки в 503» или
«сообщения не приходят», а не как падение — то есть тихо.

Это ручная проверка. В отчёте её так и называть — не «харнесс» и не «формальное
доказательство».

---

## 9. Как откатить, если всё плохо

Коммит самодостаточен: ни миграций, ни изменений API, ни нового формата на диске.

```bash
git revert <хеш>
```

Откат безопасен в любой момент и не требует согласования со старыми клиентами — снаружи
сервер не изменился вовсе.

---

## 10. Чего в самом скрипте не проверено

Сказано прямо, потому что правило запрещает полагаться на непроверенную запускалку.

**Проверено на машине разработки:** разбор скрипта, поиск корня репозитория, чтение ветки
и вершины, отказ при отсутствии `go` и `docker`, отказ при неотвечающих службах, запись
отчёта. Кириллица читается: `.ps1` сохранён **с BOM**, без него PowerShell 5.1
разваливает русский текст.

**Не проверено:** весь путь через докер — на машине разработки Docker не установлен.
Значит первый настоящий запуск будет у вас, и если скрипт споткнётся на шагах 3–5, это
ожидаемо: пришлите отчёт, починим.

## 11. Расхождение, найденное при составлении задания

`.cursor/rules/runtime-launchers.mdc` (`alwaysApply: true`) перечисляет шесть запускалок
как существующие:

> `ЗАПУСК-TIMA.bat` (`start-tima.ps1`) — Docker, dev stack, escrow stub, server,
> packaged desktop app

**В корне их две из шести** — `ОБНОВИТЬ-И-ЗАПУСТИТЬ-ПК.bat` и теперь `check-server.bat`.
Остальные лежат в `doc_mig/arhiv/скрипты-v1/`, то есть в архиве v1, который
`plan-latin-names.md` сам называет «файлами, которые никто не запускает». Архивный
`start-tima.ps1` вдобавок прибит к `C:\!tima2` и к
`%USERPROFILE%\go-toolchain\bin\go.exe` — ровно то, что то же правило запрещает.

Значит правило врёт каждому агенту при каждом запуске. Решать заказчику:

1. **Написать `ЗАПУСК-TIMA.bat` заново** — правило этого и требует. Работа не
   пятиминутная: принять запускалку непроверенной нельзя, а проверка требует живого
   старта со службами.
2. **Сузить правило до того, что есть**: `ОБНОВИТЬ-И-ЗАПУСТИТЬ-ПК.bat` для десктопа,
   `check-server.bat` для проверки сервера, стек — за compose-ом с отсылкой к
   `server/deploy/СТЕК-ДЛЯ-ТЕСТОВ.md`.

Заодно: `update-and-run-desktop.ps1` до сих пор с кириллическими именами переменных
(`$клиент`, `function Скажи`) — правило латиницы на `.ps1` не распространялось ни одной
партией. Отдельная мелкая работа, на проверку не влияет.
