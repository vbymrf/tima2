# Задание на проверку: латиница в именах Go

Что проверяем: коммит переименования 78 имён внутри пакета `server/internal/api`.
Поведение не менялось — ни одной строки кода не добавлено и не удалено, только имена.

**Проверять надо не то, что собирается.** Это уже проверено на машине разработки и
проверено сильно: компилятор Go видит каждое имя пакета. Проверять надо то, чего
отсюда не видно, — **что сервер отвечает так же, как отвечал**. Для этого нужны живые
службы, а на машине разработки их нет.

---

## 0. Перед началом

```bash
git pull --rebase
git log --oneline -1        # вершина, к которой относится отчёт
cd server && go env GOVERSION
```

Хеш из `git log` **обязан попасть в отчёт**. «Проверено» относится к коммиту, никогда к
ветке: отчёт без хеша — отчёт ни о чём.

Замок брать не надо, если проверка не меняет ветку. Если будете чинить — сначала замок
в `СОСТОЯНИЕ-ВЕТКИ.md`, как обычно.

---

## 1. Что должно быть зелёным без служб

Ожидается — всё зелёное. Если хоть что-то красное, дальше не идти: это уже расхождение
между машинами, и оно важнее самой проверки.

| # | Команда (из `server/`) | Ожидание |
|---|---|---|
| 1.1 | `go build ./...` | пусто, код возврата 0 |
| 1.2 | `go vet ./...` | пусто |
| 1.3 | `gofmt -l ./internal ./cmd` | **пусто** — ни одного файла |
| 1.4 | `go test -run '^$' ./...` | `ok`/`no test files` по всем пакетам |

1.4 ничего не запускает: `-run '^$'` не совпадает ни с одним тестом. Смысл в том, что
**тесты компилируются** — а это половина переименованных вхождений.

## 2. Главное: тесты со службами

Это тир `server-full` из `.cursor/skills/adaptive-test-runner/project/PROFILE.md`.
Что и зачем поднимается — `server/deploy/СТЕК-ДЛЯ-ТЕСТОВ.md`; ниже только команды.

**Лаунчера для стека в корне репозитория нет** — там лежит одна запускалка десктопа.
Поэтому службы поднимаются compose-ом напрямую (см. §7: это расхождение с правилом, и
его решает заказчик).

### 2.1 Поднять службы

```bash
docker compose -f server/deploy/docker-compose.test.yml up -d
docker compose -f server/deploy/docker-compose.dev.yml up -d
```

Два проекта, не один: тестовый Postgres слушает **55432** и живёт отдельно от dev-базы.
Так и задумано — `setup` труncate-ит все таблицы, и указанный по ошибке dev-адрес стоил
бы всей истории.

Где Docker не используется — портативный способ расписан в
`server/deploy/СТЕК-ДЛЯ-ТЕСТОВ.md`, «Способ 2», а адреса этой машины — в её
`doc_mig/ОКРУЖЕНИЕ.local.md` (вне git). **Строку подключения брать с машины, а не
отсюда:** неверный адрес выходит как `Skipf`, а `Skipf` читается как успех.

### 2.2 Прогнать

```powershell
$env:TIMA_TEST_DATABASE_URL = "postgres://tima:tima-test-only@localhost:55432/tima_test"
$env:TIMA_TEST_REDIS_URL    = "redis://:tima-dev-only@localhost:6379"
$env:TIMA_TEST_S3_ENDPOINT  = "http://localhost:9000"
Push-Location server; go test -count=1 -v ./... 2>&1 | Tee-Object ..\doc_add\go-test-latin.txt; Pop-Location
```

`-count=1` — чтобы не получить кэш прошлого прогона вместо настоящего.

### 2.3 Как читать результат — здесь ловушка

**`ok` не значит «тесты прошли».** Пакет, где всё пропущено, печатает то же `ok`.
При недоступной базе `internal/api/api_test.go:52` делает `t.Skipf`, и 70 тестов из 118
не выполняются, а прогон выходит с нулём. Отсутствие окружения выглядит как пройденная
проверка.

Поэтому считаем построчно:

```bash
grep -cE '^=== RUN   Test' doc_add/go-test-latin.txt   # RUN
grep -cE '^--- PASS'       doc_add/go-test-latin.txt   # PASS
grep -cE '^--- FAIL'       doc_add/go-test-latin.txt   # FAIL
grep -cE '^--- SKIP'       doc_add/go-test-latin.txt   # SKIP  ← обязан быть 0
```

**Ожидание тира `server-full`: 118 из 118, SKIP = 0.** Любой SKIP означает, что служба
не поднялась: прогон недействителен, вернуться к 2.1. В отчёт идут все четыре числа.

Три ловушки, на которых здесь уже теряли время — пароль Redis, команда MinIO и это
самое `ok` — разобраны в `server/deploy/СТЕК-ДЛЯ-ТЕСТОВ.md`. Прочитать до, а не после.

## 3. Что именно могло сломаться

Переименование трогает только идентификаторы, но три вещи, если бы их задело, сломались
бы **молча** — компилятор их не проверяет, и старый клиент на телефоне узнал бы об этом
первым. На машине разработки они сверены программно (93 файла, расхождений ноль);
здесь их проверяет живой сервер.

| Что | Чем ломается | Где увидим |
|---|---|---|
| теги структур `json:"user_id"` | имя поля в JSON уехало | любой REST-тест: клиент не найдёт поле |
| пути маршрутов `mux.HandleFunc` | 404 вместо ответа | `TestArchitectureBudgets` и REST-тесты |
| SQL и ключи событий в строках | запрос не тот | тесты групп, звонков, WS |

`TestArchitectureBudgets` заодно пересчитывает бюджеты: 65 маршрутов, 22 метода
`Server`, 132 метода `Store`. Если число не сошлось — это не про переименование,
скажите отдельно.

## 4. Живая проверка руками (если дойдут руки)

Не обязательна, но она — единственное, что смотрит на систему целиком.

1. Службы из §2.1 уже подняты; сервер поднять на хосте (`go run ./cmd/tima` с
   переменными dev-стека), десктоп — `ОБНОВИТЬ-И-ЗАПУСТИТЬ-ПК.bat` в корне.
2. Вход по телефону, код из dev-SMS (`TIMA_DEV_SMS=1`).
3. Отправить сообщение себе на второе устройство — **проверяет WS-доставку**, а
   `Notifier` и его шина переименованы (`уведомитель` → `notifier`, `шина` → `bus`).
4. Создать группу, позвать участника — **проверяет ротацию ключа** (`группыDeps`,
   `причинаВход`, `порогРотации`).
5. Позвонить — **проверяет LiveKit** (`LiveKitНастройки` → `LiveKitSettings`, поля
   `Выдача`/`Комнаты`/`Адрес` → `Issuer`/`Rooms`/`URL`).

Пункты 3–5 выбраны не случайно: это ровно те места, где переименование затронуло поля,
читаемые **на каждый запрос, а не при регистрации**. Ошибка здесь выглядит как «звонки
в 503» или «сообщения не приходят», а не как падение.

Это ручная проверка. В отчёте её так и называть — не «харнесс» и не «формальное
доказательство».

## 5. Что прислать

```
Коммит:        <хеш из git log --oneline -1>
Go:            <вывод go env GOVERSION>
Шаг 1:         1.1 … 1.4 — зелено / что красное
Стек:          поднялся / нет
Шаг 2:         RUN = <число>, SKIP = <число>, FAIL = <число>
Живая:         делал / не делал; что видел
Вердикт:       принято / чинить
```

Если что-то чинили — префикс коммита по правилам: `fix(build)`, `fix(test)`,
`fix(behavior)`. **`fix(behavior)` обязан прочитать пишущий**: переименование не имело
права менять поведение, и если поменяло — это дефект, а не мелочь.

---

## 6. Как откатить, если всё плохо

Коммит самодостаточен и ничего не тянет за собой: ни миграций, ни изменений API, ни
нового формата на диске.

```bash
git revert <хеш>
```

Откат безопасен в любой момент и не требует согласования со старыми клиентами — снаружи
сервер не изменился вовсе.

## 7. Расхождение, найденное при составлении этого задания

`.cursor/rules/runtime-launchers.mdc` (`alwaysApply: true`) перечисляет шесть запускалок
как существующие:

> `ЗАПУСК-TIMA.bat` (`start-tima.ps1`) — Docker, dev stack, escrow stub, server,
> packaged desktop app

**В корне репозитория из шести есть одна** — `ОБНОВИТЬ-И-ЗАПУСТИТЬ-ПК.bat`, и она про
десктоп. Остальные лежат в `doc_mig/arhiv/скрипты-v1/`, то есть в архиве v1, который
`plan-latin-names.md` сам называет «файлами, которые никто не запускает». Архивный
`start-tima.ps1` вдобавок прибит к `C:\!tima2` и к `%USERPROFILE%\go-toolchain\bin\go.exe`
— ровно то, что то же правило запрещает.

Значит правило врёт каждому агенту при каждом запуске, а его требование «поднимать
только через запускалку» невыполнимо. Решать заказчику; вариантов два:

1. **Написать `ЗАПУСК-TIMA.bat` заново** — правило этого и требует («If a runtime target
   has no launcher, create one before the first agent-driven launch»). Работа не
   пятиминутная: запускалку нельзя принять непроверенной, а проверка требует живого
   старта со службами.
2. **Сузить правило до того, что есть**, и оставить стек за compose-ом с отсылкой к
   `server/deploy/СТЕК-ДЛЯ-ТЕСТОВ.md`, где уже расписаны три способа.

До решения это задание идёт через compose напрямую — иначе его первый шаг невыполним.
