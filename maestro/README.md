# Сценарии Maestro

Живые сценарии для прогона на телефонах — модель 4. Про сами модели и выбор между
ними — [../doc_mig/ТЕСТЫ-НА-ТЕЛЕФОНАХ/](../doc_mig/ТЕСТЫ-НА-ТЕЛЕФОНАХ/README.md),
про устройство инструмента — [КАК-РАБОТАЮТ-МОДЕЛИ/MAESTRO.md](../doc_mig/ТЕСТЫ-НА-ТЕЛЕФОНАХ/КАК-РАБОТАЮТ-МОДЕЛИ/MAESTRO.md).

## Почему папка здесь, а не в документации

Путь к сценарию передаётся в командную строку Windows. Кириллица в нём ломается о
кодировку консоли — то самое, из-за чего в проекте заведено правило про латиницу в
именах файлов кода. Сценарий — код, и живёт он по этому правилу.

## Как запускать

```bash
MAESTRO_DRIVER_STARTUP_TIMEOUT=180000 \
  maestro --device 192.168.3.193:46843 test maestro/update.yaml
```

**Таймаут обязателен.** По сетевому adb драйвер Maestro не успевает встать за
отведённое по умолчанию время, и прогон виснет молча, без единой строки.

Артефакты каждого прогона — `~/.maestro/tests/<дата_время>/`: `commands.json` со
статусом по каждому шагу, снимки, дерево упавшего шага, журнал телефона.

## Что есть

| Файл | Что проверяет | Состояние |
|---|---|---|
| `update.yaml` | обновление из меню: от старой версии до «Обновление установлено» | **проходит целиком**, 212 с на Samsung 2026-09-15, без человека |

## Что нужно телефону, чтобы `update.yaml` прошёл целиком

1. **Старая версия приложения** — иначе обновлять нечего, сценарий увидит «Установлена
   последняя версия» и упадёт на «Обновить». Стендовый телефон для этого — Samsung.
2. **Аккаунт** — экран обновления за входом.
3. **Play Защита выключена**: `adb shell settings put global package_verifier_user_consent -1`
   (решение заказчика 2026-09-15; вернуть — то же с `1`). Иначе сценарий остановится на её
   окне явно, с причиной.

### Вернуть Samsung на старую версию после прогона

**Не `adb install -d`.** Между версиями бывает миграция базы, и после отката пакета
приложение падает на старте: `Can't downgrade database from version 8 to 7` — поймано
2026-09-15. Правильно так:

```bash
adb shell pm clear io.tima.app.v2          # стирает базу и аккаунт на телефоне
adb install -r -d TIMA-<старая>.apk
```

Дальше в приложении: номер → код (стенд отдаёт его на экране) → «Вход по фразе» → двенадцать
слов из `doc_mig/ВЕРСИИ/ТЕЛЕФОНЫ.local.md`. Три минуты, проверено дважды.

## Правила для сценариев этой папки

**`clearState` не применять.** Он стирает аккаунт. Проверяем поведение на живом
устройстве, а не на чистом.

**До установки новой версии отбор только по надписям.** Метки (`window:`, `tab:`,
`settings:`) заведены в версии 10 — сценарий обновления начинается на старой версии,
где их нет ни одной.

**Отбор по тексту — полное совпадение по регулярному выражению, а не вхождение.**
`"Установлена"` не найдёт узел «Установлена 2.0.9-dev-v2 (9)». Нужно `.*Установлена.*`.

**К системным окнам привязываться по идентификатору, а не по надписи.** Вендор
переписывает и вопрос, и кнопки: на Redmi «Обновить приложение? / Обновить», на
realme «Установить обновление для этого приложения? / УСТАНОВИТЬ». Положительная
кнопка у обоих — `android:id/button1`.
