# Зеркало `maven.aliyun.com` в сборке клиента: проверка на безопасность

Проверено 2026-09-03 на машине разработки (VMware/Evgenera), ветка `stand`,
вершина `9102e96`. Повод — сборка клиента здесь не прошла вовсе.

Всё ниже **измерено запросами**, а не выведено из чтения конфигов. Как повторить —
в последнем разделе.

---

## Вывод

Зеркало не «дополнительный источник»: в обычном (не-CI) режиме оно стоит **первым**
и для зависимостей, и **для плагинов сборки**. Измерено, что оно отдаёт
**именно ту версию Android Gradle Plugin, которую собирает проект** — `8.13.2`,
включая JAR на 13 МБ. Плагин исполняется внутри JVM сборки.

При этом **в проекте нет ни одной сверки контрольных сумм** для Gradle-зависимостей:
ни `verification-metadata.xml`, ни lock-файлов. То есть подмена артефакта не была бы
замечена ничем.

Отсюда две разные по характеру вещи:

- **Доступность — проблема уже реализовавшаяся, дважды.** 2026-08-20 на CI и
  2026-09-03 здесь. Это не риск, это факт.
- **Подмена — риск, а не факт.** Aliyun — крупный оператор (Alibaba Cloud), а не
  случайный хост, и признаков недобросовестности не найдено. Но доверие к сборке
  Android-части перенесено с Google на третью сторону, и **проверить это доверие
  нечем**.

Криптомодуль, сервер и форки не затронуты — подробности ниже. Это существенно
снижает цену вопроса, но не отменяет его: подменённый AGP собирает тот самый APK.

---

## Как устроено сейчас

`client/settings.gradle.kts`, строки 20–65. Порядок выбирается по переменной `CI`:

```kotlin
pluginManagement {
    repositories {
        if (System.getenv("CI") != null) {
            google(); gradlePluginPortal(); mavenCentral()
            maven("https://maven.aliyun.com/repository/google")
        } else {
            maven("https://maven.aliyun.com/repository/google")   // ← первым
            google(); gradlePluginPortal(); mavenCentral()
        }
    }
}
```

Такой же блок — в `dependencyResolutionManagement` (после `mavenLocal()`).

Замысел записан там же в комментарии и он разумен:

> В сети разработки `dl.google.com` блокируется, поэтому там зеркало обязано идти
> первым — иначе сборка висит на недоступном хосте.
>
> На CI наоборот: зеркало — лишнее звено, и оно уже подводило. Прогон 2026-08-20
> упал с `502 Bad Gateway` от `maven.aliyun.com` при загрузке `apache-18.pom`, и
> это выглядело как поломка кода, хотя код был цел.

**Условие выбрано не по тому признаку.** Первым должен идти тот источник, который
доступен, — а доступность это свойство машины, не признак CI. На этой машине
`dl.google.com` отвечает `200`, и зеркало здесь не помогает, а единственное, что
ломает сборку.

## Что зеркало отдаёт на самом деле

Запросы `HEAD` к `https://maven.aliyun.com/repository/google/…`:

| Артефакт | Ответ |
|---|---|
| `com.android.tools.build:gradle:8.13.2` (pom) | **200**, 11 773 Б |
| `com.android.tools.build:gradle:8.13.2` (**jar**) | **200**, **13 116 808 Б** |
| `com.android.application.gradle.plugin:8.13.2` (маркер) | **200**, 1 330 Б |
| `androidx.compose.runtime:runtime:1.11.1` | **200**, 4 716 Б |
| `org.jetbrains.kotlin:kotlin-gradle-plugin:2.3.10` | 404 |
| `org.jetbrains.kotlin:kotlin-stdlib` | 404 |
| `com.squareup.okhttp3:okhttp` | 404 |
| `org.jetbrains:annotations:23.0.0` | 404 |
| `asia.hombre:kyber:2.0.1` | 404 |

Читается так: **сегодня** зеркало ведёт себя как узкий прокси содержимого Google
Maven. Всё, что не оттуда, оно отдавать отказывается, и Gradle идёт дальше по списку.

Но узость эта — **поведение третьей стороны, а не наложенное нами ограничение.**
Gradle спрашивает зеркало первым про **каждый** артефакт и **каждый** плагин.
Если зеркало когда-нибудь начнёт отвечать шире, оно и будет выигрывать — молча,
и настройки менять для этого не понадобится.

## Чего в проекте нет

```
verification-metadata.xml   не найден нигде
*.lockfile                  не найдены
```

Значит, у Gradle-зависимостей нет ни контрольных сумм, ни подписей, ни фиксации
разрешённого графа. Единственная защита — HTTPS, а он подтверждает, что мы говорим
с зеркалом, и ничего не говорит о содержимом, которое зеркало отдаёт.

**Для контраста — серверная часть защищена по построению:**

```
server/go.sum   96 строк
GOSUMDB         sum.golang.org
GOPROXY         https://proxy.golang.org,direct
```

Каждый модуль Go сверяется по хешу с прозрачным журналом. Подмена там невозможна
без обнаружения. На клиенте того же нет.

## Что зеркалом НЕ затронуто

Проверены все `settings.gradle.kts` в репозитории:

| Сборка | Репозитории | Зеркало |
|---|---|---|
| `client/` | `mavenLocal`, **aliyun**, `google`, `gradlePluginPortal`, `mavenCentral` | **да** |
| `messenger-crypto/` | `gradlePluginPortal`, `mavenCentral`; `mavenLocal`, `mavenCentral` | нет |
| `third-party/KeccakKotlin`, `KyberKotlin` | `mavenCentral` | нет |
| `Kodium git/kodium-main` | `mavenCentral` | нет |

**Криптомодуль зеркала не касается вовсе** — это важно и это хорошо: граф
зависимостей, в котором живут Kyber и Keccak, к нему не ходит.

Ещё два смягчающих обстоятельства, оба проверены:

- **Версии зафиксированы точно.** В `client/gradle/libs.versions.toml` нет ни `+`,
  ни `latest`, ни `SNAPSHOT`. Динамических версий, которые зеркало могло бы
  «разрешить» в свою пользу, нет.
- **Незащищённого протокола нет.** Ни одного `http://`, ни одного
  `allowInsecureProtocol` во всех файлах сборки.

## Оценка

| Что | Реализовалось? | Последствие | Что поймает сейчас |
|---|---|---|---|
| Зеркало недоступно, сборка падает | **да, дважды** (2026-08-20 CI, 2026-09-03 здесь) | потерянное время, падение выглядит как поломка кода | ничего: диагноз ставит человек |
| Зеркало отдаёт подменённый AGP | нет признаков | исполнение чужого кода в JVM сборки → любой артефакт на выходе | **ничего** |
| Зеркало отдаёт подменённую `androidx` | нет признаков | чужой код в готовом APK | **ничего** |
| Подмена в криптомодуле через зеркало | невозможно | — | зеркало туда не подключено |
| Подмена в сервере | невозможно | — | `go.sum` + `sum.golang.org` |

Вероятность подмены низкая. Цена — высокая: продукт мессенджер, и правило
`crypto-invariants` про неизменность ключей защищает код, который к этому моменту
уже собран чужим плагином.

## Что предлагается

Три меры, независимые друг от друга. Первая закрывает вопрос по существу,
остальные дёшевы и полезны сами по себе.

**1. Включить сверку контрольных сумм Gradle.** Это единственная мера, после которой
личность зеркала перестаёт иметь значение: подменённый артефакт просто не пройдёт.

```bash
cd client && ./gradlew --write-verification-metadata sha256 help
```

Файл `gradle/verification-metadata.xml` коммитится и просматривается человеком.
Цена честная: при каждом подъёме версии зависимости его надо перегенерировать и
перечитать, иначе он превращается в резиновый штамп.

**2. Сделать зеркало запасным, а не первым, и выбирать по доступности.** Признак `CI`
заменить на явную переменную вида `TIMA_MAVEN_MIRROR_FIRST`, которую машина за
блокировкой выставляет у себя. Тогда там, где `dl.google.com` доступен, первым
отвечает Google, и падение 2026-08-20 не повторяется ни здесь, ни на CI.

**3. Ограничить зеркало по группам,** чтобы оно не могло ответить за чужое, даже если
завтра начнёт:

```kotlin
maven("https://maven.aliyun.com/repository/google") {
    content {
        includeGroupByRegex("com\\.android.*")
        includeGroupByRegex("com\\.google.*")
        includeGroupByRegex("androidx.*")
    }
}
```

Сегодня это ровно то, что зеркало и так делает. Разница в том, что это станет
**нашим** правилом, а не его любезностью.

### Что делать на этой машине прямо сейчас

`CI=1` перед сборкой ставит Google первым и обходит падение. **Проверено запуском
2026-09-03 на вершине `9102e96`:**

```bash
cd /c/!TIMA2/client && CI=1 ./gradlew build
#   без CI=1  →  BUILD FAILED  за 8 мин 32 с, «Could not resolve … 502 Bad Gateway»
#   с  CI=1   →  BUILD SUCCESSFUL за 17 мин 45 с
#               RUN 834, PASS 834, FAIL 0, SKIP 0
```

Разница только в порядке репозиториев: код, зависимости и версии те же самые. Это и
есть доказательство, что падение было сетевым, а не кодовым.

Проверено, что во **всём репозитории** переменную `CI` читают только две строки —
`client/settings.gradle.kts:22` и `:54`. То есть на прогон тестов и на что-либо ещё
она не влияет. Оговорка: сторонние плагины Gradle могут смотреть на `CI` по своим
причинам; в нашем коде — нет.

Это обход для одной машины, а не решение. Решение — пункты выше.

## Что решает заказчик

1. Включаем ли сверку контрольных сумм (пункт 1). Это разовая работа плюс
   постоянная дисциплина при подъёме версий.
2. Меняем ли условие выбора порядка с `CI` на признак доступности (пункт 2) —
   правка отслеживаемого `client/settings.gradle.kts`.
3. Ограничиваем ли зеркало по группам (пункт 3) — правка там же, риска не несёт.

До решения на этой машине собираем с `CI=1`.

## Как это измерялось

```powershell
# что зеркало отдаёт (200 = отдаёт, 404 = нет)
Invoke-WebRequest -Method Head -UseBasicParsing `

# доступность прямых источников с этой машины

```

```bash
find . -name verification-metadata.xml -not -path "./.git/*"   # пусто
find . -name "*.lockfile" -not -path "./.git/*"                # пусто
```

**Оговорка о сети.** Весь внешний трафик этой машины идёт через туннель `happ-xray`
(см. `doc_mig/ОКРУЖЕНИЕ.local.md`, ловушка 5). Поэтому коды ответов и размеры
считать можно, а разрешённые адреса `maven.aliyun.com` — нет: их вернул туннель, и
чьи они на самом деле, отсюда не видно. Ни один вывод выше на IP-адреса не опирается.
